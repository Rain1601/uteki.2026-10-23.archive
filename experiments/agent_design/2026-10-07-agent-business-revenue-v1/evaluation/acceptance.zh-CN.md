# 同一原文上的真实执行与参考对照

本轮目标：Uteki Data Agent 实际加载业务图 Skill，调用 Claude 一次，从已冻结的财报选段生成业务图、收入图和精确出处。用户已经认可 v2 的表达方式，并抽查了部分内容；参考候选仍不等于标准答案。

## 共同材料与差异

使用 Alphabet FY2025 的同一原件。Agent 输入限定为 `input/source_packet.json`：78 个原文块和完整的 1 张收入表，保留 2024/2025 两年，显式选择 2025。模型只选业务事实、关系和原表单元格；金额由宿主读取。

既有 Codex v2 参考位于 `../2026-10-07-business-revenue-v2/alphabet/`。它由 Codex 在此前原文审阅后整理。它的工作过程、上下文和投入时间与本次运行不同。本次称参考对照，不称相同设置的严格模型 A/B。旧参考、金额、目标节点与此评估文件不进入模型输入。

本轮不新增 Claude 独立第三路或顾问重试。Claude 在此运行中是 Uteki 的执行模型；此前顾问对话的失败记录和累计额度保留原状。

## 验收标准

| 层面 | 必须检查的实际行为 | 不由此证明 |
|---|---|---|
| 输入与 Skill | 保存原文包、实际 Skill 全文、JSON Schema、实际 HTTP 请求和各自 hash；请求与记录一致 | 模型已训练或学会技能 |
| 运行 | 一次明确模型调用，有开始/结束、供应商回执、配置、用量、估算费用；失败不删除 | 可重复多次稳定输出 |
| 业务 | 经营活动与收入分类分开；真实业务和商业组有据；归属方向正确；不把集团组合自动冒充报告分部 | 已覆盖整份财报所有业务 |
| 收入 | 正确公司/年度/USD million；金额绑定原文单元格；保留负调整；互斥项目能勾稽；小计不重复相加 | 单靠合计相等即可证明会计分类正确 |
| 出处 | 每个节点和关系能定位到原文块；每个金额能定位到原表单元格；摘要解释与引文语义一致 | 有引用即已证明所有解释 |
| 呈现 | 实际生成 Mermaid/SVG，收入单独图表，能查看引用、结果与 Trace | 浏览器视觉验收或用户已认可新模型图 |

程序硬校验与 Codex 语义复核分开记录。发现不支持的分类、遗漏或合并披露被拆分，应保留原结果并记录差异，不通过宿主补上正确答案掩盖模型错误。
