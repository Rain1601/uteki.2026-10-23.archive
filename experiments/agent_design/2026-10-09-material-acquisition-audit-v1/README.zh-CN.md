## 获取以什么为主

现有代码从 SEC submissions 核对公司身份，遍历适用的 recent / archive 目录，按显式 selection 选择申报，再下载其 `primaryDocument`。同 accession 的冲突元数据记为缺口。年报范围模式只收年报及同期间修订；latest 模式收最新原始 10-K 及其后申报的 10-Q、8-K 与修订件。**目前没有专门“指定多年所有 10-K 和 10-Q”的已验收选择模式。**

代码定位：`src/uteki/infrastructure/document_sources/company_acquisition.py:692`（公司目录）、`:747`（accession 冲突）、`:771`（形式筛选）、`:803`（latest 模式）、`:809`（所选材料及处理状态）、`:825`（primary document）。具体完整性还受时间边界、目录分页与资源上限影响；有缺口不能报告收齐。

对本轮 10-K / 10-Q 建议冻结以下规则，尚不代表全部已实现：

1. 官方 SEC 申报正文是主原件；官网镜像保留来源关系，不重复计作另一份报告。附件如被正文引用且影响解释，列为显式依赖或缺件，不能默认为已获得。
2. 公司、申报编号、材料形式、报告期间、披露时间、原件 hash 共同描述版本。不能仅凭文件名或文本相同合并不同期间材料。
3. 原件与 `/A` 修订件分别保留，建立修订关系；先核对修订覆盖内容，再决定某项事实的适用版本。当前获取器没有语义层的修订覆盖裁决，不能直接把最新修订当整份原报告。
4. “全部”指用户明确范围内的官方应收清单；应收、实收、排除、失败、缺件逐项可核对。官网其它公告、8-K、电话会等不在未声明情况下混入本轮全部范围。

## 重复检查：三种问题分别处理

| 检查 | 本轮观察 | 判定 |
|---|---|---|
| 同一原件重复存储 | Google 两份数据集的年报 raw hash 一致，解析版本不同 | 是原件复用与版本底稿，不能算两份不同报告；不能为去重删除历史快照 |
| 同一原文位置重复解析 | 所选四套底稿的 block ID 和 DOM 路径均无重复；无父子块重叠路径 | 此项检查通过，仅限这些输入和这些结构指标 |
| 同文不同位置 / 跨报告重述 | 微软年报 65 组、Google 年报 58 组、季度报告 22 组相同文本；Google 年/季报有 240 组相同块文本 | 只是重复候选，含短标记与标题，不是错误数量；语义是否可合并未全面审查 |

抽查原件：微软 block 726 / 840、Google block 622 / 1033 的相同段落确实在各自原 HTML 的两个不同 DOM 位置出现，四处文本与解析一致。微软位置为 `/html/body/div[135]/p[14]` 与 `/html/body/div[168]/div/ix:continuation/div/ix:continuation/p[11]`。因此不能把文字相同直接归因于解析器重复输出。

获取器已有 URL 单次去重、内容 hash 对象复用、accession 元数据一致性检查。相关位置是 `company_acquisition.py:390`、`:562`、`:747`。**这些不等于跨报告的事实去重。** 原始材料保留，索引标记重复/重述关系；查询交付按期间、口径、限定和来源选择必要证据，不能累加同一事实的重复披露，也不能误删不同期间的事实。后半部分是验收要求，当前未证明已实现。

## 解析质量为什么仍未通过

用户确认范围后，已对本轮实际 v0.1.11 底稿重新执行全文结构核查，不再借用旧 v0.1.12 的结论。Microsoft 6,316 段、Google 6,708 段可见 DOM 文本在声明规则下有表示，未检测漏文/块文本不一致，块顺序符合 DOM 顺序。原件及输入产物 hash 未改变。[新汇总](coverage-summary.json) · [Microsoft 逐节结果](msft-coverage.json) · [Google 逐节结果](googl-coverage.json) · [复查脚本](coverage.py)。

这些检查复用了解析器的可见性规则，不是独立视觉或语义评审。Microsoft 的 85 张表和 28 处跨节引用候选、Google 的 185 张表和 53 处跨节引用候选及 2 个图像对象仍保留语义/内容未审状态；数量不是错误数量。图像需先分类是否承载信息，不能直接当装饰忽略。

上一轮[基础审查](../2026-10-09-data-foundation-review-v1/README.zh-CN.md)已复现列表内容与标记分离、读取时遗漏表格脚注、实际运行与历史审查底稿版本不一致。历史全文文本覆盖只证明指定版本下可见文字有结构表示，未覆盖表格含义、所有图像、阅读顺序或必要上下文。已有 coverage audit 明确只支持 10-K，不能直接给 10-Q 发同样的合格结论。

## 此关交付与关闭条件

每家公司交付一份材料台账：范围/截止日期 → 官方应收项 → 实收原件及验证 → 每份解析版本与质量记录 → 重复/修订/引用关系 → 缺件与未支持内容。

- 获取：范围内应收项全部有可核对处置；缺失与排除有明确原因。存在必要缺件则不通过。
- 解析：原件到块/表/索引可回查；没有解析引入的漏文、重叠重复、错位或缺必要上下文；未支持项不能隐藏。
- 重复与版本：重复副本不重复计数，历史原件不被覆盖；不同期间、修订和口径不被错误合并；原文合理重述不当垃圾删除。
- 验收绑定原件 hash、解析器和产物 hash；新版本不能继承旧版本通过状态。

**紧接着：在这两份已选 FY2025 10-K 上修复并验收列表/脚注等解析与读取缺陷。** 10-Q 扩展时再由系统生成所选时间范围的官方应收—实收清单并补取原件；准备基础通过后进入最小充分材料的 Query 测试。Codex 负责审查与通用工程修复，不代替系统选取业务段落。
