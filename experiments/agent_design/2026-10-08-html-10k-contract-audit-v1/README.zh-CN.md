## 08 整文完成的最小下一阶段

先只做 **Microsoft FY2025 同一份冻结 HTML 10-K 全正文**。不在这一阶段追加公司、PDF、实时网络、外部代理声明或产品官网。当前 103 块 Operating Segments 精编不能作为整文。

1. **输入明确。** 固定原件 hash、完整底稿版本、公司/期间和截止日；以整份报告全部正文块为分母。导航、重复版式、隐藏元数据的排除应保留具体位置与原因。
2. **输出具体。** 可读总览 + 按原报告 Item/章节组织的精编。每章保留重要披露、期间、数字口径、管理层归属与风险限定；每项有精确原文，所有源块有处置。财务报表/附注不能只概括标题后标“已覆盖”。
3. **明确材料边界。** 对本文仅引用的代理声明、附件/外链或图片信息，标注“未读取/不支持”和原引用位置；不能虚构其内容，也不能把缺件叫未披露。若其缺失阻止本报告的重要结论，就让该结论保持缺口。
4. **判定完成。** 系统 Agent 独立生成，不由 Codex 填正文；Schema/定位校验通过；从原文到精编的覆盖核对与从精编到原文的主张核对都完成。主要业务、财务表现、主要风险、关键附注及控制披露无未解释的重大遗漏；出现格式成功但内容不足则仍不通过。
5. **整文单例与整项分开。** 此阶段可验收一个完整 10-K；用户要求的其他既有公司与新公司测试仍单独记录，不由这个单例替代。生成前预检整文分批/合并/复核的同任务费用，不用每章重建账本规避上限。
