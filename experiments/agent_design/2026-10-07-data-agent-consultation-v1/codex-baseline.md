# Codex 独立意见：在顾问调用前记录

这份意见在 Opus/Fable 调用之前形成。它不放入两款模型的请求，避免让顾问照着本轮结论作答。共同请求包含历史业务约定、代码审核和实测观察。

当前首要问题是任务交付与验收的定义。模型选择已有可用基线，但“请求成功”“引用可定位”“候选写入数据库”都不足以证明完整产品合格。

## 业务范围

建议按四类产物、两类维护任务组织：

| 任务 | 输出 | 首要验收点 |
|---|---|---|
| 获取和准备指定材料 | 原件、来源身份与版本、可定位段落/表格 | 公司/期间/截止日正确；内容完整；解析范围明确 |
| 建立结构化事实 | 原口径事实、规范化数值、证据、候选与核验状态 | 数值/符号/单位/期间/维度正确；必需事实召回；引用支持 |
| 财报精编 | 忠实浓缩的报告、关键表图与引用 | 重要披露及限定词保留；管理层解释正确归属；不混入未证推断 |
| 公司业务图 | 业务、产品/客户、赚钱方式、关系与证据 | 节点和边均可核对；主要业务完整；未知关系不补写 |
| 按研究问题补证 | 有出处的回答、计算、EvidenceBundle、具体缺口 | 回答所问；计算可复算；缺口声明不与现有材料矛盾 |
| 更新和版本维护 | 新快照、差异、重述关系与影响 | 保留旧版；无变化可复用；更新与重述不漏；可按时点读取 |

前两项有较成熟执行基础，后四项成熟度各异。BusinessMap 有实际生成器和历史样本，不能称为只有契约；也不能称为已完成通用年报主流程。

Data 可以计算“表内哪些项目构成现金流下降”，摘录“管理层如何解释下降”。Analysis 负责判断“这意味着什么、会否持续、是否改变投资假设”。不要用有没有文字、有没有 reasoning 来划分职责。

## 模型、函数与任务说明

先保留 Sonnet 5.5 adaptive/high 为有记录的执行基线。让普通程序处理抓取、解析、哈希、单位换算和算术。给 Sonnet 明确任务、可回原文的定位信息及受控读取工具。只有遇到分歧、覆盖缺口、复杂口径或高返工率，再实验 Opus 规划或复核的增量收益。

function 是具有明确输入输出的操作，例如读取指定表格、计算桥接。skill 是可复用的业务任务说明、证据要求和步骤。agent 在约束内选择并调用操作。定义一张任务卡即可起步，不必新建通用框架。

任务卡至少声明：任务与版本、公司/报告/期间/截止日、来源策略、交付结构、覆盖范围、数字精度、证据要求、允许的缺口、资源预算和验收办法。

## 评估与稳定性

程序先验范围、类型、单位、计算、引用位置、产物可读和版本写入。语义评审再判断证据是否支持陈述、是否遗漏重要项、是否错误报缺。完整任务还要从发现材料开始检查覆盖、补提、合并、修订以及最终采用状态。

Codex 可以承担首轮有依据的评审，但不自动成为标准答案。数字、引用和会计桥接优先程序复核；重要语义项由独立评审结合来源复核；高风险或有争议样本由人定标。双模型一致仍可能同错。初期强模型只审关键陈述及足够的上下文；关于“原报告不存在某项”的断言，单独短片段通常无法证明。

固定配置应追求核心事实和业务约束稳定，而不是重新生成时逐字相同。要原样重现已交付产物，应按 Trace ID 读取冻结结果。

近期核心问题是错误报缺。下一轮先只改任务契约：允许 gaps 为空；要求区分来源事实、可复算结果、管理层解释和待研究假设；在声称无法计算前核对表内已有数据。以原有错误为回归，再增加材料确实不足的相邻反例，防止提示改动导致乱算。

## 最小下一步及验收

1. 固定一个“指定报告小节 → 结构化事实 + 可复算会计桥接 + 正确缺口”的任务契约。保留旧版本；冻结独立答案、舍入规则与范围；用原题和真正缺资料的反例做少量重复。要求关键事实/算术/引用无错，缺口与材料不矛盾。
2. 加入另一公司和 20-F 的独立样本。选定一个明确报告范围，再验收覆盖、补提、合并与忠实精编。小节级通过不能推出整份年报完成。
3. 接通候选核验、修订和版本发布，之后单独验收业务图与增量更新。仅在这些任务上测出收益时，引入 Opus 规划或双裁判。

费用要按成功交付计算：执行、失败/修复、规划、评审的全部实际调用费用加工具费用，再单列人工复核分钟数与总延迟。现有约两美分的现金流小题不能作为整份年报成本报价。
