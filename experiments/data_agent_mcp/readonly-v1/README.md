# 只读 Data MCP：首轮独立消费者验收

日期：2026-10-05（Asia/Shanghai）。资料截止：2026-10-04。

**四个只读 MCP 工具已跑通，陌生 Codex 能独立完成双公司取数。10 项目标值中，数据库提供 3 项，另 7 项由消费者读原文取得；这 7 项没有变成 Data Agent 的入库成果。** 9 项与独立原文答案的精度一致，1 项使用摘要表的舍入精度且已声明。正式采纳仍为 0 项。

先看[消费者原始报告](consumer-answer.zh-CN.md)，再看[逐项复核](acceptance.json)。[调用与启动说明](../../../docs/DATA_AGENT_MCP.zh-CN.md)包含可运行入口。

## 输入、动作、产物

问题：使用截至 2026-10-04 已公开的官方年度材料，比较 AMD 和台积电 FY2023 的营收、营业利润、经营现金流、现金购置固定资产、期末现金。保留真实财年、原币种、单位、原文与审核状态；先查数据库，缺项允许阅读原文但需另标。再验证明确未覆盖的 FY2030 报告范围。

消费者为新启动的 Codex 子 Agent，不继承父任务对话；仅提供通用 MCP 协议客户端、问题和规则，没有提供公司 ID、数据版本 ID、段落 ID、数值或内部数据路径。通过指令限制其只用 MCP，不读仓库或联网；并非操作系统级隔离。消费者使用当前 Codex 会话继承的模型，没有指定其他 provider。运行期间没有 Uteki DeepSeek 调用或新提取。

读取目录与 schema → 显式选择来源/数据版本 → 查询候选 → 阅读原文补缺 → 保存回答。消费者实际 **43 次 tools/call + 1 次 tools/list**，包含两次参数校验失败；不是只统计成功调用。

## 试用发现与本轮修复

1. **已入库记录有精确期间，期间目录却为空。** 根因是目录只看来源 fiscal_periods 元数据。现在补充所选公司/来源/截止日内的观察记录期间，保留原始 basis；不从财年名推算日期，不将 period:null 当全时期。增加了双公司/多期间/候选与截止日隔离测试。
2. **search 的条件必填字段不明显。** 已在工具描述与请求说明中明确 node_id + phrase，read/context/evidence 的字段也分别列出。运行时校验一直存在。模型是否会因此减少错误尚待下一轮验证。
3. **大表的重复单元格字段名占用响应空间。** 增加无损紧凑表示：每张表给出 cell_fields，每个单元格按字段顺序返回全部值，保留空单元格、位置、跨度和正文。原始数据库、索引和文件不改。其他已有调用默认保持 full；MCP 阅读默认使用 compact。
4. **20-F 缺指标可能被说成来源不存在。** 封装前检查已修复缺口判定，年度/季度修订也使用实际来源元数据；这不等于所有旧版 DocumentRequest 检索入口已支持 20-F。

修复后用真实 MCP 回放原请求：两个 AMD 期间目录分别返回 3 个和 2 个期间；台积电无结构化记录，期间仍为空；原先 3 次 context_too_large 读取均成功。对返回的 **26 个块次、3,472 个单元格次**逐项还原，正文与全部单元格等于冻结原件。这是确定性回放，**没有把修复后的输出算进原始 Agent 成绩**，也没有进行第二轮模型试验。见[回放结果](postfix-replay.json)。

81 项定向工程检查通过；锁文件检查和 diff 检查通过。没有进行前端视觉验收。
