# Uteki 界面规范 v1

这是一套约定的设计基线，不表示当前所有页面已经符合规范。用户最新明确反馈优先。

## 2026-10-05：以精简主页统一公司与投资 Agent 页

用户明确认为精简后的机构主页效果最好，要求检查并一起优化公司和投资 Agent 页面。机构主页保持当前构图；公司与 Manager 延续三层外框、固定栏目和既有列表/内容关系。实体名称、icon、公司代码/简介或 Agent 风格/期限统一放入紧凑工具栏，下方栏目尾部放研究数量和模拟身份，去掉重复工作台标题及另占一行的实体标题。旧版对照从设计说明进入。

公司概览直接呈现内层栏目和当前摘要，取消无新增事实的“研究概况”引导行。Manager 概览保留收益、明确日期、当前配置与研究进展；报告/覆盖/操作历史正文首行只呈现计数、模拟信息和筛选，重复的栏目标题保留为屏幕阅读器标题。三类关注阶段标题、原因、日期、报告归属和版本不能因紧凑而删减。数字、表格和长文尺度保持，优先删冗余、减少上方留白；较窄宽度自然换行和阅读滚动。本轮实体页的实际排版仍待用户查看，不将机构主页认可扩展为全页视觉验收。

## 2026-10-05：先调整品牌雨滴，保留当前布局

用户认为侧栏玻璃雨滴的形态不自然，要求先修改 Logo，再看页面其他优化。本轮 C 改用既有、原图封版中的丝绸蓝雨滴，采用此前用户选定的程序抠底方式，保留原图轮廓、蓝色渐变与 S 形留白。当前资源为 `docs/design/company-workspace-swiss-c/assets/uteki-drop-silk.png`，来源和处理记录在同目录 `.source.json`；旧玻璃 PNG 与原图封版保留。此次侧栏使用效果由用户反馈，不称为新品牌图形已封版。

这一步保持已确认的 C 构图、主题和字体切换。后续页面收紧优先检查重复的工作台/机构品牌标题与无信息价值的说明，再处理留白；不在 Logo 这一步同时大改页面。品牌小图形优先复用已认可原图，避免通过生成重画改变形态。

随后用户认可丝绸蓝侧栏效果，并授权继续精简首页。本轮将机构页工具栏与机构大标题合为一个页首，只显示「投资总览」、可点击的模拟身份、日期与币种；机构名称仍保留在标题的可访问名称中。旧版对照从首页工具栏移到设计说明，字体/语言/主题/上下文入口继续可用。去掉比较区与组合区非步骤性的 01 / 02，减少比较带和图表上方间距，保留收益数字及正文尺度。当前精简页待用户看实际效果，不扩展为所有视口已验收。

## 2026-10-04：用户采用 Swiss C 为前台设计基线

用户明确采用 C 版，认可机构首页构图，并随后反馈其他页面也整体不错。后续前台从 `docs/design/company-workspace-swiss-c/` 持续优化；目录名和已有地址保留，v2 / Swiss A / Swiss B 留作历史对照。本条覆盖下方关于试稿待采纳、上方全宽曲线与下方双组 Agent 选择的历史空间安排；不意味着所有细节、所有视口或真实数据能力均已验收。

- 机构首页采用顶部单组 Agent 比较卡，宽窗口中左侧大曲线与投资事件、右侧当前组合的非对称构图。保留明快分类色、清楚字级与数字列对齐，后续保持整体构图和信息层级。
- 公司和 Manager 继续使用已确认的三层工作台。新工作以具体阅读、信息或交互问题推进，不再每轮另起一套风格。字号、间距、长文阅读与空状态可以持续细化。
- Agent 选择仍为手动，曲线与配置联动。Buy/Sell 在曲线上、报告事件在下面；所有标记按实际日期与真实绘图区宽度排布。模拟身份、报告归属、证据和快照规则保持。
- 字体目前保留 C 的 Helvetica Neue / 中文无衬线方案。用户提出研究 Times New Roman 与宋体；新增「瑞士 / 书刊混排 / 经典宋体」同页对照，尚未选定替换默认字体。字体偏好仅影响显示，金融数字与控件保持清楚的无衬线和等宽数字。
- 采纳是用户对当前前台方向的明确视觉认可，不等同于浏览器自动检验、部署、真实账户或后端能力接入。能力差距与数据层研究按用户要求后置。

## 2026-10-04：研究覆盖表达关注阶段

Manager 的研究覆盖按「当前关注 / 历史关注 / 未来关注」分类，只列该 Manager 明确登记的关注关系，不把全公司目录补进来，不以无报告推断未来关注。当前呈现关注问题与开始时间；历史保留关注期间及可阅读的报告；未来显示明确计划原因与加入时间。计划可暂无报告，此时不显示空报告入口。关注阶段、持仓及报告发布状态独立。

无报告且无关注记录的公司不占位。报告公司筛选只包含已有产出的公司；概览研究事项不从空覆盖关系制造任务。样本阶段必须明确标注为模拟，已有报告不能用来倒推当前或历史关注。原公司名单不因 Manager 关注筛选而改变。

## 2026-10-04：前台 Manager 使用紧凑列表

本轮前台反馈优先于下文旧版独立「持仓与表现」栏目安排。Manager 概览合并明确区间的表现摘要、当前公司与现金占比和研究事项表；研究覆盖按公司集中展示，正常桌面以一屏可见为目标；研究报告是独立产出目录；操作历史回看买入、卖出、报告发布。保持三层工作台与现有公司名单，不增加另一套页面结构。

研究表以公司 icon、事项、状态、更新时间、相关产出表达关系，采用有限行数与手动分页。已有研究问题不能伪装成正在执行的任务，研究覆盖不代表持仓，模拟买卖不能充当可对账流水。覆盖到报告保留 Manager 和公司筛选，阅读仍保留报告 ID、版本、返回位置；各 Manager 的筛选和分页状态独立。

## 2026-10-04：后台 Agent 入口使用列表

此规则仅适用于后台 Agent 工作台。Agent 直接列出，不用下拉框；点击名称切换该 Agent 的任务列表。行尾预留设置齿轮位置，悬停或键盘聚焦时显示，点击后查看该 Agent 的配置；触屏提供常显入口。查看配置不切换当前任务，不丢草稿、运行版本或阅读位置。配置信息需注明来源，Demo、缺失字段和真实运行配置分别表达；查看配置不隐含修改或执行授权。

## 2026-10-04：鲜明分类配色与投资事件轴

- 用户不希望饼图为了匹配雨滴 Logo 而采用单一雾蓝或普遍低饱和配色。优先清晰、自然、较鲜明的多色分类；本轮提供「经典 / 明快 / 宝石 / 活力」四套可直接切换的色卡；用户已选定「明快」，作为默认推荐配色及后续图表的分类色基线。现金统一中性灰，分类色不表达收益或风险，同一公司跨 Agent 保持颜色槽位一致，Agent 曲线使用独立颜色。
- 配色选择在本机保留，饼图、列表色标和比例条同步原位更新；不改变持仓、选中项、报告、阅读位置或研究状态。明暗主题有各自颜色值。
- 用户进一步授权前台呈现买入、卖出与报告事件，这更新了此前前台完全不展示交易记录的边界。当前仅为标明模拟的回看标记，没有下单和交易执行能力。
- 收益曲线下方使用对齐日期的事件轨道，只展示当前 Agent。Buy / Sell / Report 和公司 icon 表达类型及主体；日 / 周 / 月聚合与类型筛选独立于收益区间，自动粒度随区间调整，过密标记按可用宽度合并。展开保留每条事件准确日期、作者、公司及报告版本；不遗漏事件，不将聚合标记伪装成精确交易时点。
- 模拟买卖事件独立编写，不从收益或当前持仓反推，也不作为可对账交易账本。报告事件引用已有明确版本的发布日期。原组合与研究样本保持原状。

## 2026-10-01：机构首页比较 Agent，手动切换 Portfolio

用户进一步要求多 Agent 曲线与持仓联动，并希望通过幻灯片式缩略卡片手动切换组合。本节替代下面旧机构总览中“整体收益主指标、中间索引、独立旗下 Agent 板块”的具体安排。

- 首页上方同时比较各 Agent 与基准，使用相同日期与统一起点；点选曲线或图例，选中对应 Agent。Hover 只帮助辨认，不改变正在阅读的持仓。
- 下方一次呈现一个 Agent 的持仓列表与含现金配置图。旁边的方形缩略卡片列提供直接选择、前后按钮及局部方向键；不自动播放，不用滚轮切换 Agent。更多 Agent 沿用可原生滚动的缩略列。
- 图例、缩略卡片和组合标题共享同一个 Agent 选择；切换组合清除上一个组合的配置选中项。区间变化更新所有曲线与收益数值，持仓保持明确标注日期的当前快照，不伪装为历史持仓。
- 机构页只保留全局导航与主内容，移除没有对象选择意义的中间索引；公司和 Manager 页面继续保留对象名单。机构标题使用文字，雨滴品牌只在全局导航出现。
- 组合容器保持稳定，切换只做约 180ms、4px 以内的轻微过渡；减少动效时关闭。首次展示使用具名演示配置，返回保留会话内选择；收益和持仓持续标明模拟。

2026-10-03 细节补充：

- 配置图与持仓列表联动。悬停或键盘聚焦只预览公司、占比与金额；点击固定选中，再次点击取消；移出后恢复已选项。图形和比例按钮操作等价，不在悬停或选择时重建节点、改变路由或阅读位置。
- 从某 Agent 的持仓点击公司，直接打开该 Agent 关于这家公司的明确报告与版本。优先唯一主报告；只有一份时打开该份；多个候选而无唯一主报告时先给选择。没有对应报告就明确显示缺口，不借用其他作者或跳往公司详情。报告返回恢复机构总览及原 Agent / 配置选择。
- 首页标题、模拟标记、日期与币种合并为紧凑的一行；详细样本说明点击模拟标记查看。保持模拟身份可见，减少重复标题与独占一行的说明。

## 2026-10-01：前台以机构投资总览为首页

用户进一步明确本窗口只负责前台，后台在另一处设计。首页主体为 Uteki 投资机构，旗下 Agent / Manager 是下钻维度，不以 Manager 名单取代机构首页。此规则优先于历史“公司优先入口”及“Manager 总览首页”安排。

- 首页先呈现机构整体表现与 Portfolio：明确区间的收益、持仓公司及占比、含现金的配置图，再展示旗下 Agent 各自的收益和研究入口。机构组合与 Agent 组合需有各自口径，不能把 Agent 收益简单平均当作机构收益。
- 从机构持仓进入公司，从 Agent 进入其表现、持仓、研究报告和待验证问题。前台展示投资与研究结果，不展示下单操作、交易流水或内部执行过程。旧操作页仅保留报告发布历史供历史链接读取，不再进入前台导航。
- 用户明确允许本轮使用标注清楚的模拟收益和持仓数据，以评审完整展示效果。样本独立、具名且版本化，持续显示“模拟数据 / 非实盘”、日期、币种和收益区间；不得改变原研究数据或暗示账户已接入。模拟持仓不能从研究覆盖推导。
- 沿用三层工作台和紧凑标题；机构中间栏为总览目录与 Agent 快捷入口。Portfolio 采用持仓列表与配置图并列，比例可选中查看，公司名称另行进入研究。收益区间切换统一更新机构、基准、曲线和 Agent 口径。
- 本轮聚焦机构总览。公司报告卡片、分页查询和公司内多 Agent 切换方式留到后续逐项设计，不在这一轮扩展。

## 2026-10-01：公司概览按栏目展开，右侧可直接切栏目

用户已认可 nav5 的三层外框与最左导航 Hover 推动效果。后续逐块完善内容，不重新改造已确认导航。

- 当前对象的栏目在右侧标题下保持可见，可直接切换概览、研究报告、资料与数据、关注点；左侧悬停目录继续作为快捷入口。共享工作台中的 Manager 栏目沿用同一位置，具体内容分别设计。
- 公司右侧各栏目优先复用“左侧内容列表 + 右侧详情”的结构。研究报告按 Manager 整理目录，打开后保留目录、显式报告和版本，正文获得主要宽度；资料按证据条目选择来源详情，关注点按问题选择变化与关联报告。详情由明确选择打开，无选择时给出简洁入口提示，不擅自替用户指定一份报告或材料。
- 概览允许 hover 预览；长报告、资料和关注点通过点击选择，避免阅读时被鼠标经过打断。内层目录和外侧公司名单职责不同，内层目录保持紧凑；顶部工具、公司标识与栏目减少多余留白，把纵向空间交还阅读区。
- 公司概览默认是桌面一屏内的摘要：左侧四个栏目标签（动态、报告、资料、关注点）及各自数量保持可见，右侧只展开当前一块内容。用户明确选择手动切换，不自动轮播。悬停停留约 140ms 后切换，快速经过取消；移到内容区或移出概览后保持所选栏目，点击和前后按钮提供等价操作。方向键只在栏目标签获得焦点时切换，正文保持原生阅读。
- 切换仅在同一内容区做约 180ms 淡入及轻微位移，减少动效设置关闭动画。每家公司在会话内记住概览栏目；键盘正在阅读内容或证据时，鼠标经过标签不能抢走焦点。完整事件和报告清单从入口打开，不依赖缩小正文字号、截断整块或强制分页。
- 消息式点标和数量用于表达已有变化、待验证问题、审核状态或资料缺口；未建立阅读状态契约时不能宣称未读或点击即清零。独立报告份数不重复计算版本，证据条目不冒充文件份数，自动跟踪未接入时不显示运行进度。
- 每块最多显示少量预览，其余内容必须有完整入口；事件详情保留报告、版本、段落和证据链接。缺失数据仍显示所属模块和明确缺口，不借用其他公司内容。完整报告与详情继续原生滚动。

## 2026-09-30：固定工作台外框，以实体组织内容

用户指出公司与 Managers 之间切换时页面变化过大，明确要求类似持续使用的工作台：左侧实体列表及二级内容目录，右侧展示该实体的属性、关系和产出。本规则优先于此前将 Manager 入口导向独立结构稿的过渡方案。

- 公司与 Manager 共用品牌区、左侧导航、顶部工具栏、实体标题、正文及可收起上下文。切换只改变实体和正文，不能跳到另一套设计文档或重排整个布局。
- 实体类型 → 具体实体 → 内容类别保持两级关系。根据用户后续明确反馈，悬停公司或 Manager 后在侧栏旁浮动显示内容目录，离开后收起；不在列表中插入展开子项或改变行高。点击内容项才切换正文，hover 不标记已读。键盘与触屏保留显式打开按钮和 Escape 关闭。
- 用户进一步明确三层：最左是工作台导航（公司 / Managers），中间是当前分类的对象列表，右侧是所选对象的内容。品牌与分类入口归全局导航；搜索、对象名单和对象内容菜单归列表。两层导航不再挤在同一个区域。
- Hover 展开的是最左工作台导航，对象列表始终可见。全局导航默认约 60px 窄图标栏，进入约 80ms 后展开至 184px，离开约 180ms 后收回；通过约 240ms 的列宽过渡平滑推动列表与正文，不遮盖内容，不缩放文字。不增加固定按钮，不沿用旧版侧栏隐藏偏好；提供键盘焦点与点击开关的等价入口。
- 实体内容目录继续独立悬停浮出：打开约延迟 160ms，移出约 220ms，允许跨过菜单间隙。全局导航动效不选择对象、不重建报告、不修改研究状态；宽度变化时保持可见阅读锚点，菜单随所属列表定位。减少动效设置关闭过渡。
- 品牌雨滴使用原图确定性抠底的透明 PNG，保留已确认的蓝色与玻璃纹理。不得用重新生成的相似 Logo 替换；不再用白色裁切容器掩盖原底。
- 公司目录包含概览 / 最新动态、研究报告、原始资料与数据、关注点 / 持续跟踪；Manager 目录包含概览、研究覆盖、研究报告、持仓与表现、操作记录。内容类别适应实体，不强迫两种实体具有相同字段。
- 报告沿用同一个阅读器。由 Manager 打开某家公司的报告时保持当前 Manager 左侧入口；点击公司名称才明确进入公司视角。公司报告始终保留唯一公司、Manager、报告 ID 和版本。
- 切回实体类型或已读对象恢复最近页面和会话内滚动位置。侧栏展开 / 收起仅影响导航，不重建正文或改变阅读位置；滚轮继续只负责原生阅读。
- 关注、研究覆盖、持仓分别建模。收益、持仓、交易缺失时显示对应缺口；报告发布属于研究记录，不能冒充交易。“transfer report”等尚未明确的产物类型不擅自新增业务定义。

本轮实现范围为 `docs/design/company-workspace-v2/` 的独立交互样板，原产品原型未迁移，不代表后端或视觉验收完成。

## 2026-09-30：结构设计与 Manager 入口的新优先级

用户要求先设计页面与交互，并逐区域标注展示内容，避免把模块边界与具体样式混在一起。本轮先制作独立的 [页面设计稿](../../../docs/design/page-blueprint/index.html)，已有产品页面保持原状；沿用不使用 frontend-design 的明确要求。

- Manager 总览首先展示有明确区间与口径的表现；进入详情首先看持仓构成（含现金）、持仓公司和交易记录。研究覆盖与报告作为相关内容，不能以研究目录替代 Manager 的组合视角。此优先级覆盖下节旧方案对 Manager 入口的目录优先安排，尚未在生产原型实施。
- 公司、Manager、公司研究报告的归属保持明确。关注、持续研究覆盖和持仓是不同关系；公司报告与跨公司的组合报告需分别定义，不强行用单一公司承载组合报告。
- 标注设计以用户问题、字段、来源、动作、异常和返回路径为单位，分别标记已明确需求、设计建议、待确认问题。示意数值、可点击线框和已有后端能力不得混同。
- Data Agent 和 Analysis Agent 是内部执行角色；前台呈现资料、数据、研究、决策和证据结果。数据能力涵盖自主获取、监控、处理核验、查询计算与证据交付，不缩减为 Text-to-SQL。

## 2026-09-30：双入口与独立报告目录

用户纠正并确认公司 n:m Manager、报告唯一属于一家公司和一位 Manager。本轮采用前述推荐的“主报告＋专题报告，各自管理版本”。此结构优先于上一阶段进入公司即直接打开某位 Manager 报告的默认方式。

- 左侧公司入口：选公司后，右侧展示这家公司的研究目录，按 Manager 分组；Manager 入口：选 Manager 后，右侧按公司分组展示其研究。筛选只收窄当前目录，不混同入口对象。
- 报告拥有独立身份，版本属于报告；不能用公司＋Manager＋版本号替代 reportId，也不能把多份专题当作主报告的旧版本。报告份数不重复统计版本。
- 点击报告后，两入口共享同一个正文和已读状态；同一公司与 Manager 的其他报告保持独立。返回恢复目录筛选、原行与位置。比较右栏证据的作者与左侧入口对象分别保存，不因查看另一位作者而跳走左侧选择。
- 右侧目录使用文字分组、紧凑行和细分隔；不增加第二列常驻对象列表。既有阅读字号、双主题、本地图标及原生滚动保持。Manager 组合维度独立；无数据时明确未接入，不显示虚构完成状态。

## 2026-09-30：报告阅读样板（第 1 阶段）

用户批准网页改版计划并继续实施样板。此次明确的样式工作采用 [网页改版计划](../../../docs/design/UTEKI_WEB_REDESIGN_PLAN_v1.zh-CN.md)，不使用 frontend-design。以下是当前 `apps/uteki_zero/` 阅读入口的实施基线，优先于下方历史分屏和方向键导航约定；尚未宣称用户视觉验收通过。

- 公司 × Manager × 已发布版本始终显式；连续报告是核心阅读对象。左侧公司、顶部 Manager 与版本、右侧目录，不再强制正文分页或整屏推移。
- 鼠标滚轮、触控板和方向键用于原生阅读，不切换对象。引用在当前阅读区打开，返回原版本、原列、段落和焦点。
- 日间采用冷灰背景 `#f5f6f7`、纸面 `#fcfcfa`、文字 `#252b33`、蓝色强调 `#355d9f`；夜间对应 `#15181d`、`#1c2128`、`#e2e6eb`、`#98b7f1`。不是整页滤镜反相，公司 icon 保留品牌原色。
- 正文默认 17px / 1.85，可选 16/18px；主要阅读宽度约 720px。章节依靠文字、留白和细分隔组织，不重复包大卡片。
- 公司列表与静态雨滴原素材保留；组合、行业、工程后台仍按计划分期交付，旧版独立入口不等同新方案完成。

## 2026-09-29：架构阶段先定义功能与注意力

当前 Agent 契约与前后台交互设计阶段，按用户要求不使用 `frontend-design`，不做样式与美观设计。交付聚焦主要对象、用户问题、信息优先级、动作、反馈、状态和可见性；用功能线框检查实际研究任务。

既有视觉参数保留供后续明确的视觉工作使用，本阶段不据此制作新页面。设计建议应说明理由、代价与可验证例子，不把讨论中的个人想法直接写成已确认需求。新技术需有一手依据，并区分设计提案与已实现能力。

核心交付是可独立阅读的正式研究报告，减少用户与 Agent 的交互。公司与 Manager 入口提供报告阅读、证据追溯、版本变化与报告比较，核心内容不依赖用户先追问。内部 Agent 自主研究、补数与审阅；前台阅读已有产物不启动模型。动态 UI 暂缓，问答仅保留为未来可选补充。

## 2026-09-25：首页从零探索的最新结构约定

用户否定旧首页效果，明确要求从 0–1 重新设计、不依赖已有实现。本次独立原型 `apps/uteki_zero/` 不沿用下文的旧版配色、布局及原生滚动限制；旧工作台维持原规则。新原型的视觉仍待反馈，不视为已经批准的新视觉基线。

- 固定一屏：左侧选对象，右侧标签切内容。公司研究与组合管理是同一个工作台中的两个独立视角，以公司和组合分别为主对象。
- 同层级条目通过点击切换，保留方向键辅助操作。2026-09-29 用户明确取消滚轮／触控板滑动切换，认为阈值吸附不自然；滚动只用于原生阅读，不改变当前选择。
- 顶部工作区、左对象列表、右内容标签通过明确按钮选择；正文条目通过前后按钮或页码圆点切换。鼠标所在位置不再决定滚动切换的层级，正文页脚说明当前序列。
- 两个工作区及各对象保留各自的选中标签、条目和未保存笔记草稿；点击与方向键也能完成同样操作。已读、待复核、笔记、主报告版本继续独立。
- 内容优先分屏组织；极小窗口或缩放下保留正文内部阅读兜底。滚动至正文边界后停止，不自动翻页，也不在下一段手势中切换条目。
- 此轮覆盖新原型，不把试验规则自动扩展到现有报告编辑、数据表等页面。

## 2026-09-29：公司标识采用 icon

- 列表、详情标题、持仓中的公司标识使用紧凑独立图形，配圆形容器；公司名称显示在图标旁。参考用户提供的 TradingView 列表截图。
- 优先使用经核对的 icon 素材及其原有品牌颜色、留白和背景。不能把完整横向字标缩小后充当 icon，也不自行从字标裁图或重绘。
- 素材注册表显式区分 `presentation: icon` 与 `wordmark`；图标槽位只读取 icon。规则适用于未来新增公司，不能依赖固定公司分支。网站图标或第三方证券图标的来源、身份映射与核实状态单独记录。

## 页面结构

- 公司是研究主入口；报告、新闻、材料、组合关系挂在公司下面。
- 首页以管理投资者注意力为目标：优先展示已关注公司中已有判断的变化，再展示值得开始研究的新公司及理由。每家公司维护一份主报告，追踪记录与专题报告围绕它积累；变化、证据与持续任务必须能回到具体报告因素。
- 自主研究与委托经理组合使用独立视角。前者关注判断、证据及其持仓含义；后者关注经理的持仓、动作与收益。经理角色不等同于研究报告的作者，组合动作不代表用户个人决策。
- 公司研究页只保留一个“分析报告 / Reports”入口；公司根路径和报告路径共用该入口，不再并列展示相同内容的“研究详情”。
- 标准工作台保持一个窗口：固定全局导航和必要操作，内容在明确的板块中连续滚动；公司 thesis、长文、数据库页可使用适合阅读或表格的布局。
- 优先原生触控板上下/左右滑动，不用箭头分页作为主要浏览方式。不劫持滚轮，不强制整屏吸附。
- 卡片边界稳定。展开内容发生在当前块内部，其他卡片不换位、不缩小。不用遮罩或鼠标旁弹层展示普通阅读内容。
- 全局导航结构一致；只有用户触发的导航展开可按上述约定平滑推动内容，正文滚动不改变导航宽度。保留对象列表与全局导航的清晰层级，消除重复品牌栏。
- 高密度桌面布局在窄屏可切为模块横向浏览。不可通过隐藏核心模块或操作假装适配成功。
- 本项目以桌面研究工作台为主要验收对象。默认使用用户的正常桌面视口；未经用户要求，不主动切换手机/H5 视口验收。通用前端技能的响应式建议不改变此优先级。

## Hover、展开与动效

- Hover 是提示和预览，不是完成操作。使用浅底或内容显现，不出现粗描边、左侧竖杠、漂浮工具团、按钮放大。
- 键盘 focus-visible 保留清楚的焦点提示；不可为消除鼠标圈把键盘可访问性一起删掉。
- 预览空间预留，hover 不改变行高，不把下一家公司推走。信息太多时点击进入块内阅读。
- 进入预览可延迟约 200ms，离开延迟约 250ms；滚动经过不触发抢眼展开。点击固定，移动鼠标不能关闭正在阅读或编辑的内容。
- 按钮/底色约 120–160ms；块内内容约 180–220ms，位移最多 2–4px。使用同一 ease-out 曲线，避免弹簧、缩放、逐卡入场与整页飞入。
- 关闭恢复原滚动位置和焦点，动作按钮始终可达。响应 reduced-motion，不用动画掩盖加载。

## 内容与状态

- 一个事实只维护一份事件/版本状态，不因为在多个板块出现而重复计数。近期、历史、未读是视角，不是重复的数据清单。
- 已读不等于已审核或已采纳。Hover 不标记已读；操作失败不能显示成功。明确本机状态与服务端同步的差别。
- 新增公司显示加入理由和来源；缺失就显示待补，不代写成事实。
- 候选、未知、未接入保持真实。页面不展示实现细节、测试标签、提示词和无助于判断的说明。
- 原始材料、来源时间、修订前后与作者可追溯。研究编辑仍遵循项目快照与采纳规则。

## 交付与收敛

修改前选定参考组件，不每次另起风格。优先修正原规则，避免在共享 CSS 尾部无限覆盖。把视觉调整限制在用户授权页面，保留业务状态。

默认验收方式（2026-09-23 用户约定）：Agent 优先检查数据结构、字段映射、来源对应和代码逻辑，运行与改动相关的必要检查，通过后交付。页面视觉 review 由用户负责，不默认打开浏览器、反复截图、切换语言/视口验收或为细节多轮调整。用户明确要求视觉检查，或必须在浏览器复现具体问题时，才做定点检查；不因缺少视觉验收阻塞交付和已授权开发。这一约定优先于通用前端技能中的强制视觉验证建议。

按需视觉 Review 清单（供用户检查，或明确要求 Agent 视觉检查时使用）：
1. 首屏能否辨认主对象、变化和下一步？有无重复栏目与冗余大标题？
2. 字体与元信息层次是否稳定？浅色文字是否可读？中英文是否都成立？
3. 滑动、hover、展开、收起是否保持位置连续？有没有跳动或遮挡？
4. 鼠标、触控板、键盘、窄屏与减少动效是否有等价路径？
5. 已读、审核、空状态、失败状态是否真实？
6. 分别记录自动检查和实际视觉验收。未看过真实页面不得声称视觉通过。

正常交付附页面入口、已完成的自动检查和已知限制，视觉反馈随后处理；不因为可以再设计就无限扩展范围。


## 2026-10-04：投资总览图表的最新交互

## 2026-10-04：曲线交易与持仓时间轴的进一步调整

## 2026-10-05：Swiss C 本轮交互与报告呈现基线
