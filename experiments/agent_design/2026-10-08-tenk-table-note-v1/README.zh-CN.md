# HTML 10-K：财务表与表格形态脚注的读取修复

本阶段按用户最新范围，只核查 HTML 10-K。**已关闭一个真实缺陷：主表后的脚注本身被 HTML `table` 排版时，读取主表会遗漏该脚注。** 此次不改变原始财报、不重写冻结底稿，不调用模型或网络。

## 本轮完成

`reading-groups-v0.3` 在读取时把相邻的脚注表与主表组成一个上下文。原文块、单元格、金额和单位均不改动。

| 实际输入 | 原读取结果 | 修复后的结果 |
|---|---|---|
| AMD FY2023，客户集中度表 block 804 | 遗漏 block 805 的 `* Less than 10%` | 主表与完整脚注一起返回 |
| AMD FY2024，客户集中度表 block 800 | 遗漏 block 801 的同类限定 | 主表与完整脚注一起返回 |
| Alphabet FY2025，准备金变动表 block 1306 | 遗漏 block 1307 的 `Note:` 说明 | 主表与完整说明一起返回 |
| Microsoft FY2025 全份已解析底稿 | 没有匹配本次新增规则的脚注表 | 全部分组成员保持不变 |

三个修复样例都验证了 `read(count=1)`：只比原来多带应有的脚注块，不吞入后面的段落或其他表格。从脚注反向读取也可看到对应主表。四份底稿的 blocks、index 和 manifest 的 SHA-256 均保持不变。

**判定规则来自结构，不含公司答案。** 每个非空行必须恰好有两个非空单元格：独立脚注标记与解释文字。符号/编号还须与主表中的独立标记格相符。`Note:` 可按紧邻的显式说明关联。`*10.28` 等展品索引不是独立脚注标记，不会被并入。跨 Part/Item 或超出用户所选阅读节点时，不扩展读取范围。

新增 `note_links` 保留脚注块 ID、标记格坐标、定义格坐标、匹配的主表单元格坐标与关联依据。`semantic_applicability: not_inferred` 明确表示这只是可检查的阅读上下文；不能把符号匹配自动当作已验证的财务口径。
