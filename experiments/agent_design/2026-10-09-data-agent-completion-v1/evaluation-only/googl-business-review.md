**Cloud 列表的 103/104 不是缺业务。** 103 原文仅 `5.`，类型为 page_marker；104 是 `Table of ContentsAlphabet Inc.`，标为 running_header。其组元数据明确：

## 工程问题与保护边界

第一轮唯一 query gap 来自全文搜索 `Google Services` 的分页 `limited`。第二轮另有一次 `reportable segments` 无字面命中；第三轮同样有无命中和搜索分页。该轮运行代码将这些搜索诊断永久添加为 requirement gap，后续成功阅读不能消解。**单次词未命中或有下一页，不证明材料缺失。** 搜索收据应保留这些限制，但不能自动阻止已取得充分原文的任务完成。真正未取得信息应由明确缺口及交付/审阅检查处理。

第三轮选择被拒的两个 ID 是 `block-001235`、`block-001236`；冻结的已读 ID 分别为 `block-001235-68dbd7dd`、`block-001236-2f8c99ac`。因此准确原因是模型截掉了身份后缀，而非对应原文从未读取。两处也都是页码/页眉。严格身份拒绝正确，不应加入猜测 ID 的兜底；更好的错误反馈可以指出具体不合法的选择项。

第二轮没有 `select_evidence`，第三轮没有成功完成选择。因此没有把探索中的全部材料隐式交给 Analysis，这项边界正常。SSLError 是传输失败，不能算内容评测失败或假定成功。
