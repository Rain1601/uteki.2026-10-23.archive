## 本轮修复

`download_policy=reuse_verified` 原先只在调用者显式提供 CIK（SEC 公司身份编号）时读取旧文件。调用者通过股票代码解析出同一家公司时，即使旧原件已校验，也会再次下载。

现在先收集历史候选，待本次 SEC 公司身份核验完成，再按匹配 CIK 载入候选。复用前仍检查文件路径、字节哈希、公司身份、文件类型及报告期间。保留逐文件回执的崩溃恢复方式。不同公司的记录不能提供复用候选，不以股票代码相同替代身份匹配。

改动：

- `src/uteki/infrastructure/document_sources/company_acquisition.py`
- `tests/unit/test_acquisition_recovery.py`

离线验证：73 项获取、传输、恢复、范围目录、重放及 CLI 测试通过。新增行为检查证明：股票代码解析后只重新读取公司身份元数据，不重复下载已验证报告；仅有逐文件回执时也可恢复；同股票代码但不同 CIK 的缓存被排除。现有测试覆盖另一个公司、另一个期间、缺失范围、错误来源与损坏原件恢复。

## 当前支持与缺口

已有通用能力：明确代码/CIK 身份；截止日期；指定 10-K / 20-F 报告期间或范围；修订文件保留；按最新 10-K 与后续 10-Q / 8-K 获取；8-K 附件发现；显式认可域名的 IR / Blog / Events 有界发现；不可变原件、哈希、身份验证、费用为零的本地复用、失败及冷却状态。

尚未证明或未完成：

1. 五家公司同一入口的明确来源配置和同范围获取验收。现有注册目录仅 AMD / TSMC 年报 profile。
2. 统一支持 NVIDIA 现存 PDF 的身份与派生材料契约，或取得并验证明确指定的 SEC HTML；不能悄悄回退到别家公司/期间。
3. 官方发布稿、电话会文字稿的存在性和完整性判定。页面发现有界且主动记录 coverage gap，不能当作穷尽证明。
4. 全新公司自动身份/配置输入的盲验；通用函数接受明确输入，不代表当前目录支持任意公司。
5. 官方材料“已获取”与“提取正确”是不同验收。此处哈希、身份或索引文件存在不证明表格/业务解析质量。
