## 3. 获取后如何处理：三个边界

1. **结构化数值**：保留原响应/许可内可留存快照、供应商原指标与原值；核验身份、期间、单位、维度、版本和证据后，才建立统一查询记录。标准化映射不覆盖原披露事实；映射不明列 unmapped，不猜指标。
2. **文档与缺失事实**：保存原件及目录、章节、表格/单元格、正文证据；先消费原件已有 iXBRL/XML 标记，缺失或未标记部分再解析 HTML/PDF/文字，扫描图像确有需要才 OCR。解析数字必须连同定义和条件；文档保存不等于事实可查询。
3. **计算与解释**：基于已验收输入显式计算，保留公式/版本/输入关系；管理层解释按证据检索，分析推断单独标明。SQL查询不承担猜口径、补事实或合并冲突版本的职责。

这里只定义责任边界，不新增数据库设计、爬虫平台、OCR/Agent开发或自动调度。

## 4. 所有来源共用的验收门槛

| 验收项 | 完成条件 |
|---|---|
| 范围 | 运行前固定类别、材料/系列清单、历史跨度、cutoff、版本视图及期望更新频率；扩展不继承财务时间窗口 |
| 完整性 | 文件目录与内容事实分开验；财务分母来自独立原件清单，主表全部行/列、全部附注表格与正文定量事实、财务补充均纳入。不是供应商返回多少就算应有多少 |
| 正确性 | 原值/符号/单位、时点/期间、维度/实体、上下界和限定条件一致。合计对账只能提供检查线索，不能证明语义正确 |
| 追溯 | 数值回到原表行列或原文精确片段；论述回到准确证据；供应商与原件映射可复核。整份报告链接不替代精确出处 |
| 版本与历史可得性 | 原/后续版本不覆盖；披露公开时间、供应商可得时间、本机获取时间分列。没有供应商历史可得证据就不声称当时接口已可提供；不拿最新重列补历史cutoff |
| 缺口与冲突 | 未披露、尚未披露、权限不足、获取失败、未映射、解析失败、含义冲突分别记；缺值不填零，重复事实不相加，冲突不静默取首条 |
| 稳定性 | 记录发现完整、分页/历史补取、重复获取、失败恢复、更新延迟、修订留存；短期成功/缓存命中不证明长期稳定。DS-03既有三轮/十交易日规则不改，扩展另冻结适配标准 |
| 权限与费用 | 确认可用接口、历史、原件、留存及使用权限，记录实际费用/失败；先满足效果和可靠性，再比费用；本表不授权采购 |
| 结论 | 文件通过、事实覆盖通过、查询通过、真实Agent业务通过和稳定性通过分别报告；独立原件核验不由模型自审替代 |

核心最终完成要求：冻结范围内每个应有事实均可按原含义查询并带证据；缺失可以明确报告，但不能因此把“完整财务”勾为完成。区间/条款/多维事实可以不是一个标量字段，仍须可按其含义查询。

## 6. 财务核心来源分工与获取方案 · v0.2

### 6.1 主源的两种职责

- **事实依据主源**：SEC 申报原件；公司官方 IR 对未在 SEC 出现的财务补充/定义作为对应事实的一手依据。SEC 不自动优先于更新后的 IR 版本，按来源、公开时间与版本差异核验。
- **数值获取主源**：优先选择一个有合法权限、覆盖与出处通过验收的专业数据源。当前只是选型建议，不把候选名称写成“已接入/已选定”。原披露（as-reported）与标准化（standardized）同时区分，原披露优先满足完整覆盖；跨公司标准化是另一个验收维度。
- **补源**：SEC 原件已有 XBRL 标记、HTML 表格/正文，以及官方 IR 独有财务披露。第二专业供应商用于明确缺口或有争议的对照，不默认多路全量接入。

没有专业权限时，来源能力/成本这一项仍待确认；不因此自动把全部工作改成自行解析。对专业源明确覆盖不到的事实，解析原件属于补缺路径；对权限未知的事实，先标“权限/覆盖待核”。

## 10. 当前数据源职责方案 · v0.6

本方案先保证不用付费源也能建立完整、可追溯的事实基础。FMP 是可替换的结构化加速层，尚未采购或通过真实数据验收；即使以后接入，也不改变官方原件的事实主源地位。

| 层次 | 已明确的数据源 | 负责内容 | 不承担什么 |
|---|---|---|---|
| 事实主源 | **SEC EDGAR**：Submissions、申报索引、10-K/10-Q/8-K及附件、iXBRL/XBRL | 申报目录、原件、accession、公开/修订版本、原披露事实、上下文/单位/维度及证据 | CompanyFacts 不作为全部附注或全部分部的完整来源 |
| 官方补源 | **公司 Investor Relations** | SEC未完整覆盖的业绩发布、财务补充表、官方工作簿、非GAAP调节、KPI、指引和定义 | 不以新闻转载、聚合站或搜索摘要替代公司原件 |
| 免费结构化入口 | **SEC CompanyFacts / CompanyConcept** | 标准taxonomy、整发行人事实的快速发现、初步查询和交叉核对 | 不覆盖所有自定义标签、多维分部、正文条件和全部附注 |
| 专业结构化候选 | **FMP Premium** | 标准季度三表、部分原披露标签、产品/地区收入及报告JSON，降低首轮取数和标准化成本 | 不作为完整性分母；不单独证明精确出处、全部附注、历史版本或PIT |
| 自有派生层 | **项目内显式计算** | 经验证输入上的Q4、TTM及约定指标；保存公式版本、输入和证据 | 计算结果不能伪装成公司直接披露或供应商原值 |

### 10.1 冲突与缺项规则

1. 同一事实出现冲突时，先按发行人、accession、报告期间、单位、维度和修订版本核对；当前有效的 SEC 原件决定“公司披露了什么”，历史版本继续保留。
2. IR 独有披露作为官方补充事实保存，并记录公司URL、发布时间和取得时间；如果同一文件也提交 SEC，关联到对应申报，不重复算两条事实。
3. FMP 与官方原件不一致时记录差异，不静默覆盖。没有精确映射的供应商值可以用于候选查询，不能标成已完成追溯。
4. 完整性分母来自 SEC＋IR 原件清单；供应商返回多少字段不决定覆盖率。缺失、未披露、不适用、无权限和解析失败分别记录。

### 10.2 当前选型状态

- **已确定的必需来源**：SEC EDGAR＋公司官方IR。
- **已确定的免费结构化入口**：SEC CompanyFacts / CompanyConcept，但只在其官方覆盖边界内使用。
- **唯一优先付费候选**：FMP Premium。SimFin BASIC、EODHD Fundamentals保留备选，不并行接入；Daloopa、S&P、FactSet因无明确公开价暂后置。
- **尚未决定**：是否购买FMP。只有真实样本证明它能明显减少取数/映射工作，并确认许可、版本和留存边界后才采购。

本节明确来源及职责，不代表获取、解析、准确性或稳定性已经通过，也不启动具体公司、采购或开发。下一步只把采购前真实验收的最小样本、字段清单和通过条件冻结下来。
