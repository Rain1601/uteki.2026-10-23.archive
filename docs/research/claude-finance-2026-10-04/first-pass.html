用户在哪个界面工作？

入口负责的工作需要区分
Claude Chat提问、读材料、研究与草拟；查看回答及成果。对话界面是工作入口。
Cowork围绕任务操作本地文件和连接应用，分步骤完成产出。金融插件提供业务方法与工具组合。
Claude Code在代码库、数据管线和自建工具中工作。可以运行相关插件；本身不是特定投资经理。
Excel / PowerPoint 等在原工作文件旁分析、编辑、检查，再形成汇报。工作簿、报告和演示文稿可以保留为独立成果。
Claude Platform把模型或托管 Agent 接入机构自建应用。这是定制入口；不能等同 Cowork 的内部实现。

入口分工依据：官方部署指南（第 4、6–8 页）。跨应用协作：Cowork 与金融插件说明。这里整理产品分工，未登录账户实测。

Managed Agents 公开到什么程度？

官方 API 文档定义四个概念：Agent（模型、提示词、工具和技能），Environment（执行环境），Session（一次运行），Events（输入、工具结果、状态等事件）。应用创建配置、发起 Session，通过事件流观察和追加指令。文档还列出定时执行能力；这些属于平台能力，不能推定每个金融 Skill 已配置了持续任务。公开运行文档

与 Uteki 的关联，仅作为待讨论的映射

Analysis Manager 可对应“研究职责＋投资方法＋执行配置”；Data Agent 可提供取数、处理、查询与证据产物。但所查金融仓库没有展示一个与我们完全对应的统一 Data Agent，也不能从 MCP 接口推断其后端使用 Text2SQL。

需要继续区分三个问题：模型怎样选工具，数据工具怎样返回可信数据，产品怎样保存研究状态并展示变化。目前公开资料对前两者的接口与参考方法更清晰，对供应商数据处理及产品内部状态存储披露有限。

03 / 走一遍：财报发布后更新研究

已读源码以 Earnings Reviewer 为例。这里描述参考模板的要求，尚未运行金融模型或调用数据商。

步骤实际职责交付 / 检查点
1. 定义输入指定 ticker 和财报期间，提供或定位覆盖模型。公司、期间和既有研究上下文要明确。
2. 取得原始材料通过 FactSet / Daloopa 获取实际值、共识、申报文件，并读取完整电话会。原文与来源；缺出处的数字需要显式标记。
3. 分析本期变化earnings-analysis 分析指引、驱动及电话会信息。哪些变化触及原有论点。
4. 更新模型model-update 更新实际值、预测与差异。变更单元格应能追溯到来源。
5. 检查计算audit-xls 检查平衡关系、断链和计算单元格。方法指令不等于已通过实际验收。
6. 生成研究草稿组合差异表、模型和研究快报。供分析师复核的草稿；模板不承担对外发布。

逐步依据：Earnings Reviewer 业务流程；模型更新与审查技能。

为什么还拆成多个 worker？

Managed 示例把电话会阅读、模型更新准备和最终文件写入分开配置。它们的工具权限并不相同：主 Agent 可以调用子 Agent；最终 writer 没有 MCP，接收整理后的材料写文件。这个拆分展示了职责和工具边界，并未证明所有提示词约束都已由程序强制保证。主配置 · writer 配置

数字、图表和报告究竟在哪里生成？

公开 DCF 方法区分两种执行环境：Excel 内通过 Office JS 写公式、由 Excel 计算；独立文件使用 Python/openpyxl，并要求重算。图表技能调用 Python 图表库；报告组装读取前序文本、工作簿和图表。计算路径 · 图表 · 报告组装

不同技能的自动化程度不同。初始覆盖技能明确每次只做一个阶段，需要核对前序文件后继续；Thesis Tracker 描述证据更新与跨会话保存要求，但自身不提供数据库或调度实现。初始覆盖边界 · 论点跟踪边界

06 / 瑞士风格：研究问题，尚未采用

研究重点是信息组织方法：网格怎样建立秩序，文字怎样形成层级，色彩怎样服务表达。不能仅用“少颜色、去圆角”概括，也不能直接把海报规范移植到金融工作台。

研究方向来源支持的方法先避免的误解
网格组织Müller-Brockmann 将网格作为组织视觉信息的工作工具，展示不同分区和应用。Niggli · Grid Systems（1981）网格不意味着所有内容使用等大的方格。
字体与层级Emil Ruder 的方法强调结构、可读性、节奏和比例。Niggli · Typography（1967）不能简化为某一字体、大标题和黑白配色。
色彩与信息秩序展览强调几何结构、精简构图和快速理解；作品包含黑白及鲜明红色。Poster House · The Swiss Grid没有依据要求只能使用低饱和色。

对 Uteki 的待验证推论：固定对齐和数字列有利于横向比较；稳定字体层级可能减少无意义卡片；鲜明颜色仍可用于区分公司或曲线。代价是过硬的网格可能压缩中文长标题和报告阅读空间。这些要拿真实内容比较后判断，不是本轮样式决定。
