Load this skill when planning or querying. Its content and hash stay frozen for the run.

Business composition and revenue composition are distinct question dimensions. For business-composition requests, plan and obtain the source's definition of each requested business/segment's principal products, services or activities, their affiliation and necessary qualifiers. Revenue or monetization categories alone are insufficient. A product/platform can define the business even without a separately reported revenue line. Preserve the relevant definitional enumeration, not every product mention across the report. Verify this coverage before trimming material. For pure revenue requests, retain the numbers and necessary period/unit/accounting context without forcing a product catalog. Describe the requested dimension in requirement descriptions; do not narrow the original question to what the first search happened to find.

record_origins shows accumulated same-scope query record evidence IDs with immutable original citation locations, short quote previews and requirement_ids identifying the queries that returned each record. Only those requirements may select it. Compare related criteria together before choosing equivalent occurrences; prefer an already verified coherent original context when it supports several requested facts with all needed qualifiers. Do not choose the first returned record independently for each criterion merely because it matches numerically. Related criteria can share one query requirement. The host supplies navigation metadata and never makes this semantic selection for you. It stays available after reading source blocks; use its exact continuation cursor for omitted entries and each citation's read_request for complete metadata. These are navigation aids, not body reading. Inspect the original locations before selecting equivalent occurrences. A reviewer's cross-check citation does not replace a record's original source. Selecting or omitting source_evidence does not change a selected record's citation or its table context. To remove an unnecessary table, select another already-queried occurrence satisfying the same entity/metric/period/value_kind criterion with sufficient original evidence; never rewrite its source identity. Keep necessary units, headings and qualifiers.

Plan explicit requirements. Use kind=read_node with source_id and node_id whenever complete chapter reading is required. The host tracks required, returned and unread body IDs, rejects premature finish and preserves remaining gaps.

Use kind=query with an explicit QueryPlan for numeric requirements. Entity, periods and formula must match the requirement and pinned scope. The host verifies records, citations and registered calculations; Business text cannot satisfy a margin requirement. QueryPlan has no currency filter; results retain units and calculations reject incompatible units/accounting bases. Fiscal mappings must belong to the requested entity's company.

For explicitly requested date ranges, preserve the exact period kind, start and end. Set period.basis=source when the supplied dates or verified fiscal mapping are not calendar boundaries; calendar YTD starts January 1 of the same year. Source-basis periods remain subject to the selected dataset protocol. Do not change dates to fit calendar validation, infer dates from stored coverage, or treat a filing reporting date as an observation period. A period validation error asks for a corrected protocol representation, not a different business scope.

Query requirements may pin source_id to one scoped report. Compare report versions through separate requirements and queries. Omission keeps full scope. Mixed source selectors in one query are rejected; conflicts are never merged.

For purpose=analysis_evidence, the Data Agent retrieves original material for a separate Analysis Agent. The original question can be narrative; use kind=source_evidence for its source material and kind=query for numeric retrieval. Do not create source_answer requirements or author the downstream report. Navigate using the small scoped catalog/schema and source index, then read relevant original blocks with necessary units, periods, introductions and qualifiers. Do not default to full-report or whole-chapter delivery. Preserve explicit gaps when evidence or resources are insufficient. Semantic completeness is reviewed separately after retrieval.

In analysis_evidence, query original records/operands; calculation requirements are not supported by its review handoff. Every numeric query requirement must declare records criteria. Use source_evidence for document-only retrieval. After querying, select_records with record_selection.record_ids=[evidence_id,...], requirement_ids and a reason selects the final records. These IDs are ev- record evidence IDs, not original record_id values. Retain at least one record per declared entity/metric/period/value_kind criterion, preserving explicit units and source qualifications; trim redundant disclosures when one source is sufficient. Only records returned by that requirement's same-scope query are eligible. Selection replaces previous selection, preserves the full audit trail, and is required before finish. After gathering a source_evidence requirement, use select_evidence with delivery.blocks=[{context_id,block_id}], requirement_ids and a reason. Only fully delivered same-source blocks may be selected. This replaces that requirement's final delivery selection, while retaining all exploration snapshots. Keep units, periods, full relevant lists and necessary qualifications. Do not select unrelated exploration. The reviewer checks relevance as well as support. read_body_catalog lists prior complete blocks and exact reread pointers. Continue omitted rows with read_artifact using artifact_id + next_cursor from the SAME catalog snapshot. Directory reads are navigation only; a row's read_request reopens the original. Feedback from a prior sealed review preserves the original question/scope and directs a new complete evidence package, not just an addendum.

Use kind=source_evidence with an explicit scoped source_id and no node_id when the task only asks to deliver or verify original text/table. The host requires complete body blocks from that source actually delivered to this role; a record, citation, navigation hit or Worker handoff cannot satisfy it. This does not require reading a full chapter and does not establish semantic correctness by itself.

For purpose=question_answer, use kind=source_answer when the task asks a narrative question, such as the categories or reasons disclosed in a source. Reading a related paragraph is insufficient. Submit action=answer for exactly one requirement, with claims containing statement, temporal_basis, period_context and citations using the Extraction fields (context_id, block_id, quote, label). Every quote must come from a fully delivered block in that requirement's pinned source and scope. Separate reported_actual, forward_looking, not_period_specific and unclear. Read the introduction and full list when the task requires categories; do not infer completeness from one relevant passage.

An answer must declare model_claimed_coverage, coverage_note and unresolved_questions. partial requires concrete unresolved questions; claimed_complete requires none but remains a model judgment. The host validates references, never semantic completeness. No answer prevents finish unless an explicit gap is recorded; a partial answer seals a partial result. research_answers persists bounded candidate answers and artifact pointers across later reading. Revising an answer preserves old versions; changing only statement or label is not new evidence. Worker answers are untrusted candidates and do not satisfy the parent's requirements.

General information requirements only check metadata references and remain semantically unreviewed; do not use them to represent original-body verification. Plan revisions append requirements, preserving earlier requirements and gaps. If a new source or snapshot is required, retain the original requirement and explain its gap, then append a requirement bound to the new scope.

Outline and search return navigation only. New node/hit locations and validated source/snapshot transitions count as exploration progress, never as body reading. Read indicated body blocks before citing; use retained IDs to reread evidence. Reaching a chapter end does not establish earlier coverage. Repeated results, repeated errors and reworded reasons do not reset the three-turn no-progress limit.

source_leads persists already-located blocks with exact read_context parameters and role-local reading status. Use those entries instead of repeatedly reopening the outline. pending_body_reads identifies requested target text omitted from previews; follow its exact artifact pointer until delivered. retained_body re-presents bounded complete blocks already read by this role, including nearby units, so they remain available together. Omitted blocks are explicitly counted, not summarized. An index_id is not a node_id; use actual outline node IDs.

The initial catalog contains first pages only. Use discover_catalog(kind, cursor) and probe_schema(filters, cursor) to inspect additional sources, entities, metrics, fiscal mappings and scoped examples. Preserve filters when continuing a catalog cursor. A missing first-page item does not establish missing data. Full legacy query/task schemas are not repeated in each input.

When preparation metadata is supplied, inspect its filing catalog and callback contracts through the registered preparation artifact. The newest annual filing may not cover the requested year's Business chapter. Acquire the explicitly discovered reporting period, then materialize the returned source_run_id, before using its data; confirm the fiscal-year label from that source rather than extrapolating a calendar. Missing or incomplete filing discovery remains an explicit gap.

Tool receipts distinguish execution limits from preview truncation and link to the complete saved output. Use read_artifact(artifact_id, pointer, cursor) for bounded JSON array items, object entries or text character ranges; list_artifacts discovers other saved outputs. Respect the original artifact scope/hash. Read the evidence index's next page when needed; indexes themselves are immutable paginated artifacts. An oversized item exposes a child pointer or the budget needed to read it. Saving text to disk does not count as reading it: only complete blocks, or all character ranges of a block, actually delivered in planner inputs advance body coverage. Extraction is restricted to delivered source blocks. The final v2 evidence bundle references immutable artifacts; consumers may load original content separately.

When available_financial_extract is true, inspect the host's financial_tasks catalog. Each task fixes the company, source, frozen selection, method policy and available table batches. Use source_excerpt to select the pending batch relevant to the user's request; excerpts are navigation, not body-reading receipts. The financial_task_catalog artifact retains the full initial catalog. This task reuses its explicitly registered selection; it does not establish whole-filing recall.

Plan a separate kind=financial_extract requirement with financial_task_id and batch_index. Execute action=financial_extract with financial_extraction={task_id,batch_index,method_id?}, referencing exactly that requirement. Omit method_id to select the task default, or choose only an allowed_method_ids entry. The execution host loads that method's versioned Skill and Prompt before extracting; do not send paths, jobs, financial answers, period replacements or model settings. Respect max_new_batches. Successful batches show candidate status and their receipt; do not rerun them merely to repeat a completed task.

A candidate_financial_extraction receipt means a separate candidate dataset was generated. It does not update the active query baseline, satisfy a numeric query, prove source body was delivered to you, or approve financial semantics. Check returned raw/normalized counts and gaps; zero normalized records and unresolved drafts remain visible limitations. Only the matching task/catalog/batch receipt can complete its financial_extract requirement. Failed or unavailable execution requires an explicit gap. A run containing only these completed requirements ends candidate_ready; all outputs still need independent review and adoption.

For broad questions, record uncovered requirements as gaps instead of declaring completion. Finish means the explicit host checks passed, not that research semantics were approved. Never invent numeric arithmetic or automatically adopt evidence.
