# 竞对关系：官方来源与通用提取规则

核对日期：2026-10-07。Codex 调研。**可以从官方材料获取，但产物应是“谁在什么业务上，依据哪段披露，被谁视为竞争者”，不能只是公司名称列表。** 本轮交付来源调查与规则候选，尚未接入 Agent 自动提取或改动旧业务图。

## 到哪里找

| 来源 | 优先阅读位置 | 能得到什么 | 不能直接推定什么 |
|---|---|---|---|
| 10-K | Item 1 / Business / Competition；再读 Item 1A 风险段落及交叉引用 | 公司描述的竞争领域、点名公司或竞争者类别 | 不是所有公司都披露完整名单；未出现不等于没有竞争 |
| 20-F | Item 4.B / Business Overview，以及 Item 3.D 风险披露 | 所在市场、竞争定位、竞争对象或类别 | 不能照搬美国 10-K 的标题和版式 |
| 8-K、6-K 及正式附件 | 重分部、并购、战略或业绩材料中的竞争描述 | 年报之后的变化、公司对局部业务的补充 | 不能无声回填为旧年度已经知道的事实 |
| 官网 IR、产品页、官方演示稿 | 有发布身份和日期的正文 | 产品定位、官方比较、业务范围补证 | 产品功能相似本身不是官方宣布竞争关系 |
| 另一方的官方申报 | 对方的 Competition 段落 | “另一方披露双方在某业务竞争” | 不等同于本公司也作了该披露；不能伪造反向引文 |

出处依据：Regulation S-K Item 101(c)(1)(ii) 将竞争环境列入业务描述的披露主题；这不是统一列出所有竞对名称的模板。[eCFR 原文](https://www.ecfr.gov/current/title-17/chapter-II/part-229/subpart-229.100/section-229.101)。20-F Item 4.B.2 涉及主要竞争市场，4.B.7 要求说明公司关于竞争地位陈述的依据。[SEC Form 20-F，印刷第 18 页](https://www.sec.gov/files/form20-f.pdf#page=18)。这里用于选择检索入口，不作法律意见或完整披露义务判断。

## 四种真实情况，决定 Schema 怎么设计

| 材料与位置 | 实际观察 | 正确产物 |
|---|---|---|
| NVIDIA FY2025 10-K / Item 1 / Competition | 按加速计算、云厂商自研、SoC、网络等类别列出部分公司；例如加速计算项点名 AMD、Huawei、Intel，云厂商自研项点名 Alphabet、Amazon、Microsoft 等 | 有名称、有业务边界的“发行人披露”关系；不扩成这些集团全部业务的竞争。[原文](https://www.sec.gov/Archives/edgar/data/1045810/000104581025000023/nvda-20250126.htm) |
| Microsoft FY2025 / Intelligent Cloud / Competition | Azure 段落描述云服务商和开源方案；AI 段落同时说明部分竞争者也是现有或潜在伙伴 | 竞争类别对象。名单未点名时保留类别，伙伴关系可以并存。[官方年报](https://www.microsoft.com/investor/reports/ar25/index.html) |
| TSMC FY2023 20-F / Item 4.B / Competition | 当前定位段落描述其他晶圆代工厂与集成器件制造商，并说明工艺和市场范围会影响竞争 | 记录两类对象及限定；该段没有提供公司名单，不补写 Samsung 或 Intel。[SEC 原件](https://www.sec.gov/Archives/edgar/data/1046179/000119312524099840/d592628d20f.htm) |
| Intel 2024-04-02 8-K 附件 / Intel Foundry / Products and Competition | Intel 的材料明确将 TSMC 等列入代工竞争范围，并区分先进技术领域 | 可给 TSMC 增补“Intel 陈述”的关系，保留陈述方和披露时间；不能写成 TSMC 自述。[官方附件](https://www.sec.gov/Archives/edgar/data/50863/000005086324000068/a04022024form8-kexhibit991.htm) |

另外，Alphabet FY2025 的 Competition 主要列搜索、广告、云、AI 等类别，适合作为“不能补猜竞对名称”的反例。[SEC 原文](https://www.sec.gov/Archives/edgar/data/1652044/000165204426000018/goog-20251231.htm)。薪酬文件中的 peer group 是薪酬对标组，不能直接等同于业务竞对。

TSMC 当前网页读取未成功，竞争段落由项目已冻结的 SEC 原件及标准块核对；没有把网页错误当作“未披露”。Microsoft 同时核对冻结 SEC HTML 中的对应块。精确定位和原文指纹见 [两个来源片段](source-spans.json)。NVIDIA、Intel 与 Alphabet 本次为官方网页阅读，未伪称已加入本地标准解析包。

## 建议的最小产物

每条竞争声明单独保存：**陈述方 → 本方业务 → 对方公司或类别 → 竞争范围 → 时间 → 证据片段**。与 BusinessMap 中已确认的业务 ID 关联；外部竞争者不能误塞进“本公司包含的产品”。

| 字段组 | 规则 |
|---|---|
| 来源范围 | 显式公司、文档、报告期间、发布时间、知识截止日、原件 hash；新旧版本分别保存 |
| 对象 | `named_entity` 或 `unnamed_category`；保留源名称，实体 ID 未核实则留空，不用同名猜配 |
| 业务范围 | 使用来源直接支持的产品/市场描述；映射到本地业务 ID 时另留依据。没定位到具体产品不升级成集团全面竞争 |
| 依据 | `issuer_disclosed`、`counterparty_disclosed`、`inferred_overlap` 分开；推断需双方产品证据与解释，不装成披露 |
| 精确出处 | source/block ID、原文 hash、字符起止、短引文、章节和原件链接；页码仅作辅助 |
| 核查 | 候选 / 核对通过 / 有歧义 / 拒绝；名称匹配、引文存在与语义支持分别检查 |
| 完整性 | 保存查过哪些位置、未读位置和失败；“指定片段未点名”不等于“整份年报无竞对” |

通用规则可以允许显式行业指南，例如半导体按代工/芯片设计/终端产品区分，软件按产品任务与客户范围区分。指南只帮助模型问对问题，不能提供企业名单或预期边。行业指南要有适用输入、版本和拒绝条件；公司名不能触发隐式答案。

## 接入顺序与验收

1. 在已选官方原件中发现候选段落；保留范围与失败。先复用已有搜索、章节回读，不强制每次做全网搜索。
2. 模型按规则提出关系候选；程序检查身份、日期、引用、对象类型和必填字段。
3. 语义复核确认该片段支持对象、方向和业务范围；分别展示披露、推断和待确认。
4. 用户按需打开“外部竞争关系”。不修改旧报告内的组织/业务包含关系，不自动启动监控。

验收案例包括：点名公司、仅披露类别、来自对方的披露、伙伴与竞争并存、不同期间改变、缺少公司/来源、同名歧义、跨公司证据污染。独立合成例和未见材料需另测，以上公司例子留在评测侧。
