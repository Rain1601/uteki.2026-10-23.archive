# E6-QP1：公司范围漏填修复与三次独立复跑

2026-10-12。**问题审核首次通过 3/3，最终内容交付通过 3/3。** 本题范围漏填本轮未复现；全流程无纠错为 2/3，第三轮仍有一次与审核无关的记录 ID 误写。不能把小样本结果称为所有问题长期稳定。

## 现象 → 机制 → 修复

v3 R3 将公司写在证据对象中，请求范围留空，导致两个审核项的请求身份相同。旧校验正确拒绝，问题不在收入数据或校验松紧。实际模型 Schema 把请求身份拆散，scope 位于最后、可省略且默认空；单纯要求模型注意没有稳定解决。

本轮改变生成结构：每项先输出必填 request（引文、锚点、维度、范围决策），再输出 judgment（证据与判断）。范围必须显式选择 qualified 并提供原问题限定词，或 self_contained 并解释为何不需要独立限定。后者不是校验豁免。

程序只将模型填写的字段投影到既有 canonical V2，不从证据补公司/年份，不合并检查。新增原始 generated、投影哈希和 canonical parsed 记录；所有文件纳入快照。原校验和历史 V1/V2 保持不变。修订仍使用原 canonical 诊断，新提示仅解释生成结构与诊断字段映射，没有叠加公司特例。
