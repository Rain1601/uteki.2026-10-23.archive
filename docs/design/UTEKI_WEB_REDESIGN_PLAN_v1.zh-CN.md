# Uteki 网页改版计划 v1

日期：2026-09-30。状态：可实施的原型计划；本轮仅调研和制定计划，未修改网页、安装第三方 skill 或接入生产服务。

功能依据：[前台与工程后台交互草案](UTEKI_WORKSPACES_v1.zh-CN.md)、[报告内容与交付标准](UTEKI_REPORT_DELIVERY_v1.zh-CN.md)。本计划补充网页组织、视觉、实施顺序和验收，不修改投资方法、资料准入或发布治理。

## 1. 已确认范围与方案默认值

**已确认：** 前后台统一规划、分期交付；先做完整可交互原型；阅读舒适、排版清楚、减少堆叠、简单有效美观；支持日间／夜间；调研 GitHub 上实际可用的 UI skills。保留现有六家公司与本地公司 icon，沿用已认可的静态品牌标识。滚轮和触控板只用于阅读。

**尚未由用户选择、此版采用的默认方案：** 再次打开恢复上次阅读；证据在当前阅读区打开，返回恢复原段落、位置与焦点。它们是可调整方案，不记录成用户已确认偏好。

本次明确的网页规划请求决定本计划范围；不改写其他任务在设计入口 README 中记录的契约讨论或 Figma 暂停状态。既有 Figma 仅作为功能参考，不照搬其中跨 Manager 错链、旧版正文不全或空框架。

本期交付覆盖 U0–U5、E0–E7 的页面与关键状态，数据明确标注为演示。真实数据接入、权限隔离、模型调用、调度、重跑、发布、交易和部署不属于原型实现。

## 2. 页面结构与阅读方式

### 共用外壳

- 保持单窗口，固定顶部和左侧对象列表，正文区域原生滚动。顶部高度 56px；桌面左侧约 232px；左列表改为自然滚动，不再分页隐藏其他公司。
- 研究前台一级入口为「公司 / Manager / 行业」；「工程后台」作为独立工作区入口。后台使用「工作队列 / 数据 / 分析 / 评估 / 运行」，上下文通过案例、任务、运行、产物面包屑表达。
- 全局仅保留工作区、语言、主题等必要操作。前后台共用字体、颜色、间距和基础控件，后台通过紧凑列表和表格提高密度。
- 所有导航用明确点击；移除报告页码圆点、整屏推移与阅读区域的方向键翻页。正文方向键保持浏览器阅读行为，控件内保留符合语义的键盘导航。

### 公司与报告

- 公司页头固定显示公司、Manager、版本、信息截止和报告有效状态；Manager 与版本分别选择，不隐式替换为另一位 Manager 或其最新版本。
- 右侧主要标签为「报告 / 变化 / 对比」。业务、thesis、因素与风险、估值、投资判断、观察计划和边界属于完整正文及其目录，不再拆成必须逐屏点击的卡片。
- 报告开头用简短导读交代业务、核心判断、关键条件与主要疑点；后续完整论证可直接连续阅读。章节顺序由报告数据提供，不把八部分建议硬编码成所有 Manager 必须相同的模板。
- 宽度充足时正文旁显示简洁目录；桌面宽度低于 1280px 时目录收进「目录」按钮下的可展开列表，不挤压正文。正文建议最大宽度 720px。
- 首次阅读先交代背景；回访展示相对该案例已读版本的重要变化。新版本只提示可查看，不替换正在阅读的版本或跳动位置。
- 引用打开为同一内容区的证据阅读视图，显示所支持／反对的具体结论、原文上下文、定位、来源时间及限制；返回原引用。比较页进入证据后返回时恢复原比较对象和两侧位置。
- 对比先列方法、期限、信息截止及可比性，再逐项呈现判断与假设差异；两份长文独立滚动。一侧未发布时明确说明，不补内部草稿。

### 注意力、Manager 与行业

- 公司列表角标继续表示未读变化。另设「注意事项」入口，按对判断的影响、未解决状态和时间排序；每项显示优先原因、受影响案例和报告入口。
- 同一事项用一个稳定事件 ID，多个证据合并引用；同一来源的不同事项仍各自保留。已读不移除未解决风险。个人「留待复核」改称「留待查看」，避免混淆研究 review。
- Manager 页提供「方法与研究 / 组合报告 / 持仓与动作 / 表现」。公司报告回答是否买及条件，组合报告回答权重和取舍；相互跳转携带原 Manager 身份。仅展示比例、现金及归一化表现，基准未配置或样本不足时明确显示。
- 行业页提供完整行业论点、提出者、版本、证据、未知和关联公司；各 Manager 的采纳与分歧分别展示。行业列表来自显式演示档案，不将行业标签冒充研究报告。

### 工程后台

- 首页为队列列表，优先显示阻断交付、重要未解决发现、待审候选、到期未完成任务；同一问题的重试折叠在一项下面。
- 打通「队列 → Data / Analysis → Review → 修订版本 → 固定发布预览」，并提供评估与运行详情；正文、结构化记录、引用与日志分别分层呈现。
- Data 页区分资料覆盖、核心财务包、程序检查、内容核验和共享版本。Review 页把目标结论、问题依据、处理意见和复核状态连起来。
- 固定发布预览复用前台报告渲染与字段选择，只读取指定版本。执行结束、内部采纳、研究有效与对外发布分别表达。
- 本期可查看既有模拟任务及结果、填写动作预览；重跑／修订／发布的实际提交保持「未接通」。演示场景选择器可切换固定失败、空态与冲突样例，不生成假任务或假发布成功。

## 3. 视觉与双主题规范

目标是安静、清楚的研究阅读界面。用文字、对齐、留白和轻分隔建立层次，只有独立组合内容才用容器；报告正文不嵌套卡片，不使用装饰性指标大字或背景光效。

| 项目 | 首版实现值 |
| --- | --- |
| 字体 | PingFang SC、系统无衬线为正文和控件；品牌字标沿用现有素材，不新增远程字体依赖 |
| 正文 | 默认 17px，行高 1.85；阅读设置支持 16 / 17 / 18px，并本机记忆 |
| 标题与辅助文字 | 页面标题 28px，章节 20px，控件 14px，日期／来源等 12–13px；核心信息不缩至 9–11px |
| 间距 | 使用 4 / 8 / 12 / 16 / 24 / 32 / 48px；段落与章节留白有明确层次 |
| 表格 | 正文 14px，数字等宽对齐，清楚的行列标题；宽表在自身区域横向滚动，不压缩到无法阅读 |
| 容器 | 控件圆角 6px，独立表面 10px；阴影只表达浮层，普通列表用轻分隔 |
| 动效 | 按钮状态 120–160ms，视图内容至多轻微淡入；无整屏滑动、缩放或持续品牌动效；尊重减少动态设置 |

| --- | --- | --- |
| 页面背景 | `#F5F6F7` | `#15181D` |
| 阅读表面 | `#FCFCFA` | `#1C2128` |
| 主文字 | `#252B33` | `#E2E6EB` |
| 次级文字 | `#59636F` | `#ADB7C4` |
| 品牌链接／选中强调 | `#355D9F` | `#98B7F1` |

- 主题提供「日间 / 夜间 / 跟随系统」，首次跟随系统，手动选择本机保存；首次绘制前应用，避免亮暗闪烁。切换不重置路由、版本、笔记或滚动位置。
- 夜间独立设置正文、表格、表单、焦点与状态颜色，不反转图片或公司 icon。公司 icon 保持原素材背景与品牌色；品牌标识使用稳定浅色承托，不新增重绘。
- 正文与必要辅助文字以至少 4.5:1 为验收目标；焦点和必要非文本控件以至少 3:1 为目标。风险、支持、待复核同时使用文字与语义颜色，不仅靠色差。
- 窄窗口时左列表折叠为带当前对象名称的选择器，目录收起；比较切为上下两份可独立阅读的报告，不隐藏正文或必要操作。以正常桌面窗口为主要视觉评审对象，不扩展为独立移动端项目。

## 4. 技术实现与分期

沿用 `apps/uteki_zero/` 和现有访问地址，以原生 HTML、CSS 自定义属性、ES modules 实现。保留公司素材注册表；拆分页面、路由状态、主题、演示数据与个人状态，避免继续在单个全量重建函数中堆逻辑。不新建后端、数据库或通用平台框架。

### 数据与导航最小契约

- 公司案例按 `(companyId, managerId)` 标识，报告绑定不可变版本与发布记录；将单一 `company.report` 改为显式案例与版本引用。所有事件、证据、组合动作和行业关系引用同一案例／版本身份。
- 静态只读数据提供层返回文档 P1–P6、I1–I6 对应的视图数据。研究与工程演示数据分模块；前台不读取工程草稿。本地模块拆分仅模拟展示边界，不宣称有访问权限隔离。
- 本期采用 hash 路由适配现有静态服务，例如 `#/app/companies/:company/cases/:manager?version=...&section=...`，工程路径使用 `#/engineering/...`。证据与比较地址同时携带原案例／双方版本；无效身份显示缺失状态，不回退其他公司。
- 显式 URL 优先；无路由时恢复有效的本机记录；无记录时使用演示配置中明确指定的首个体验场景。该场景属于命名 fixture，不成为后续真实服务的公司默认值。
- 返回栈记录来源路由、版本、章节锚点、区内滚动位置及引用焦点；比较记录两列位置。主题与语言切换局部更新，保持正文原语言、来源地区和版本。
- 个人已读、留待查看、笔记、最近阅读版本与主题单独本机保存；使用新的原型存储版本，旧键保留，不把无 Manager 身份的旧笔记猜测迁入新案例。草稿留在会话，保存失败可重试／复制，不显示已同步。

| 阶段 | 可交付内容 | 完成条件 |
| --- | --- | --- |
| 1：报告阅读样板 | 新外壳、日夜主题、完整公司报告、Manager／版本选择、目录、证据返回、比较、阅读恢复 | 用明确的 GOOGL 双 Manager 演示案例走完 U1 → U2 → U5；含完整旧版本与待复核场景。再用另一家现有公司验证一侧未发布、缺失引用及状态隔离 |
| 2：研究前台完整化 | U0 注意事项、完整 U3 Manager 与组合、U4 行业；六家公司入口和各自显式演示状态；个人留待查看／笔记 | 所有入口指向正确案例与版本；事件不重复计数；收益／基准／覆盖不足状态可检查，无空框架或无解释的无效按钮 |
| 3：工程后台完整化 | E0–E7 及 Data → Analysis → Review → 版本 → 发布预览；评估、运行和错误场景 | 发现能定位结论与引用，修订保留父版本，预览只显示固定前台字段；未接通操作不假报完成 |
| 4：统一收口 | 前后台两主题统一、双语界面、长文／表格／错误状态与键盘行为检查；更新界面规范与设计记录 | 自动检查与用户视觉反馈分开记录；交付页面入口、场景索引与明确的后端未接通清单 |

每阶段产出都可直接在网页查看；先完成阶段 1 的阅读体验再铺开其余页面，避免一次生成大量未经过阅读反馈的屏幕。首次场景只用于原型，不作为真实投资判断或评估参考答案。

## 5. 验收与后续接入

| 场景 | 验收结果 |
| --- | --- |
| 连续阅读 | 完整正文已说明业务、判断、正反依据、估值条件及未知；不需要对话或逐张翻页拼接核心内容 |
| 身份一致 | 公司入口、Manager 持仓、历史与比较始终维持公司＋Manager＋版本；不得跨 Manager 串线 |
| 引用与返回 | 从正文或比较打开证据后，返回原版本、段落、列和焦点；浏览器后退、刷新和深链接可恢复对应对象 |
| 自然操作 | 滚动、正文方向键只阅读；到边界不换条目；主题、语言、新版本提示不抢选择与位置 |
| 发布状态 | 研究中不露草稿；旧版待复核仍可读全文；新版、旧版与失效预览各自明确；未知或失败不假装成功 |
| 注意力 | 同事项三条证据只计一个事件；同源不同事项不误合并；已读未解决风险继续存在 |
| 个人保存 | 已读、稍后与笔记不改 Manager 研究；禁用本机存储时保留草稿、显示失败并可复制／重试 |
| 双主题 | 正文、链接、选中态、焦点、输入、表格、风险和 icon 在日夜主题中均可辨；无主题闪烁、文字裁切或行高跳动 |
| 后台诊断 | 部分完成、review 未复核、发布失败、样本不足等都有固定演示场景；查看任何场景不触发模型、交易或任务 |

自动检查覆盖数据引用、路由／历史状态、事件去重、存储失败、主题持久化及实际颜色对比度；不以测试数量代替产品验收。默认由用户在正常桌面窗口检查阅读与美感；仅在明确要求或具体浏览器问题出现时进行定点浏览器验证。

计划制定时仅检查文档：本地链接与格式通过；上述主文字、次级文字、链接色对两种对应背景的最低计算对比度为日间 5.64:1、夜间 7.97:1。尚未实现页面或检查实际组件、语义状态色和浏览器视觉结果。

真实接入作为后续独立阶段：先核对报告、证据和发布清单的读取映射，再实现页面／JSON／下载／原文访问一致的服务端可见性；随后才开放任务控制、修订和发布。原有 `review_workbench` 的局部档案能力可供适配，但不是现成的通用前台 API。

## 6. 第 1 阶段实施记录（2026-09-30）

用户回复“OK继续”后，在 [原型入口](../../apps/uteki_zero/index.html) 实施报告阅读样板；本地预览为 `http://127.0.0.1:8768/uteki_zero/`。原版保留在 [legacy.html](../../apps/uteki_zero/legacy.html)，没有删除既有实验。
