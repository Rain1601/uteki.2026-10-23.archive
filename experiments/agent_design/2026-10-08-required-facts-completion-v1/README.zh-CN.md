## 本轮通用修复

1. 正式 Schema 明确：`question_refs` 只能引用分析师问题的原文块；财务报表用空列表，不能塞入 task/requirement/record ID。
2. 补提入口复用既有 packet、批次目录、Skill、抽取、合并、规范化和数据库投影。合并时拒绝跨公司、跨来源、不同目录、变动原文和引用未实际交付块；相同模型局部 ID 不会覆盖另一批记录。
3. 收到明确格式或规范化问题时，最多做一次基于原文、自己原输出和机器诊断的完整修订。原始输出封存，不将人工修改当成模型结果。
4. 显式选用 `table-year-header-v1` 时，程序允许原表年度列的日期标签匹配已有精确年期：必须是英语完整日期、等于已知年期结束日，原表中同一列上方存在覆盖该列的年度标题，且模型已引用该日期。程序补录该标题依据。不会推算起始日；季度、其他语言和不支持的版式仍保留缺口。
5. 39 项相关离线测试通过，包含两家合成公司、多批缺失→补提→合并、字段自修、跨来源拒绝、日期/列/标题错误拒绝、原发表 hash 防篡改、并发重复恢复防护、选择未推进后的同账本恢复、源绑定上下文随目标指标安全缩小。离线测试不能等同于新的真实模型评测。
6. TSMC 首次选择未推进后，通用调度明确“一批可以只完成部分缺口”。投资表先完成 3 项，再从剩余经营表完成 3 项。实际运行之后另修正子批输入的 `selected_blocks`，记录原父级范围，并为模型缺口增加批次归属：另批后来补全的事实，不应被早期批次缺口描述误认为仍然缺失。这个元数据改动已离线验证，尚未为它单独再次付费运行；历史输出没有重写。

## 边界与下一步

最终 `fact_coverage` 保持 `partial`：6 个指定事实都有候选，但模型仍说明没有提供报表外的注释，也没有提供明确会计准则正文。不能把“合并口径”当成“US GAAP 已验证”，也不能把没有输入的材料当成未披露。这里通过的是 6 个指定原表单元格，尚非整报告的语义验收。

历史来源标签映射仍为显式配置，并绑定该来源与块 hash；这轮不是模型自动发现所有期间/币种目录的证明。TSMC 两表已真实验证；更多公司与完整报表范围仍待推进。
