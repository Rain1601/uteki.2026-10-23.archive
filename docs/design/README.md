## 当前主线：Agent 能力、实现与功能 E2E

这里的 Agent 指 Uteki 的产品职责，不包括协助开发的 Codex 子任务。Planner、Worker、Extractor、Reviewer、Revision 这些名称分别描述组织角色、能力或任务，不能据名称数量推导独立 Agent 或服务数量。

| 职责组 | 输入 → 核心产物 | 实现组织 | 当前核对结论与 E2E 缺口 |
| --- | --- | --- | --- |
| Data | 明确公司/期间/截止/来源与问题 → 有原文、口径、计算、核验状态及缺口的证据包 | Planner 持有任务，按需 Worker；Direct Extractor、Record/Semantic Review 属于数据提取与核验能力；采集、解析、查询、计算主要由工具完成 | 本次限定真实题的 7 条事实/6 项要求通过独立内容核验；Worker 步骤耗尽后由主角色接手，稳定完成和跨公司效果未验收 |
| Analysis | Manager 方法/问题与同范围已核验材料 → 业务、thesis、因素/风险、估值假设和报告候选 | 研究作者使用规划、方法 Skill 与工具；行业研究、机构研报对照是研究任务类型，是否拆执行角色由实验证明 | 已真实消费同范围核验材料并生成限定候选；核心事实正确，但混淆任务核验与全局采纳，重复要求核验并提出部分超范围补充任务，内容仅部分通过；完整报告仍待验收 |
| 独立研究审阅 | 问题、方法及同范围材料 → 独立初判；之后读取作者稿 → 有证据的发现与修订复审记录 | 审阅上下文与作者分开；Revision 是作者依据发现执行的任务；与 Data 的事实核验分层负责 | 现有 team 实验的 Reviewer 首次输入已含作者稿，尚不满足已确认的“先独立初判、后对照报告”；narrative 的引用修复也不能替代该审阅 |
| Manager | 共享证据、研究候选、质疑与方法/组合状态 → 独立投资判断、采纳理由、行动条件及目标比例 | 长期价值型与阶段性进攻型是两种持续方法实例，复用数据与研究能力 | 两类方法边界已定；持续案例、研究更新、组合决定及账户衔接尚无完整功能 E2E 验收 |

固定模型配置、Skill/提示词版本、工具权限、有界执行、成本和失败记录是跨角色运行条件，分别核验；不把 Skill 文本声明用某模型当成已经实现的模型绑定。账户、发布门槛与版本隔离由确定性服务执行，不因它们尚未完成而新增一个 LLM Agent。

每项能力统一用四类证据核对：**职责契约 → 实际入口与调用链 → 保存的真实运行产物 → E2E 验收结论**。文档确认、代码存在、程序检查通过、模型内容合格和完整链路通过分别记录。以下为分阶段验收计划；阶段 1 的查询、内容核验与限定消费已在真实模型上贯通，Analysis 内容及 Worker 完成率仍有明确缺口：

| 顺序 | 功能 E2E 的输入与输出边界 | 必须观察到的行为 |
| --- | --- | --- |
| 1. 数据交付闭环 | 首先使用已显式冻结的 GOOGL 年度资本投入问题与材料，直到经过适用核验的证据包或准确的部分/失败结果 | 模型自主完成数值与用途问题；独立核对不能靠引用存在替代；遗漏触发修订或保留缺口，输出可被 Analysis 读取。另用缺来源、跨公司/期间、未读引用与重复无进展等反例验证边界。冻结材料任务通过不证明全材料采集已完成，来源获取与 ready 覆盖另验 |
| 2. 研究与报告闭环 | 方法与数据交付 → 研究候选、Reviewer 独立初判及对照、作者修订、Manager 最终判断 → 一致的中英报告版本与发布状态 | 全程通过真实任务交接，无人工搬运答案；可追溯关键主张，拒绝未处理质量缺陷，保留合理观点分歧。限定专题只能验收相应链段；首次完整公司报告仍须满足必需材料、核心研究与审阅门槛 |
| 3. 持续更新与决策闭环 | 新证据或复核触发 → 两位 Manager 各自修订/维持 → 版本记录；输入齐备后再接模拟账户及 ETF 对照 | 共享事实不强制共享结论；旧报告和案例可还原，失败不写成无变化；确定性账本验收后才记录模拟成交与表现，不能靠页面示例或研究文字制造持仓 |

S01 是未来连续模拟的启动配置，不回填过去成交，名义金额仍只用于内部核算。各 Manager 的资料、研究与执行条件达到就绪后记录实际启动时点，不能事后挑选有利起点。每位 Manager 配套的 ETF 对照采用与其相同起点及评价区间；Manager 间比较另列相同日历区间，不把不同起点的累计收益直接当作同一场比较。

账户启用即开始计时，之后选择现金也属于实际决策，不能等第一次买股才启动对照。共同主对照指同一个 ETF 品种，每位 Manager 配套各自起点的独立基准账户。共同区间只将已有净值归一并重算指标，不重置真实模拟持仓或补做交易；无法取得匹配行情时明确比较缺口，不换用另一 Manager 的起点数据。

S02 仅使用本轮冻结的信息，晚到材料进入后续版本；订单迟到进入后续轮次。按实际交易日历确定下一正常交易时段，不将周末、休市日当作成交日。只有取得相应真实开盘行情且满足订单与资金规则后才记录模拟成交；缺价、停牌或检查不通过时不制造成交。开盘价是模拟核算的参考价格，不能当作真实券商成交保证；摩擦成本按已确认 S04，数量及具体资金处理由待完成的账户契约约束。若改为盘中响应或其他执行时点，应显式更新执行政策，不能静默变化。

**说明示例（虚构）：**连续两个正常交易日，第一天纽约时间 20:00 冻结资料；Manager 在下一交易时段开盘前 30 分钟之前封存“买入 100 股某公司”的订单。若开盘参考价格为 101 美元且订单/资金检查通过，模拟成交金额为 10,100 美元，按 S04 计入 10.10 美元模拟成本，合计扣款 10,110.10 美元。100 股与 101 美元仅用于解释，不能变成生产默认值；所有记录保留决定、封存、参考行情和实际记账时点。

S03 在运行前固定，保留已确认的风格收益与风险评价；ETF 只作对照，不加入 Manager 可投资资产。2026-09-30 已核对基金官方页面：[SPY 对应 S&P 500](https://www.ssga.com/us/en/individual/etfs/state-street-spdr-sp-500-etf-trust-spy)、[QQQ 对应 Nasdaq-100](https://www.invesco.com/qqq-etf/en/about.html)。基准身份已选定，行情覆盖和账户核算仍需工程验证。

### 模拟成本、现金收益与税务口径：第 13～15 题处理结果

用户已明确选择 13A、14A、15A。以下已确认规则分别影响交易频率、现金配置及投资者身份下的净收益。Manager 与对应 ETF 使用一致的核算规则；一致的规则不等于不同现金权重和换手率受到同样影响。

| 编号 | 已确认规则 | 答复 |
| --- | --- | --- |
| S04／13：交易成本 | 每次买入或卖出扣成交额 0.10% 的合并模拟成本，同时查看 0% 和 0.25% 情景 | 13A |
| S05／14：现金收益 | 主结果按纽约联储 EFFR 作为现金计息参考，同时保留 0% 利息对照 | 14A |

S04 的 0.10% 主场景及 0%／0.25% 对照是已选定的实验参数，不是券商报价或已校准的真实执行成本。0.10% 表示每成交 10,000 美元计入 10 美元成本；买入和卖出分别计算。其合并表示佣金、价差和滑点的模拟影响，不能另行重复扣除同一成本。敏感性结果须标注实验条件，单独记录，不能反向改写主账本或择优替代主结果；不宣称其他成本环境下 Manager 会作出完全相同的决策。

S05 中 EFFR 是纽约联储根据美元隔夜联邦基金交易计算并公布的参考利率，官方发布的是前一营业日数据，不能当作当天提前已知。[纽约联储 EFFR 说明](https://www.newyorkfed.org/markets/reference-rates/effr)（2026-09-30 核对）。用于模拟现金计息是本方案的假设，不代表券商实际支付该收益，也不是新增可投资资产。工程须在运行前固定来源、可得时点、历史利率序列、计息资金口径与公式；数据缺失明确标注，不能用今天的利率回填历史或静默换成 0%。

S06 的税前方案表示该层未建模投资者税负，不表示实际投资免税。主结果是扣除已选模拟交易成本、按 EFFR 计入现金收益、未扣投资者税负的收益，报告须明确这三个口径。未来税后场景须有明确适用身份、收入类型、期间及规则来源，不因目标用户包含中国和美国就自动推断个人税务身份；首版不要求先建税后场景。

风险治理沿用既定约束：Manager 在方法内自主决定现金与有依据的集中持仓，事前声明风险和复核规则；实质风险政策变更另行验证并按既定权限确认。此处不新增统一仓位上限、统一止损比例或逐笔人工审批；具体规则由方法配置形成可评审版本。

以下是待实现的确定性验收例，不是实际交易或模型运行结果。显式合成输入：已付款并结算的 A 证券 0.5 股，可用现金为 0；卖出参考价为 100 美元，B 证券后续买入参考价为 40 美元。均为测试专用证券和价格，不构成业务默认值。该例只核对交易本金和成本分录，EFFR 利息须另有样例，不将主场景利率改成 0%。

| 动作 | 预期账本结果 |
| --- | --- |
| 有效窗口卖出 A 证券 0.5 股 | 成交额 50 美元、成本 0.05 美元、待结算应收 49.95 美元；可用现金仍为 0 |

| 适用结算日历下完成并记录结算 | 将 49.95 美元从待结算转为已结算可用现金；转账不产生第二笔收益 |
| 结算后，另有及时封存的有效订单，在符合 S02 的窗口买入 B 证券 0.5 股 | 成交额 20 美元、成本 0.02 美元；20.02 美元从订单预留转为买入付款占用或结算扣款，只扣减可用资金一次，余额为 29.93 美元。先前未成交订单不自动回填 |

工程还须以反例验证：重复处理成交或结算事件不重复记账；其他买单不能复用已预留或应付资金；原有独立可用现金不受其他待结算卖出款影响；缺价格、证券范围或结算记录时保留缺口；Manager 和 ETF 对照遵守同一数量、成本与资金规则。

## 首先讨论的三个取舍

1. **以正式报告作为核心交付。** 内部公司案例维护持续研究状态，对外报告是该案例的明确发布版本；公司与 Manager 入口读取同一份报告。报告完整交代判断、依据与未知，用户通过目录、引文和版本比较阅读；问答仅作为未来可选补充，不是获得核心内容的前提。
2. **关注判断变化，同时保留背景。** 首次阅读先显示业务和 thesis；回访突出相对已读版本的变化。后台优先列影响交付的异常和待审问题，再逐层打开执行记录。未读、未解决、已采纳和已发布分别维护。
3. **先验收交付，再扩展 Agent。** 采用“规划 + 方法 Skill + 工具循环 + 独立内容审阅”的组合；查找、计算、审阅是否拆角色，要通过同题对照决定。关键推理用高能力模型是当前方向，仍要验证某一具体模型在对应任务上的表现。

注意力管理要能解释为何优先、允许用户稍后处理，并保持阅读位置。Microsoft HAX 的 G3/G4/G9/G14/G16 为时机、相关信息、纠正、谨慎更新和动作反馈提供依据；这是成熟交互研究，不将其称为新技术。[HAX Design Library](https://www.microsoft.com/en-us/haxtoolkit/library/)
