## 1. 每次任务必须说清什么

业务范围由调用方输入、选定数据集元数据或显式选择的版本化配置提供。未知、冲突或不支持时返回具体错误或缺口，不改查另一家公司、最近年度或第一份报告。

| 范围项 | 明确内容 | 缺失或冲突时 |
|---|---|---|
| 主体 | 公司 ID、市场、CIK（适用时）、主体层级；母公司与子公司分开 | 拒绝身份不明的任务；同名公司不能按第一项选择 |
| 报告制度 | 已核对的国内发行人 / 外国私人发行人等制度及其依据 | 不仅凭交易所或 ticker 推断；不支持的制度列明边界 |
| 材料角色 | 年度、季度/中期、临时披露、业绩稿、演示稿、电话会文本/音频等具体子集 | 不把“财报”自动扩大成所有官方渠道 |
| 期间 | 明确报告期末或范围；事件材料另给事件/披露窗口 | 周制财年保留真实日期；不得将 AMD 2023-12-30 改成 12-31 |
| 知识截止日 | 截止哪一天已公开；日内研究另需时间与时区 | 当前日期粒度不能冒充日内无前视偏差 |
| 来源策略 | 选定监管渠道、已核对的 IR 地址及允许托管域名；是否允许第三方 | 未配置渠道列缺口；不自行变更为第三方转载 |
| 版本策略 | 保留原版、修订版、转载/镜像关系；说明使用哪一版 | “最新”不是默认规则；不自动用修订全文替换原版 |
| 执行边界 | 请求数、文件数、字节、时间、重试等明确资源限制 | 达到上限返回已完成部分与未尝试项，不报告全范围完成 |

当前获取配置已有 `symbol`、`market`、可选 `cik`、`as_of`、`filing_selection`、`source_policy`、`limits`。报告制度、细分材料角色、修订适用关系和下述完整状态维度是拟议扩充；本文件不把拟议示例当作可直接执行的 API 配置。

## 2. 材料如何分类

**一份材料分别记录角色、申报类型、物理格式和版本关系。** 例如，某文件可以同时是“业绩新闻稿”“8-K 的 EX-99.1 附件”“HTML”“原始发布版”。不能把这些合成一个 `type` 后互相替代。

| 材料角色 | 常见正式载体 | 第一版应保留什么 | 判断边界 |
|---|---|---|---|
| 年度报告 | 10-K、年度用途的 20-F，以及相应修订；公司 IR 年报 | 正文、目录、披露日期、真实报告期、修订和必要引用依赖 | 20-F 还有其他用途，需核对本份用途；IR 年报与申报正文不默认完全相同 |
| 季度/中期报告 | 适用发行人的 10-Q；部分外国发行人的 6-K 附件或 IR 中期报告 | 实际期间、正文/附件归属、财务报表和附注 | 6-K 不是固定频率的 10-Q；不用统一“每年三份”验证所有公司 |
| 临时披露 | 8-K、6-K 及相应修订/附件 | 事件日期、披露日期、事件角色、附件清单 | 8-K/6-K 的报告日期不能一律当财务期末 |
| 业绩新闻稿 | 公司 IR 原稿；8-K/6-K 附件 | 对应业绩期间、发布时间、所附表格及版本 | EX-99.1 标签本身不能证明是业绩稿，需读标题/内容 |
| 业绩演示稿/补充表 | IR 文件或申报附件 | 演示/财务期间、图表、非 GAAP 口径说明、版本 | 文件名中的季度只能作候选，不能单独完成期间核验 |
| 电话会材料 | IR 活动页、准备发言稿、文字实录、音频/视频 | 活动日期、业绩期间、制作方、托管方、版本、准备发言与 Q&A 覆盖 | 只有发言稿不能报“完整实录”；自行转写记为派生材料 |

监管用途依据：SEC [10-K](https://www.sec.gov/files/form10-k.pdf)、[10-Q](https://www.sec.gov/files/form10-q.pdf)、[8-K](https://www.sec.gov/files/form8-k.pdf)、[20-F](https://www.sec.gov/files/form20-f.pdf)、[6-K](https://www.sec.gov/files/form6-k.pdf) 官方表单，查阅日期 2026-10-07。这里定义工程选材边界，不替代逐发行人的适用性判断，也不实现完整申报义务日历。

附加关系约定：

- **正文与附件：** 保留 accession、附件编号、说明、父申报和各自原始 URL。需要的财务正文在附件时，主申报下载成功只计主申报，不计附件成功。
- **引用依赖：** 正文明确引用其他材料时登记依赖和缺口；本次未获取的部分不能算完整。仅处理任务所需的依赖，不扩为无限递归抓取。
- **修订：** `/A` 单独冻结；记录修订対象、声明变更范围及证据。只修改封面或签名的修订不能顶替整份财务报表。
- **同一内容的多处发布：** SEC 附件和 IR 原稿保留各自来源。相同字节可共用内容对象，但来源关系不删除；相似文字只标待核对，不能自动合并为同一版本。
- **电话会：** IR 托管的第三方实录可记“公司官方渠道托管、第三方制作”，不能改称“公司自行撰写”。Corrected/Final 等标签保留原文和版本日期。未经核对的版本关系保持未知。

## 3. “官方”与“这份材料正确”分别核对

| 检查 | 要回答的问题 | 合格证据 | 不足以通过的证据 |
|---|---|---|---|
| 来源资格 | 为什么这个渠道可作为该公司的官方渠道？ | 监管域名与申报身份链；公司已核对主页到 IR/活动/托管文件的链接链；记录核对人/程序、日期与依据 | 仅位于 `allowed_hosts`；搜索排名第一；域名看起来像公司名 |
| 单份身份 | 文件是否属于指定主体、期间、角色和版本？ | SEC 清单和原件内身份字段一致；IR 文件标题/正文/活动信息与所需范围一致 | 同一域名；同一个 CIK 但实际讨论子公司/对手方；文件名含年份 |
| 时间资格 | 截止日当时是否可得到这个版本？ | 原始披露或版本发布日期与依据 | 抓取日期；URL 年份；当前页面日期覆盖历史版本日期 |
| 内容质量 | 原件有没有被完整且正确解析？ | 后续整文核查、表格/锚点/缺失检查 | HTTP 200、身份字段匹配、hash 正确 |

程序先检查可确定的字段与字节；模型可提出材料角色、期间和关系候选；有冲突或证据不足的项目保留待审。人工或明确配置的核验流程用于处理待审项，无须把每份普通文件都变成一次用户确认。

**当前边界：** `source_policy.official` 是调用方配置分类，不是自动完成来源资格研究。当前 IR/RSS/网页抓取仅沿已配置地址及允许域名做有限发现，并保留覆盖不完全提示；自动寻找官网 Blog/渠道并核验属于 TODO 13。当前任务不能顺带创建持续监控。

## 4. 保留分阶段状态

以下是**拟议逻辑维度**，不是已发布枚举。实现时复用已有回执字段并增加必要字段，不覆盖历史 manifest。

| 维度 | 需要区分的结果 | 示例 |
|---|---|---|
| 来源资格 | 已核对 / 待审 / 不符合策略 | 允许访问 CDN，但其与公司 IR 的链接关系仍待审 |
| 发现 | 找到候选 / 指定范围未找到 / 搜索未完成 / 不适用 | 链接上限耗尽属于未完成，不属于未找到 |
| 获取 | 未尝试 / 下载成功 / 核验后复用 / 延后 / 失败 | 429 等待重试，保留回执和下次允许时间 |
| 单份身份 | 匹配 / 冲突 / 信息不足 / 当前校验器不支持 | SEC PDF 可真实存在，但 inline HTML 校验器不支持 |
| 时间资格 | 截止日前 / 截止日后 / 时间未知 | 发布日未知材料可留档，但不能据此证明截止日前已披露 |
| 版本关系 | 原版 / 修订 / 镜像或转载 / 关系待核对 | 修订成功获取，不代表整份旧报告被替代 |
| 解析 | 未运行 / 支持且完成对应范围 / 有缺口 / 不支持 | 原件身份通过，目录章节仍有遗漏 |
| 数值加工 | 未运行 / 支持的候选 / 无支持记录 / 口径不支持 | TSMC IFRS/TWD 与当前适配器不匹配 |
| 核验/采纳 | 候选 / 已核验对应范围 / 已显式采纳 | 下载和模型一致不自动触发采纳 |

这些状态可以同时成立。例如 TSMC FY2023 原件已下载、身份通过、截止日合格，但数值适配不足。原文读取与有出处的 Query 可以继续；财务结构化完整性保持未通过。

“未发现”必须带 **查找渠道、筛选条件、查找时间、请求边界、已完成/未完成的检查**。允许说“在已检查的 IR 活动页中未找到实录”；不能据此说“公司没有公开实录”。“不适用”也需依据，不能把不支持的接口记为不适用。

## 7. 怎么判“做完了”
