## 2. 财报经过哪些步骤

```mermaid
flowchart LR
  A[已获取的冻结原件] --> B[程序保真切块和表格]
  B --> C[标记噪声与未处理内容]
  C --> D[核对目录与精确定位]
  D --> E[按产物范围做模型加工]
  E --> F[格式、原文、遗漏分层核验]
  F --> G[Query 计划、取证、回答]
```

**先保留能回到原件的底稿，再控制送给模型的内容。** 程序解析会按已声明规则排除脚本、隐藏区等非正文；它保留原件字节。导航等业务无关内容先标记，再由阅读/模型输入视图排除并记录清单。不能先用模型摘要替代原件，随后只索引摘要。

| 步骤 | 程序与模型分工 | 每一步能看到的结果 | 当前边界 |
|---|---|---|---|
| 0 获取 | 程序执行所选来源策略、身份/hash 检查；有疑义的来源或角色可由模型建议、核验流程处理 | 所选范围、来源、原件、获取/身份/时间/版本状态及缺口 | 本轮复用冻结 AMD/TSMC 年报；不新抓财报 |
| 1 保真解析 | 程序按原始顺序保留段落、表格网格、DOM/页码、图片引用 | 原文块、单元格、跨度、文本 hash、图片/无法处理项 | 当前 HTML 分支已有；PDF 与 OCR 不能沿用本轮通过结论 |
| 2 噪声分类 | 程序识别可确定的重复导航和版式；不确定项保留，模型可另提分类候选 | 布局角色、排除原因、仍保留的原文及受影响范围 | AMD 105 / TSMC 163 个完整导航短块尚未标记；诊断不能当修复 |
| 3 目录与定位 | 程序核对标题、范围、原锚点、块/单元格归属；模型导航建议须回原文验证 | 章节树、目录/正文差异、锚点、冲突与缺口 | PageIndex 是单独的有界适配评估，不替换系统执行内核 |
| 4 产物加工 | 模型按任务计划选择范围、提取事实、忠实精编或生成业务图；程序约束工具、预算、格式和版本 | 显式计划/待办、所读块、实际模型配置、原始响应、候选、未读/未完成清单 | 模型参与这里的内容选择与加工；不是每个段落都必须调用模型 |
| 5 分层核验 | 程序查 Schema、引用归属、单位换算和范围；独立内容核对查语义与漏项，模型裁判可辅助 | 格式结果、原文支持、遗漏/冲突、修订版本、核验/采纳状态 | JSON 合法或引用存在均不能替代语义验收；不自动采纳 |
| 6 Query | 模型选择数据类型、制定取证计划；程序执行受约束查询/检索；模型依据返回证据回答 | 请求范围、选库理由、工具日志、回读片段、回答、计算与具体缺口 | 事实性计算须给输入和公式；研究推断属于后续 Analysis 能力 |

这里的“计划与过程”指可观察的任务计划、工具动作、证据选择说明和结果，不要求保存模型私有思维链。每一步都关联运行 ID / Trace；程序步骤标“纯程序”，不虚构模型或 token。

## 3. 用同一份真实材料讲清五类产物

固定来源为 AMD FY2023 10-K，source `source-291485b98a75d8cfabe47571`，报告期末 2023-12-30，披露日 2024-01-31。来源包的 [身份与版本](../../../experiments/agent_design/2026-10-07-parser-runtime-v1/prepare-amd/dataset/indexes/source-291485b98a75d8cfabe47571/source.json)、[原文块](../../../experiments/agent_design/2026-10-07-parser-runtime-v1/prepare-amd/dataset/indexes/source-291485b98a75d8cfabe47571/blocks.jsonl) 和 [阅读版](../../../experiments/agent_design/2026-10-07-parser-runtime-v1/prepare-amd/dataset/indexes/source-291485b98a75d8cfabe47571/document.html) 可核对。

两个小点：

- **业务段落：** 第 3 页块 72 说明四个报告分部，73–76 分别列出 Data Center、Client、Gaming、Embedded；块 77 明说 All Other 不是报告分部。块 73 保留“主要包括”限定及产品列表，不能改成穷尽性清单。
- **现金流：** 第 58 页块 `block-000686-a6e8806b` 的零基 row 25、column 3 是 `1,667`；行名为经营活动产生的现金净额。需连同年度列、单位、主体及报表标题读取，单元格本身不能建立全部口径。

事实小样来自 [既有规范化候选](../../../experiments/architecture_baseline/2026-10-04-amd-tsmc-annual-v1/amd-fy2023-cash-flow-main-agent-v2/query/turn-003/financial_extract/extraction-01/normalized.json)。其实际期间为 2023-01-01 至 2023-12-30，状态仍为 candidate；字段单位通过不代表整个财务包已核验。业务图使用 [BusinessMap 契约](../../../src/uteki/domain/business_map/models.py)。

### Schema 告诉使用者什么

Schema 不只是“JSON 怎么写”，还要说明字段代表什么、适用范围、怎样读、什么状态可用。五类小样的 Schema 与消费说明是验收契约；生产端沿用已有各类模型和服务，不宣称新增统一 API 已上线。

| 契约内容 | 必须回答的问题 |
|---|---|
| 来源与版本 | 来源 snapshot、原件 hash、解析包/模型运行版本是什么？证据是否属于所选公司和版本？ |
| 产物范围 | 整份材料、一个章节还是几个单元格？哪些已处理、未读、不支持？ |
| 时间依据 | `temporal_basis` 描述时点、时段、材料披露上下文、未知或不适用；按该类别要求日期与来源。不能给所有业务段落强填年度起止日 |
| 值与含义 | 数值原值/尺度、规范化值/单位、实际期间、主体/维度/口径分别是什么？不能从字段合法推断语义正确 |
| 状态 | 原件获取、解析、候选生成、内容核验、采用分别在哪里？draft / partial 是小样覆盖声明，不替代已有产品 review 状态 |
| 读取与限制 | 能按哪些键检索、怎样分页、何时必须回原文、哪些关系/口径不能自动合并？ |

精编的句子级引用和 `temporal_basis` 等共同说明是本轮拟议契约。现有 BusinessMap Evidence 使用段序号、text_hash 等定位；与新解析包的 source/block 绑定在小样元数据中明确映射，不声称生产适配已经贯通。

## 4. 验收怎样分层，结果怎样写

每条记录都写 **输入 → 动作 → 预期 → 实得/未运行 → 证据**。预期答案放评测材料，不进入发现、提取或规范化输入。以下阈值针对指定验收集；不外推“全部财报正确率”。

| 层 | 输入与动作 | 预期和通过条件 | 当前实得 / 待运行 |
|---|---|---|---|
| 获取 | AMD/TSMC 明确年度范围；核对身份、版本与 hash；执行范围缺失/错公司/越截止日等反例 | 限定目标原件/必要附件逐份核对；误接纳错公司/期间/时间为 0；未知与失败不写成未披露 | 历史年度获取有回执；[新增角色/反例规范](official-scope-v1.zh-CN.md)尚须逐项实施验收 |
| 程序解析 | 扫描冻结全文，检查 DOM→块、表格、目录、锚点及不可见/图片范围 | 每个问题有位置和分母；文本保留不等于金融含义正确 | 双公司结构审计已运行；AMD 1,184 块、TSMC 1,929 块。整文语义/图像/脚注正确率未评测 |
| 小样契约 | 读取五类小样与对应 Schema；比对 source/hash、块/格、单位、关系方向与状态 | 全部必需字段和引用可验证；草稿/partial 不冒称全产物；原值与规范化值一致 | 小样的具体校验结果以生成回执为准；这不是新的模型提取质量分数 |
| 模型加工 | 固定章节/表格、Prompt/Schema、模型配置和独立答案；分别检查事实、精编、业务图 | 数值/符号/单位/期间/主体/口径、重要限定、漏项各计分；关键串范围错误为 0 | 历史现金流候选可展示；本轮未运行新的精编/业务图模型生成，也未评测全文漏项 |
| Query Q1 | 明确问“有哪些报告分部，All Other 是否属于报告分部，Data Center 主要包括哪些产品？” | 四个分部正确，明确 All Other 不属于；证据包含块 72–77 相关片段，产品保留“主要包括” | 是本题的待运行标准；要求块 77 仅因本题明确问 All Other，不变成所有业务 Query 的硬规则 |
| Query Q2 | 明确问 AMD FY2023 经营现金流原报表值、币种尺度及实际期间，并限定 source | 原表 `1,667`，百万美元；如读规范化事实则 `1,667,000,000 USD`；引用行/列/单位/主体，区分候选 | 可对照历史真实候选/Query；本轮没有新增实时模型回答 |
| Query 反例 | 漏主体/截止日；询问未获取电话会；要求不支持的跨口径比较 | 报缺范围/材料/适配，不回退别的公司或版本；保留获取证据和查找边界 | 待纳入新定题集；成功检索一段不证明缺口回答正确 |
| 端到端 | 从上述显式范围到答案，逐跳核对原件→块→候选/索引→回答 | 所有引用归属正确；回答范围与实际已处理范围一致；不能用好答案掩盖解析缺陷 | 既有链路只证明其历史样例；本轮完整端到端 benchmark 未运行 |

**分母先冻结。** 解析按确认应保留的块/表格/图像单元评测；事实按应提指标×实际期间×维度评测；精编按重要披露与限定清单；业务图按节点/关系/属性；Query 按问题所需证据与回答要点。不同分母不能相加成为单一“正确率”。

未来稳定性试跑每个指定问题先顺序运行 3 次，同输入、同来源版本、同配置，比较事实、证据充分性、缺口和费用/耗时。措辞不同单独记录，不等于事实不稳定；3 次一致也不保证未来确定性。新模型试跑的次数与预算须在执行范围中明确，本文件不自动触发请求或重置账本。双模型裁判作为辅助，其一致意见不能取代独立原文对照。

## 5. 本轮单项修复：原始锚点必须回到包含它的块

已复现：AMD 原件 `f-313` 位于现金流块 686 的 `1,667`，旧 anchors 却指向块 688 的目录导航。拟议算法优先取包含锚点的最近合格块；只有独立标记/包装锚点才使用后继规则。隐藏、重复、文末无目标等情况分别保留诊断。

验收至少覆盖段内 span、表内单元格、嵌套表、块自身、两块之间的空锚点、包装元素、隐藏 id、重复 id、末块内及文末后锚点。验证旧包 hash 不变、新包结构合法、块内容不因锚点修复被改写、新旧锚点差异可解释，固定环境重建可复验；另用 TSMC 和独立合成结构检查。

不采用顾问中未经核实的“PART I 锚点应固定到块 39”作为通用断言：块 39 的文字虽是 PART I，但它与块 40 的 BUSINESS 共享继承来源锚点；需要按原始 DOM 与具体锚点属性判断。修复不顺带删导航、重编号或改 TSMC Item 识别。本节定义验收，完成状态以本轮实际修复记录为准。
