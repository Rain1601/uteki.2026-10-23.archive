# Uteki 界面规范 v1

这是一套约定的设计基线，不表示当前所有页面已经符合规范。用户最新明确反馈优先。

## 2026-10-21：整屏工作台与局部滚动

公司与 Manager 对象列表支持明确按钮展开/收起：展开显示搜索、名称与原有元信息；收起保留窄栏 logo/头像、选中态、名称提示与键盘可访问名称，仍可点击切换对象，不将整列隐藏。两种对象列表共享本次会话的收起状态，与最左全局导航独立；宽度变化平滑推动内容并保留正文阅读锚点、搜索条件，减少动态效果时直接到位。

同日用户反馈：首页多个浅底区域使界面碎片化，后续恢复连续底色，主要用留白、浅灰细线与字体层级分区；颜色集中于数据、曲线和小面积选中态，避免用逐块浅底替代结构设计。

用户确认页面整体适配窗口，标题、导航和操作区固定；超量内容在所属组件内部原生滚动，报告也采用固定标题与操作区、正文独立滚动。不靠缩字号、截断内容或隐藏滚动条塞进一屏。按页面逐步落实，不能把首页完成记为所有页面已完成。

## 2026-10-21：向 Anthropic 原站原生做法学习

用户说明 Editorial 是从 Claude 官方网页蒸馏出的说明，要求优先采用原站原生做法，并逐条 review 了改动。依据为 `docs/design/dashboard-demos/editorial/study/` 中 10-10 留存的 overview、connectors、docs 及研究论文截图；未重新访问线上页面，不称像素复刻。原站自有字体 anthropicSerif 不可用，以已授权的 Noto Serif SC / Liberation Serif 替代。用户确认：

- **标题**：页面标题（投资总览、公司名、报告标题）用衬线常规体、大字号、不加粗。
- **正文**：报告长文和界面正文改为无衬线，覆盖此前“衬线负责阅读”的约定；数字仍用 tabular-nums。
- **强调色**：主按钮、选中 tab 下划线等交互强调用墨黑；蓝色保留给品牌 Logo、图表序列和链接文字。冷白底与“明快”分类色不变。
- **分隔与容器**：分区用浅灰细线，不用深色粗线；普通内容不包卡片，只有浮层使用圆角卡片与阴影。
- **选中态**：顶部 tab 用墨黑下划线；侧栏和列表选中项用浅灰圆角底块。
- **标签与符号**：每页最多在标题上方保留一个分类小标签；链接不加 `→`；`↗` 只用于离开当前页面的入口；编号只用于真实顺序（如报告章节）。
- **动效**：不加入页面加载动画；保留既有 hover/展开过渡与减少动效设置。

实施顺序：先修共享问题并集中 token，再按首页 → 报告/Manager → 公司页推进；公司概览去重与取消轮播会改变 10-01 认可的结构，须另行确认。规则确认不代表各页已改完或已获视觉认可。

## 2026-10-15：将 Editorial 设计应用到投研前台

用户明确认为 `dashboard-demos/editorial/` 是目前最好的设计，并授权以它优化 Swiss C 各页面。迁移标题层级、正文与控件的字体分工、细分隔线和按阅读任务组织的留白；保留机构/公司/Manager 的既有外框、数据、来源与导航。不要直接导入 Editorial 的全局样式，以免同名组件互相覆盖。

同日反馈明确要求页面与蓝白 Logo 统一，用户已认可冷白底与蓝色强调的白天配色。夜间避免大面积蓝底，本轮候选采用中性石墨灰，仅交互强调使用灰蓝；同一丝绸 Logo 在夜间单独提亮、降低饱和度，白天原样保留。夜间方案尚待用户视觉认可。横排记录卡片随最长内容等高、底部状态对齐，保留完整标题；不要通过截断或固定高度掩盖中英文内容长度差异。

用户随后认可整体进展，并要求保持白天配色、显示选择收进 sidebar。字体、语言、主题与设计说明统一位于全局侧栏底部，复用侧栏展开/收起；顶部不再放通用“上下文”按钮，出处和章节目录保留贴近对象的入口。首页标题、模拟数据标识与截止范围保留，标题区与内容连续，不增加横向接缝。列表占位和选中正文使用相同版心与对齐规则，切换不应导致横向跳动。

新增 `Editorial` 字体方案为无已存偏好时的默认值，复用原型的本地 Liberation / Noto 字体。原瑞士、书刊混排和经典宋体选项及已存选择继续有效。字号按工作台而非官网展示页调整；图表序列、买卖与风险状态保持自身语义。用户认可的是参考方向，本轮具体迁移效果仍待用户 review。

## 2026-10-10：Anthropic 启发的共用编辑原则

用户要求逐渐沉淀支持新页面、组件及自主设计的原则。第一版位于[EDITORIAL_DESIGN_PRINCIPLES.md](../../../docs/design/dashboard-demos/editorial/EDITORIAL_DESIGN_PRINCIPLES.md)：概述先行、结构清楚、字体分工、版心随任务、操作贴近对象且回程完整、图表只解释一个问题、证据语义保持、语义主题稳定定制。原站观察、已有认可基线与待验证推导分开。研究报告是当前应用实例；不称为Anthropic官方规范或所有页面已经符合，不将公共官网的字级密度照搬到每种App页面。按任务选择不同布局，复用既有tokens与组件。

## 2026-10-10：Data Agent 单次运行采用三栏查看

用户确认左侧任务/运行、中间结果与调用过程、右侧评估。复用真实工程后台，不恢复退役的演示工作台。当前左侧是已记录运行列表，不称为可发送新任务的会话系统。中间结果/过程/配置切换保留同一运行，右侧固定该次运行的标准与评估；三栏分别原生滚动。原失败与恢复都保留，切换或浏览不启动模型。

用户复查确认左侧按执行开始时间倒序，最新运行在最上面。历史未保存运行开始时间时取首个有效模型调用时间；未知时间置末，不以运行名称或文件修改时间猜测日期。

评估区分程序校验、模型审核、Codex 独立验收及人工意见；费用区分已知估算与未知预留。评估和过程按实际运行、版本与证据绑定，四项数字正确不能替代整体交付通过。详细原文和结构化记录按需展开；既有双结果比较继续独立评分。前台公司名单和采纳状态保持原范围。

## 2026-10-10：正文媒体与交互反馈

用户认可当前调研出来的交互，要求可展开媒体、视频组件进入阅读页，并探索不同动效，不全部使用方块流程图。媒体跟随正文解释用途；视频、曲线、轨道等按内容选择。保持清楚的图注、播放状态、关闭返回和主题配置。此反馈不代表每个新素材或生产迁移已获视觉批准。

## 2026-10-10：整体编辑风格确认与组件行为

用户认可完整Editorial工作台风格，并授权参考Material UI及其他UI网站完善组件。保留现有字级、留白、配色角色和整体结构，参考成熟组件的行为、键盘路径、错误反馈与组合方式；不把授权理解为替换成Material默认皮肤，或全部组件/生产页面自动获批。

## 2026-10-10：PDF风格确认与整体页面推进

用户确认中英两页PDF排版OK，后续继续组件与整体页面设计。保留已经固定的字体角色、阅读宽度与版面规则；从独立样册推进概览/列表详情/文档阅读的组合，不因PDF认可声称网页具体样式获批。新增原型仍明确模拟范围，不默认替换生产Swiss C或真实后台。

## 2026-10-09：Anthropic 编辑设计方向与组件样册

用户明确喜欢 Anthropic 多个页面的编辑设计，颜色无需一致，并要求学习 Header、Sidebar、PDF、Table 及全部常用组件，以确定风格、组件化和稳定定制。后续新样例以字体角色、主次结构、阅读宽度、细分隔线和栏目节奏为核心，不用普通 SaaS 组件完成度代替用户审美偏好。无衬线负责结构与操作，衬线负责阅读；标题角色可按页面变体选择，不能默认全部衬线。配色是可独立定制的语义主题，状态与数据身份保留。

独立样册位于 `docs/design/dashboard-demos/editorial/`，版本 v0.1。用户认可的是 Anthropic 总体方向，样册细节仍待查看；不把此次方向认可扩大为已批准覆盖 Swiss C、旧 Dashboard 或生产页面。组件盘点区分官网实见、DOM 检查与风格推导，PDF 单独核验。固定字体版本和跨机器字形尚未完成。

## 2026-10-07：业务结构与收入结构分别成图

用户明确要求每张图只讲一个维度。业务结构图回答“有哪些业务、提供什么”，默认展示真正的层次图，收费方式和证据放详情；收入结构图单独回答“选定期间的收入如何构成”，有核定数据时使用条形、饼或环形图。不能把 `revenue_component_of` 和“包含”混在业务树上靠颜色区分。移出收入分类后仍须回原文补齐广告等核心经营活动，不可仅删节点或改类型而漏掉业务。

报告分部、业务/应用平台和产品服务保留各自身份；业务图面积不代表金额。收入图仅使用同一公司、期间、币种/单位、收入范围及分母下互斥穷尽、可勾稽的分类，明确金额、合计与证据。合并披露不拆成独立产品收入；负调整或抵销用带正负轴的条形/勾稽表，不能取绝对值或塞入饼图。数据为空、分母未知、范围不全或勾稽失败时显示具体缺口，不补零、造“其他”或画成完整构成。业务与收入可以有据多对多关联，不假设一对一；需要时用映射详情检查，不重新混成一张树。

从财报提取节点与关键信息，保留片段依据，再生成 Mermaid 及可见图；JSON、字段表和文字关系作为详情。保留源码及候选状态，呈现不代表生产 Agent 已自动生成或用户已认可最终样式。内容与验收方法见 [业务图 Skill](../../uteki-business-diagrams/SKILL.md)。每轮反馈按当前 TODO、此前完成、本轮完成、下一步呈现。

## 2026-10-06：后台只保留结果与过程两个主入口

用户随后明确：运行结果页的左侧列表固定在窗口中，阅读右侧内容时不能随整页滚走。顶部导航占固定空间，右侧内容独立原生滚动；左侧长列表仅在自己的区域内滚动，不牵动右侧。无可见输出的运行在列表与详情上方明确显示“未交付”，说明有记录的停止原因；不能让“执行结束”看起来像已交付结果。

本条覆盖下方同日较早的后台入口安排。后台面向工程人员，主导航只显示“运行结果”和“运行过程”。公司、材料和数据工作台不再作为并列产品模块；它们是产物的范围和下钻工具。根地址进入运行结果。前台 Swiss C 与公司名单保持原样。

每个结果展示根 Trace ID，点击进入其过程，过程可返回同一结果。供应商 Request ID 属于单次调用，不能替代根 Trace。结果概览列出实际模型、供应商、推理档位与用量；步骤明确关联各自调用。未知配置显示未记录，不猜成默认值。配置查看、运行状态、内容质量、采纳与人工评分分开表达。

A/B 使用两份产物并排、同一评分口径、分别保存分数与依据。评分绑定 Trace、结果版本和哈希；0 与未评分分开。不同输入/任务/来源范围/输出要求须提示不可公平比较。单次模型样本标明来源，不冒充完整 Agent 或模型能力排名。原始日志、产物和证据可下钻，默认不复制成第三个独立工作台。

## 2026-10-06：后台以 Agent 工程观察为核心

用户明确后台面向工程侧，核心是观察各 Agent 的运行过程和产物；数据工作台只是其中一个模块。界面可朴素，优先呈现 Agent 能力与实现阶段、任务输入、真实步骤、工具输入输出、父子运行、产物、失败、费用和未解决问题。未来 Analysis、Risk、Portfolio 沿用同一观察方式；尚未实现者明确标注，不用前台虚构样本制造运行状态。公司、材料、期间和版本继续作为明确范围保留。现已新增 `/agent-runs`，以 Agent 列表、运行列表和过程／产物／用量／配置四栏观察 Data 执行；`/data-workspace` 保留资料与财务检查。新页的视觉 review 仍由用户完成。盘点及实施证据见[代码概览](../../../docs/CODE_OVERVIEW.zh-CN.md)，整体职责沿用[工程后台方案](../../../docs/design/UTEKI_WORKSPACES_v1.zh-CN.md)。

## 2026-10-06：仅保留投研前台与真实研究工作台

## 2026-09-25：首页从零探索的最新结构约定

## 页面结构

- 公司是研究主入口；报告、新闻、材料、组合关系挂在公司下面。
- 首页以管理投资者注意力为目标：优先展示已关注公司中已有判断的变化，再展示值得开始研究的新公司及理由。每家公司维护一份主报告，追踪记录与专题报告围绕它积累；变化、证据与持续任务必须能回到具体报告因素。
- 自主研究与委托经理组合使用独立视角。前者关注判断、证据及其持仓含义；后者关注经理的持仓、动作与收益。经理角色不等同于研究报告的作者，组合动作不代表用户个人决策。
- 公司研究页只保留一个“分析报告 / Reports”入口；公司根路径和报告路径共用该入口，不再并列展示相同内容的“研究详情”。
- 标准工作台保持一个窗口：固定全局导航和必要操作，内容在明确的板块中连续滚动；公司 thesis、长文、数据库页可使用适合阅读或表格的布局。
- 优先原生触控板上下/左右滑动，不用箭头分页作为主要浏览方式。不劫持滚轮，不强制整屏吸附。
- 卡片边界稳定。展开内容发生在当前块内部，其他卡片不换位、不缩小。不用遮罩或鼠标旁弹层展示普通阅读内容。
- 全局导航结构一致；只有用户触发的导航展开可按上述约定平滑推动内容，正文滚动不改变导航宽度。保留对象列表与全局导航的清晰层级，消除重复品牌栏。
- 高密度桌面布局在窄屏可切为模块横向浏览。不可通过隐藏核心模块或操作假装适配成功。
- 本项目以桌面研究工作台为主要验收对象。默认使用用户的正常桌面视口；未经用户要求，不主动切换手机/H5 视口验收。通用前端技能的响应式建议不改变此优先级。

## Hover、展开与动效

用户于 2026-10-15 明确重视这类“小”交互，后续界面工作将微交互与交互状态反馈作为检查项。配置图与图例双向联动：悬停/键盘聚焦预览，点击固定、再次点击取消；预览展示原记录的名称、占比与金额，不重建内容、改变路由或修改业务状态。最近一次鼠标/键盘输入接管预览，静止指针不能盖过新键盘焦点。可展开入口保留方向提示，展开后同步可见状态与 `aria-expanded`；只读内容不伪装成可点击链接。

- Hover 是提示和预览，不是完成操作。使用浅底或内容显现，不出现粗描边、左侧竖杠、漂浮工具团、按钮放大。
- 键盘 focus-visible 保留清楚的焦点提示；不可为消除鼠标圈把键盘可访问性一起删掉。
- 同类入口的 hover 与 focus-visible 使用相同的内容反馈，键盘另加 2px 主题强调色焦点圈；表格中聚焦链接时可高亮所在行。按下反馈只在按住时短暂生效，不移动或缩放元素。选中/展开由实际状态决定，鼠标经过或焦点移开不能覆盖它；禁用按钮不显示可操作的 hover/按下反馈。保留当前日夜配色与整体布局。
- 预览空间预留，hover 不改变行高，不把下一家公司推走。信息太多时点击进入块内阅读。
- 进入预览可延迟约 200ms，离开延迟约 250ms；滚动经过不触发抢眼展开。点击固定，移动鼠标不能关闭正在阅读或编辑的内容。
- 按钮/底色约 120–160ms；块内内容约 180–220ms，位移最多 2–4px。使用同一 ease-out 曲线，避免弹簧、缩放、逐卡入场与整页飞入。
- 关闭恢复原滚动位置和焦点，动作按钮始终可达。响应 reduced-motion，不用动画掩盖加载。

## 内容与状态

- 一个事实只维护一份事件/版本状态，不因为在多个板块出现而重复计数。近期、历史、未读是视角，不是重复的数据清单。
- 已读不等于已审核或已采纳。Hover 不标记已读；操作失败不能显示成功。明确本机状态与服务端同步的差别。
- 新增公司显示加入理由和来源；缺失就显示待补，不代写成事实。
- 候选、未知、未接入保持真实。页面不展示实现细节、测试标签、提示词和无助于判断的说明。
- 原始材料、来源时间、修订前后与作者可追溯。研究编辑仍遵循项目快照与采纳规则。

## 交付与收敛

修改前选定参考组件，不每次另起风格。优先修正原规则，避免在共享 CSS 尾部无限覆盖。把视觉调整限制在用户授权页面，保留业务状态。

默认验收方式（2026-09-23 用户约定）：Agent 优先检查数据结构、字段映射、来源对应和代码逻辑，运行与改动相关的必要检查，通过后交付。页面视觉 review 由用户负责，不默认打开浏览器、反复截图、切换语言/视口验收或为细节多轮调整。用户明确要求视觉检查，或必须在浏览器复现具体问题时，才做定点检查；不因缺少视觉验收阻塞交付和已授权开发。这一约定优先于通用前端技能中的强制视觉验证建议。

按需视觉 Review 清单（供用户检查，或明确要求 Agent 视觉检查时使用）：
1. 首屏能否辨认主对象、变化和下一步？有无重复栏目与冗余大标题？
2. 字体与元信息层次是否稳定？浅色文字是否可读？中英文是否都成立？
3. 滑动、hover、展开、收起是否保持位置连续？有没有跳动或遮挡？
4. 鼠标、触控板、键盘、窄屏与减少动效是否有等价路径？
5. 已读、审核、空状态、失败状态是否真实？
6. 分别记录自动检查和实际视觉验收。未看过真实页面不得声称视觉通过。

正常交付附页面入口、已完成的自动检查和已知限制，视觉反馈随后处理；不因为可以再设计就无限扩展范围。

## 2026-10-07：工程后台的调用配置切面

- 结果和过程以同一 Trace/调用关联；逐调用保留当时配置，不能用当前设置覆盖历史。明确指定、已记录、未记录、未发送与供应商实际生效值分别表达。
- 调用发生时间常显并标注时区，详细配置和原 UTC 可展开；查阅、刷新和并排比较不暗示新调用。左侧选择稳定，右侧阅读和展开保持位置。
- 多模型试验按单次、单任务推进，每次核对结果、用量和配置再继续；候选配置和计划任务不冒充已执行结果。
- 采样参数显示实际值和未发送原因。明确区分 API 不支持、当前模式忽略、历史未记录；固定配置不承诺逐字复现。比较重复运行时，事实稳定、文字一致、解释质量与成本各自有依据，不合成一个模糊的“成功”。
