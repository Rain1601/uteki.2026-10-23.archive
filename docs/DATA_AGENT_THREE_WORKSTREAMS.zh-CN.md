| 主 To-Do | 业务目标 | 交付物 | 当前判断 | 建议推进顺序 |
|---|---|---|---|---|
| **DA-01 获取与储存** | 给定公司，找到所需官方材料/数据，持续更新并保存 | 原始文件或 API 响应、来源清单、版本、获取记录、缺件说明 | SEC 获取、官网有限发现及归档已有；任意公司发现、全材料获取、FMP 接入和持续监控未验 | 先确认材料与来源范围，补关键获取缺口；监控与更多来源后置 |
| **DA-02 解析与索引** | 把材料变为能查、能读、能定位出处的数据 | 原文块、表格、结构化事实、目录/索引、使用说明、原文定位 | HTML 能力较齐；PDF 有文字/页码/坐标基础，完整章节/表格索引不足 | 明确 PDF/HTML 的产物和查询接口；按冻结材料验证，不等所有公司取齐 |

这三个是业务能力，不是三次很小的编码任务。下面只列模块、问题和验收，不另建平行任务队列。完成当前范围不代表官网、新闻、所有格式均已支持。DS-02 既有财务范围保留为范围契约，不因收敛而删减标准。

## DA-01 获取与储存

| 模块 | 负责什么 | 当前能力 / 问题 | 下一步与验收 |
|---|---|---|---|
| 公司身份与官方来源 | 公司名称/代码识别，官网、IR、blog 等来源归属核验 | 有显式身份/来源配置；A01 从指定官方根起点发现材料。不能称仅输入任意公司名就可完整发现 | 冻结身份歧义和官方来源判据；陌生公司、同名与错误域名独立验证 |
| 材料发现与获取 | SEC 财报/附件、官网报告、网页、新闻、博客；API 原始响应 | SEC 程序化获取、模型发现英文 HTML 已有；FMP 当前没有已验收接入，新闻/博客全集未验 | 先定义各来源应取什么；按应收清单核对实收，不拿下载成功代替取全 |
| 储存、去重与版本 | 保存原字节、URL、时间、公司、期间、内容 hash、版本关系 | 已有 hash 储存、重复内容复用和改版保留。未知发布日期明确不可用于历史截止日推断 | 区分相同文件、镜像、改版和重复披露；保留全部来源，不全局删相同段落 |
| 更新与监控 | 定期发现增量、去重、留失败、恢复、观察延迟 | 有 refresh/恢复组件；持续监控稳定性未验 | 当前列为后续模块；按来源和时间窗口独立验收，不无变化重取 |

输入格式与储存形态须分清：PDF/HTML/Markdown 是文档表示，JSON 可是原始 API 响应或加工产物，DB 是结构化储存。SQL 是查询语言，不是原材料类型。PDF/HTML 的现有能力不能推定 Markdown/任意 JSON 自动支持。

**归属与优先级：**
- 优先处理的缺口：官方来源范围、应收清单、首次公开时刻。台积电 T01 的实时目录受阻及日期缺失归在这里。
- 已有成果封存：DS-03-A01 两家公司各一件 HTML 有限验收；T01 冻结目录 31/31 件和三次一致不再反复列为新工作。
- 外部阻塞单列：目录 Cloudflare 挑战；缺专业 API 权限。不能用重试次数或旧目录把缺口勾完。
- 后续：FMP 适配、历史扩展、新闻/blog 与连续监控。在对应模块下定范围，不新增公司专属任务线。

源码：[获取协调入口](../src/uteki/agents/data_query/coordinator.py#L483)、[官方发现/校验/存储](../src/uteki/infrastructure/document_sources/official_discovery.py)、[程序化获取](../src/uteki/infrastructure/document_sources/company_acquisition.py)。

## DA-02 解析与索引

| 模块 | 当前已有功能 | 缺口 / 设计问题 | 应交付什么 |
|---|---|---|---|
| 文档解析 | HTML 可见文本、段落/标题、表格单元格与目录；PDF 文字块、页码、bbox 坐标 | PDF 当前把文本块写为 paragraph，普通年报缺少真正的多层章节树；PDF 表格结构与扫描页 OCR 不在当前通用路径验收内 | 按原文顺序的块/表格、格式缺口及确定性重建记录 |
| 原文定位 | HTML DOM/锚点/字符区间；PDF 页码/坐标；指定图片可绑定文字证据 | 支持程度依格式不同；页码存在不代表章节准确或高亮已全链可用 | 从每条证据回到冻结原件的具体段落/单元格/图区域，按格式实测 |
| 导航索引与搜索 | HTML 法定目录、节点→块范围；现有 DocumentReader 按节点字面搜索和分页阅读 | PDF 索引粒度是否足够、跨页上下文如何拼接、多层目录如何供查询选择，仍需设计；现有字面搜索不是语义排序 | 小目录先导航、按需取块，能读必要上下文且不整篇灌入模型 |
| 财务结构化 | HTML inline XBRL 的有限 US GAAP 指标映射、财期/单位/证据引用、DuckDB 候选记录 | 全主表/附注未覆盖；IFRS/TWD 可读不等于数值适配完成；财务语义尚需独立核验 | 带单位/期间/口径/版本/出处的事实表，以及未映射清单 |
| 数据使用说明 | parsed package 的 schema、来源元数据、目录、manifest；query schema/指标/财期说明 | 各格式的能力声明要一致；Markdown/API JSON 的来源适配不可冒称已完成 | 消费者知道有哪些数据、怎么搜/读/查、哪些不支持 |

解析产物不必让用户记住文件名。它们只承担五种职责：**来源身份证、原文内容、导航目录、精确定位、结构化数据与使用说明**。原件始终保留。

这里需要模型的地方与工程的地方分开：现有 HTML/PDF 基础拆分与索引主要是程序；指定图片的语义转录有模型参与。是否让模型辅助 PDF 章节识别、复杂表格或全文财务提取，要在此模块设计并验证，不能宣称目前都由模型完成。

**归属与优先级：** PDF 索引与 Query 如何衔接是本模块优先设计项。台积电 T02 是这一能力的验收案例，微软/谷歌 10-K 是 HTML 对照案例。两张谷歌图片是图片补证案例。PageIndex 是候选技术路线，不是第四项产品能力；仍保留待比较状态。R7 历史阅读分组兼容归这里。

源码：[按格式解析与能力声明](../src/uteki/infrastructure/research_data/company_materialization.py#L91)、[PDF 目录构建](../src/uteki/infrastructure/document_sources/earnings.py#L63)、[HTML 标准产物与 schema](../src/uteki/infrastructure/document_sources/parsed_package.py)、[搜索/阅读](../src/uteki/agents/reading/document_reader.py#L64)、[DB 表](../src/uteki/infrastructure/research_data/query_dataset.py#L22)。

## DA-03 查询与材料交付

| 模块 | 工作方式 | 现状与缺口 | 验收看什么 |
|---|---|---|---|
| 问题与范围 | 模型识别公司、期间、材料类型及问题需求，读取小目录/schema | 指定问题已有自主计划；陌生公司/更多问题不保证稳定 | 不漏公司、不多取公司，范围歧义显式处理 |
| 查询执行 | 模型生成有类型的条件；程序编译参数化 SQL，或执行目录/文段查询 | 已有数值查找、字面文档搜索、原文分页和计算；不支持任意 SQL/任意数据源 | 能复核条件、SQL、原始返回及来源；有限指标不冒充完整库 |
| 结果复核与补查 | 模型看返回材料，缺了再取，多了收窄；程序检查范围/协议 | 已有真实循环和双审；误用/纠错与更广泛化仍有缺口 | 必需材料齐，冗余受控；缺少映射不能误说原件未披露 |
| 数据包交付 | 交付足够回答问题的数据和原文，关联版本、精确出处和缺口 | 指定题可严格加载；Analysis 真实消费未完成 | 最少充分集合；不以整份财报或数字正确掩盖遗漏/浪费 |
| 过程与效果评测 | 每步快照、模型配置、结果、修订和费用；独立评测 | 已有日志/有限题库；旧包缺失与跨题长期稳定仍未关闭 | 分别看内容正确、首审通过、完整交付、无纠错与总费用 |

例：“微软和谷歌两年收入”应得到两家公司对应年份的数据、单位、期间及精确原文依据。模型提出 entity/metric/period/source/cutoff 等条件；程序生成和执行 SQL。这里不是让 Codex 手选章节。业务解释、报告、业务图由下游分析 Agent 生成。

**归属与优先级：** E6-R5b 记录引用/动作归属、R2 探索来源影响交付、R3 无报告期末来源审核归这里，先按当前路径复现再修。R4 有限重试是共享运行机制，主归本模块、关联获取。E6-QP1 与 E6-R4 封存已有有限通过结果，剩余跨题/自然触发验收留在模块内。R22-H 缺历史原包归证据缺失，后置，不阻断新设计。

源码：[目录发现/使用说明](../src/uteki/infrastructure/research_data/query_catalog.py)、[条件编译与 SQL](../src/uteki/infrastructure/research_data/query_service.py#L246)、[自主执行](../src/uteki/agents/data_query/autonomous.py)、[复核与交付加载](../src/uteki/agents/data_query/answer_handoff.py)。

## 清理规则与本轮快速核验

1. **已完成且有证据的阶段：封存。** 不反复列“提交 A01”“重新下载同样文件”等动作。有限通过不能升级为全部通过。
2. **同责任模块的多个案例：合并跟踪。** 公司名只作验收标签。两个症状在没有因果证据前，不宣称是同一根因或删除失败记录。
3. **可本机快速检查的工程能力：已检查。** 本轮运行 official_discovery、parsed_package、company_materialization、query_catalog 四组 49 项离线检查，全部通过；覆盖去重/版本、解析包完整性、候选事实范围和目录分页等。合成/脚本检查不等同新模型质量验收。
4. **不好立即核验的：分类保留。** 设计缺口（PDF 章节索引）、外部阻塞（实时目录）、待实跑（更广 Query）、缺材料（历史包）分别记；不统一标成 Bug，不为凑完成数放宽标准。
5. **顺序：先来源与解析/查询契约，再补机制，再按模块验收。** 现有冻结材料可用于解析设计，台积电外部目录阻塞不阻断所有讨论；但其 T01 总验收仍不通过，T02 真实验收不偷跳原前置。
