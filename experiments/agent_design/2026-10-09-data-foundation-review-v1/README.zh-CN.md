# Data Agent 前置数据基础审查

2026-10-09。本轮结论：**前置工程与材料条件尚不能整体验收通过。** 已确认的缺口足以影响后续取材的完整性与聚焦程度；现在不应通过更换模型或扩大输入来掩盖它们。

本轮没有模型或网络调用，没有修改生产代码或历史数据。新增内容只有审查文档、只读探针和核验记录。工作区在本轮前已存在的未提交修复不属于本轮完成项。

评价口径：[Data 证据验收标准](../../../docs/DATA_AGENT_EVIDENCE_ACCEPTANCE.zh-CN.md)。单个固定 Query 只是调试闭环；正式验收需要多问题、多公司、范围/时间与能力边界案例。当前终点为 Data 证据包，不是 Analysis 报告。

## 审查范围与可核查结果

- 对最新真实运行所用 Microsoft 数据集、既有 Alphabet 数据集和 AMD FY2023 数据集，实际验证冻结文件及来源、只读记录和解析索引。Microsoft/AMD 另通过正式解析包校验；所选旧 Alphabet 索引没有正式 `source.json` 包，不能冒充新版正式包。
- 三个所选数据集共有 69 个 manifest 文件引用通过 hash 校验；结构化记录没有发现无所属来源的行。数字记录数量是候选披露次数，不是独立财务事实的内容正确证明。
- 小范围负例检查拒绝错公司、错来源、越界读取和提前于公开日读取。没有发现这些路径下的跨公司泄漏；没有声称所有路径均审完。
- 独立核对真实 HTML DOM、原文块与读取上下文，发现下列具体缺陷。
- 既有新版结构覆盖检查覆盖 18,155 个文本段，但只证明声明规则下的文字对应关系，不证明列表、脚注、财务口径和视觉信息已正确消费。

材料上下文探针另选用了 acquisition-reuse 中三家公司 v0.1.11 包；具体路径逐项列在材料审查中。它与上述旧数据集对照不是同一批版本，不能互相移用通过结论。

实际文件、版本、hash和记录数量见 [输入核验](verification.json)。复现：`PYTHONPATH=src:. .venv/bin/python experiments/agent_design/2026-10-09-data-foundation-review-v1/audit.py`。只重建本目录记录，不改冻结输入。

## 主要发现

| ID | 分类 | 证据与影响 | 通过条件 |
|---|---|---|---|
| F01 | 验收绑定缺口 | 前次结构审查对象为 v0.1.12；最新 Microsoft 查询实际用 v0.1.11，选定 Google 为 v0.1.6、AMD为v0.1.7。同一原件的 index/blocks hash 不同。旧审查结论不能移用到当前底稿；不意味着旧版一定全部错误 | 审查与运行绑定同一原件、底稿及读取实现；重建产生新版本，保留历史 |
| F02 | 真实上下文缺陷 | Microsoft Intelligent Cloud 的项目符号与正文分成独立块。读标题/引导句可只返回标题、引导句和“•”，读正文又缺所属列表关系 | 根据可验证结构组装符号和正文，保留标题/引导/必要并列项，不能吞入下一个无关章节 |
| F03 | 真实脚注缺陷 | Microsoft 地理收入表的(a)标记与解释分成两块，读主表不返回该限定；Google 回购等表也有相同形态 | 读主表及反向读脚注均返回必要限定，不靠公司专属条件硬补 |
| F04 | 真实目录/查询冲突 | Microsoft、Google 已有 FY2024 数值记录，但财年映射只声明当期。`FY2024 revenue` 在生成SQL前被拒绝 | 发布有原文依据的历史财年及精确日期映射；缺失/歧义期间仍显式报缺口 |
| F05 | 已声明适配限制 | 所选 AMD 原文可读，但其冻结结构化数据为0条；完整月份协议不支持周制财年的日期边界 | 使用明确支持的精确来源日期协议新建底稿并核验；未支持时标记“未结构化”，不得伪称未披露 |
| F06 | 说明不充分/风险未量化 | 除capex外，指标定义多数只是重复字段名；业务维度是原始XBRL标识。“2025年度”与“FY2025”对非自然年公司会解析成不同期间 | 补足指标定义、口径、覆盖和日期含义；歧义不能静默猜测。影响模型准确率尚未量化 |
| F07 | 新交接代码的集成缺陷 | Microsoft 部分投资表 full 读取约112KB，超响应限额；compact约42KB能读。新有界交接却固定用full重取，合法紧凑读取无法进入复核 | 查询与交接使用兼容表示和原文验证；不靠截断表格或无界放大输入绕过 |

F02/F03原文、DOM、实际返回块及 F07 大小探针见 [材料证据](material-probes.json) 与 [材料审查](material-review.md)。F04/F05/F06及范围负例见 [目录/查询审查](catalog-review.md) 和 [可复現记录](catalog-probes.json)。

## 已有但不能误标通过的能力

- 目录、字段说明、字面搜索、分页读取、参数化查询和输入范围限制均已有代码；不等于它们能准确回答所有问题。
- 相邻“脚注本身是表格”的读取修复已有历史验证；没有覆盖本次“脚注标记和正文分离”的形态。
- 当前目录主要为 Part/Item 层级。大片章节内如何精确定位仍依赖关键词与模型选择；缺少细粒度语义导航是能力限制，不把每个宽章节都算解析错误。
- 图像内容、远程脚注、跨节引用和全部复杂表格语义仍有未审范围。不能从零文本遗漏推导它们已通过。
- 当前 Analysis 前复核会发现缺口并阻断；自动补查、查询替代关系和重读状态修复仍未完成，且不属于本轮前置审查已修复的内容。

## 按顺序继续

1. **当前优先：在明确版本底稿上修复列表与脚注的阅读上下文。** 用上述真实样例和独立合成输入验证“必要内容齐全、不额外吞入”。原始文本和引用保持不变。新增版本和验收记录必须与运行入口绑定。
2. 修复目录、财年/数据覆盖与查询可用性的一致性；明确 AMD 的精确日期适配范围和指标说明。
3. 修复查询/交接表示不一致及过程快照的已知状态问题，再验收 Data 的查询修订与交付闭环。
4. 按已定义多维矩阵冻结测试集，Codex独立评审证据包的充分性、聚焦、忠实性和可消费性；评测答案不进入执行输入。

本轮没有替任何公司填写业务答案。下一轮修复聚焦第1项，其余保持有序队列。
