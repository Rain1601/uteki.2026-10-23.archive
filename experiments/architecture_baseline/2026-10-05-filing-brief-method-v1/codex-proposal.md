# Codex 当前会话：材料精编方法提案

状态：在读取本轮 DeepSeek 回复之前保存。属于方法设计，不是完整年报精编结果，也不是 Gold 答案。本会话有额外历史上下文，不能将此比较称为严格控制条件下的模型排名。

## 目标和取舍

让阅读者快速理解公司如何赚钱、经营结果发生了什么、增长付出什么代价、有什么重大限制。压缩篇幅但保留会改变理解的事实、口径、反证和未知。Data Agent 不据此给出买卖或仓位结论。

“必须看”：删掉会使业务、盈利质量、资金安全或重要执行条件被误解的信息。“需要留意”：当前影响尚不明确，或有待后续兑现，但有明确业务关联的信息。“本次不展开”：重复表达、版面噪声或与本次目的无直接关系的细节。原始材料不删除；低关注内容留下位置和省略理由。

重要性与可信度分开。重大但证据不足的风险不能因不确定而消失。固定章节是覆盖检查的入口，不能直接给整章统一分数。行业关注点可由 Agent 从业务模式提出，但不得用样例公司的答案替代阅读。

## 输入和处理

输入必须绑定公司、材料版本与哈希、语言、报告期间、材料截止范围、阅读目的、可用原文块/表格/图形，以及已核验财务记录和缺口。只有当前材料时，不假装知道上一年的完整风险变化；比较只能基于当前材料给出的对比信息。

1. 建立全文覆盖清单：目录、正文、表格、图形、附注、附录、引用但未取得的外部文件；标明取得、解析、已检查与未检查。缺页或图形不可读属于材料缺口。
2. 按业务问题取证：客户与产品、收入来源、竞争与供应链、盈利/现金、资本配置与资本承诺、风险、治理/审计及重要会计政策。财务附注必须进入扫描范围，异常与反证优先复核。
3. 每个信息点记录内容类型（已披露事实、管理层解释或计划、分析解释）、重要性、理由、支持位置和会改变含义的限制；数据不足、冲突与不可比单列。
4. 先组成带证据的信息集合，再选择信息结构与图表；不要先写漂亮文章再补引用。图中每个数据点引用事实记录，业务箭头说明是交易关系还是分析推断。
5. 双向审核：结果回查原文的正确性；原文回查结果的重要遗漏。审阅者独立扫描原文的审计、风险、承诺、附注与被省略内容。程序检查身份、引用、金额/期间/单位/公式和重复；模型检查含义与遗漏；重大争议交给人工裁定。
6. 修订只针对有证据的问题，保存版本和修订理由；缺失原始材料通过补充材料解决，不能靠更多提示词填空。

## 输出

人看一份中文精编及等义英文版：业务图、必须读的信息、关键财务表、重要变化与约束、留意事项与下一次验证问题、材料缺口。图表数量和篇幅随材料复杂度决定，不强制六张图或机械压缩比例。

系统同时保存三类可追溯信息：重要性与依据清单、全文覆盖/省略清单、审核与版本记录。财务表引用已有规范化事实，必要新增候选按原有分层核验处理，不再由文章重新生成一套金额。

精编是共享材料层的阅读辅助；不同 Manager 可在此基础上重新排序重要性，并直接回查原文。材料层保留事实和限定条件，经理的投资判断保持独立。

## 比较、老师和 Skill

下一阶段冻结同一份完整材料，使用同一任务目标与输出限制，两边分别产出，保存工具和模型条件。评分顺序：重大事实错误/误引，重要遗漏，限定条件及负面证据保留，可追溯性，再看阅读效率、时延和成本。没有人工审定的重要信息清单时，不能宣称召回率100%。

Codex 输出是候选老师，不是事实依据。隐藏作者让用户对照，另做从原文出发的遗漏审阅，避免双方共同遗漏。按错误类型吸收更好的步骤，不强求整篇赢家。将胜出方法写成共享核心 Skill，Codex 与 Uteki 各自适配工具，记录实际加载文本、哈希和模型；在未用于教学的另一家公司或报告期上复验后再提升为默认方法。

概念例（非台积电现状结论）：若年报说某工厂已投产，而未来扩产仍需许可，精编必须分别保留“已投产”和“未来扩产待许可”；不能合并为产能都已兑现。庆典照片可以不展开。若附注另载重大建设承诺，即使正文只写一行，也应提升到必须看。

当前未确定：首份成品用哪个材料版本、人工阅读篇幅偏好，以及正式精编任务执行器的接入方式。前两项由用户/明确实验配置决定；执行器应复用已有来源和记录能力，避免临时 Codex 代跑冒充默认系统能力。
