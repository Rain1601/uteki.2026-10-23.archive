## Purpose

为研究项目提供可重复、可追溯的进度盘点，使使用者能够一起查看代码版本、待办声明和规范记录，识别需要进一步复核的证据缺口，避免把文档或文件的存在当作已验收的功能。

## ADDED Requirements

### Requirement: 只读事实盘点

检查命令 SHALL 输出 Git 版本及工作树信息、TODO 的勾选声明和来源行号、规范文档的标题及显式状态。命令 MUST 不修改项目、不调用模型、不运行测试，也不刷新网络远端。

#### Scenario: 技术提案存在于提交中
- **WHEN** 项目有明确标为提案的规范文档和对应 Git 提交
- **THEN** 报告保留提案声明，不把提交解释为能力实现或验收通过

### Requirement: 声明与验证分离

报告 MUST 将 TODO 勾选保留为声明，将链接存在性保留为文件检查结果；尚未执行的实现和语义验证 SHALL 标为未验证。

#### Scenario: 勾选任务缺少证据文件
- **WHEN** 已勾选 TODO 指向不存在的本地文件
- **THEN** 报告同时展示勾选声明与缺失链接，不判定需求通过

### Requirement: 有界输入和可自动化输出

命令 SHALL 支持 JSON 和简明文本输出、正整数提交条数限制及显式项目目录。链接越出项目范围 MUST 不读取；无有效 Git 仓库或非法参数 MUST 返回非零退出码。开启链接检查时，缺失或越界链接 MUST 返回非零退出码。

#### Scenario: 越界链接
- **WHEN** TODO 链接解析到项目目录之外
- **THEN** 报告标记越界，不读取目标内容

#### Scenario: 无效项目
- **WHEN** 指定目录不属于有效 Git 仓库
- **THEN** 命令清晰报错并返回非零退出码
