## 2. 视觉基线（摘要）

完整规则和例外见界面规范。当前有效的要点：

- **字体角色**：页面标题（投资总览、公司名、报告标题）用衬线常规体、大字号、不加粗；正文和界面文字用无衬线（2026-10-21 覆盖了此前“衬线负责阅读”）；数字用 tabular-nums。默认字体方案 Editorial（本地 Liberation / Noto），瑞士、书刊混排、经典宋体三种方案仍可选，已存偏好继续读回。
- **颜色**：白天冷白底 `#f7f9fc`、品牌蓝 `#315d9e`；夜间石墨灰底 `#24262b`、导航 `#1d1f23`，夜间 Logo 单独提亮（夜间方案仍待用户视觉确认）。交互强调（主按钮、选中 tab 下划线）用墨黑；蓝色只留给品牌、图表序列和链接文字。Buy 绿、Sell 红、Report 紫的语义色贯穿图表和操作历史。
- **分区**：连续底色，用留白、浅灰细线和字体层级分区；普通内容不包卡片，只有浮层用圆角卡片和阴影；不用逐块浅底代替结构设计。
- **选中态**：顶部 tab 用墨黑下划线；侧栏和列表选中项用浅灰圆角底块。
- **标签与符号**：每页最多在标题上方保留一个分类小标签；站内链接不加 `→`，`↗` 只用于离开当前页面的入口；编号只用于真实顺序（如报告章节）。
- **动效**：不加页面加载动画；保留 hover、展开、区间滑块（200ms）、主题切换（220ms，仅点击时启用）等过渡；全部遵守 `prefers-reduced-motion`。
- **Token**：`tokens.css` 最先加载，集中定义标题字体角色、8 档字号、墨黑强调和圆角；颜色值在主题块，字体族在 `typography.css`。

## 3. 布局与交互约定

- **整屏工作台、组件内滚动**（2026-10-21 确认）：页面整体适配窗口，标题、导航和操作区固定；超长内容只在所属组件内部原生滚动，不靠缩字号、截断或隐藏滚动条塞进一屏。由 `viewport-layout.css` 承担。**目前只有首页落实**；报告、Manager、公司页尚未迁移。
- **对象列表**：公司与 Manager 的左侧列表可展开（224px）/收起（64px，只留 logo/头像、选中态和名称提示）；收起状态只在当前会话共享，不写入研究状态。首页不显示对象列表。
- **全局侧栏**：字体、语言、日夜主题和设计说明放在侧栏底部；顶部不放通用“上下文”按钮，章节、出处、模拟说明从对象自身的入口打开。
- **反馈一致**：所有 hover 都有对应的 `focus-visible` 反馈；按下时短暂降低透明度，不位移不缩放；可展开项同步 `aria-expanded` / `aria-controls`，关闭后焦点回到入口。
- **状态保持**：切换语言、主题、区间、对象或跨路由返回时，保留阅读位置、筛选、选择和焦点；不重建无关节点。
- **模拟数据**：虚构样本处处标明（下划线文字标识，不用灰底块），不把设计情景当成真实账本或真实成交。

## 4. Swiss C 页面结构

| 页面 | 当前结构 |
|---|---|
| 机构首页（投资总览） | 标题行只留模拟数据说明、截止日期和币种；North / Field 作为“投资总览”旁的图例按钮（单击切换、双击看持仓历史、支持方向键）；近 1 月 / 年初至今 / 近 1 年区间切换；收益曲线带买卖标记和报告事件轨道，点击看事件详情；右侧紧凑组合配置（环图中心显示持仓构成）、持仓和“组合动态”列表（决策与风险按日期倒序，可筛选） |
| 公司 | 概览按栏目展开，资料、关注点、报告目录；报告目录按作者/公司、类型、标题联合筛选 |
| Manager | 概览、研究覆盖（四标签、等高卡片、分页）、报告、组合决策（配置变化／研究依据／风险与回应）、风险跟踪（状态筛选、左列表右详情）、操作历史 |
| 报告阅读 | 具体版次标题、判断、章节、全局证据编号和出处面板；网页与 PDF 共用 `report-presentation.mjs` 的内容 |

风险 → 决策 → 报告 → 返回的往返保留原路径、筛选、阅读位置和焦点；各 Manager 的选择互相独立。

## 5. 代码与测试约定

- 原生 ES modules，无前端框架、无构建步骤；不引入带全局选择器冲突的整套原型 CSS。
- 样式按职责拆分（如 `institution.css`、`manager-workspace.css`、`report-reading.css`、`directory-controls.css`、`theme-motion.css`、`viewport-layout.css`）；改动优先修改生效规则或共享 token，不在末尾追加更高优先级的覆盖。
- 视图逻辑按对象拆分（如 `institution-view.mjs`、`manager-view.mjs`、`portfolio-updates-view.mjs`、`report-directory.mjs`），每个模块配 `*.test.mjs`。

运行 Swiss C 检查：

```bash
node --test docs/design/company-workspace-swiss-c/*.test.mjs
```

研究工作台的 JS 检查包含在 `scripts/run_offline_checks.py` 里。

## 7. 工作方式

- 默认由用户审阅页面效果；只有用户要求或需要复现具体浏览器问题时才打开浏览器或截图。程序检查、浏览器核对和用户视觉认可分开报告，测试通过不等于视觉认可。
- `frontend-design` 只在用户点名时使用。
- 样式工作不调用模型、不部署。
- 新的前端决定写进本页对应章节；反复出现的偏好改写界面规范里的对应规则，不堆叠互相矛盾的例外。
