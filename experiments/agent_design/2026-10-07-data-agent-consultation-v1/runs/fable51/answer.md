# Uteki Data Agent 设计意见

## 0. 总判断

当前瓶颈不是模型选型，而是三件事：**任务契约不清、答案与覆盖分母缺失、candidate→正式采用的闭环未定义**。10 次 Sonnet 重复里事实 5/5 稳定、说明 1/5 通过，说明数值提取已基本可控，失分集中在"缺口判断"和"解释口径"——这两处的失败首先是契约与评分问题，其次才是模型问题。先修契约、建小答案集，再谈分工。

---

## 1. 先下判断

### 1.1 最该解决的三个问题

| 优先级 | 问题 | 依据 | 不解决的后果 |
|---|---|---|---|
| 1 | **缺口（gap）契约未定义** | "至少两项 gaps"旧提示；多次把"无管理层归因"扩大为"无法计算" | 任何评分都在惩罚模型遵守了错误指令；Analysis 收到假缺口会发出无谓补证请求 |
| 2 | **没有独立答案集与覆盖分母** | 40 条实例只对应 6 个独立事实；semantic_completeness=not_evaluated | 无法区分"引用能定位"和"覆盖完整"，benchmark 扩不动 |
| 3 | **正式采用的判定规则空白** | 所有快照仍是 candidate | 工程后台能展示过程，却答不出"这份数据能不能用" |

### 1.2 可能想错的地方

- **把 1/5 当成 Sonnet 不稳定。** 五次说明文字各不相同，但核心事实一致；失败点是口径不是算力。先修契约再评稳定性。【事实+判断】
- **单个匿名 Codex 评审被当作标准。** 已出现 -53.2% 误判，说明裁判没有拿到"精度契约"。裁判缺答案时只是第二个有同样盲区的模型。
- **默认需要 Opus 规划。** 材料获取→解析→分批提取→精编是固定流程，规划应是程序而非模型。真正需要模型选下一步的只有"按问题补证"和"预期位置找不到报表时的定位"。现阶段 Opus 规划不值得引入。【建议】
- **默认便宜模型预处理有收益。** 你们已有确定性解析（目录、段落、表格）。用模型压缩原文会丢限定词与单位。便宜模型只值得在"候选段落排序/路由"这一处做试验，且需与关键词+目录规则对照。【假设，待验证】
- **双语精编被当成当然要求。** 它使成本约翻倍，并引入"双语一致性"这一新验收项。建议改为"一份权威语言版本 + 派生翻译"，由用户决定。

### 1.3 Sonnet 执行 / Opus 规划 / Codex 评估的成立条件

| 角色 | 现阶段 | 成立条件 |
|---|---|---|
| Sonnet 执行 | 可采用 | 契约固定、输出 JSON 可程序校验、每批输入受控（不整本年报送入） |
| Opus 规划 | 不引入 | 仅当"按问题补证"任务出现多步定位失败率可量化且程序规则无法覆盖时再试 |
| Codex/强模型评估 | 限定引入 | 裁判只拿"陈述 + 引用片段 + 答案键"，不拿全文；程序能判的不交裁判 |

## 2. 业务任务表

### 2.1 分类：独立任务 vs 横向能力

- **独立任务**：有自己的触发、产物契约、验收和失败表示，可单独跑 benchmark。
- **横向能力**：没有独立产物，附着在每个任务上，通过任务指标间接验收。

| 类别 | 内容 |
|---|---|
| 独立任务 | T1 材料登记、T2 结构化事实、T3 财报精编、T4 业务图、T5 按问题补证 |
| 横向能力 | 引用验证、版本/增量维护（refresh、重述标记）、Trace/成本记录、缺口表示规范 |

区别在用法：用户或 Analysis 只会"请求一个任务"，不会"请求一次 refresh"；refresh 的结果体现为"T2 事实版本号变了并标记了重述"。

### 2.2 任务定义

| 任务 | 触发 | 必填输入 | 最小输出 | 完成标准 | 失败/缺口表示 | Data/Analysis 边界 |
|---|---|---|---|---|---|---|
| **T1 材料登记** | 指定公司+期间+报告类型 | 公司标识、财年、类型（10-K/10-Q/20-F） | 原件、来源 URL/时间戳、目录、段落/表格索引、材料哈希 | 目录章节全部映射到段落范围；表格数≥程序识别数 | `material_missing`（未找到）、`section_unmapped`（章节列表） | 纯 Data |
| **T2 结构化事实** | T1 完成后按报表/章节批次 | 材料块 ID 列表、目标报表 schema、单位/期间契约、精度契约 | 原口径候选、规范化事实、每条引用（块 ID+行/列）、缺口清单 | 程序复算小计相符；引用全部可定位；覆盖分母内项目全部有值或有分类缺口 | 缺口三分类：`not_in_material` / `in_material_no_attribution` / `requires_judgment` | Data 可做明确公式计算；不解释商业原因 |
| **T3 财报精编** | 一份完整报告 T2 完成后 | 全部章节索引、T2 事实、精编目录模板、目标语言、篇幅上限 | 分章摘录+浓缩文本、保留表/图引用、每段落引用 | 覆盖分母（章节清单）每章有对应段；数字全部能回链到 T2 或原文 | `section_omitted`（显式列出未覆盖章节及原因） | 忠实摘录管理层解释，标注"管理层表述"；无自行推断 |
| **T4 业务图** | 一份报告 T1 完成后，可与 T3 并行 | 业务/分部/产品/客户/供应商相关章节；节点与关系类型表（见 2.3） | 节点、关系、每条关系≥1 引用、未证实关系单列 | 每条关系引用支持该关系；节点无重复命名；与分部收入表一致 | `unsupported_relation`（模型认为存在但无引用） | 不推断未披露的客户/供应商 |
| **T5 按问题补证** | Analysis 提交问题 | 问题、公司、期间范围、可接受材料类型 | 定位材料列表、摘录/事实、回答覆盖度、未解决部分 | 每条摘录有引用；明确"已回答/部分/无法从材料回答" | `question_unanswerable_from_material` 并列出已检索范围 | Analysis 提问与判断；Data 只给材料与计算 |

T1 是其余任务的前置，可不作为用户可见任务，但需要独立验收。

### 2.3 精编与业务图的定义建议及待用户决定项

**财报精编**：按"原报告章节清单"为覆盖分母，每章节输出"摘录（引用）+ 浓缩（标注为 Data 浓缩）"，表格保留为引用而非重绘。待用户决定：目标篇幅（如全文 5%–10%）、是否双语、读者是分析师还是模型消费者（决定格式）。

**业务图**：建议最小定义为"节点类型表 + 关系类型表 + 每条关系的披露证据"。首轮节点类型：公司、分部、产品线、地区、已披露重大客户/供应商、重大依赖（代工、许可）。关系类型：拥有、销售、采购、依赖、竞争（仅披露）。待用户决定：是否要求跨年可比（节点稳定 ID）、是否纳入财务量（分部收入）。不要把 AMD/TSMC 的分部结构当作默认字段；节点类型是通用的，节点实例全部来自材料。

## 3. function / skill / agent 的关系（以 T2 现金流提取为例）

不新建框架，只按"谁决定下一步"划分。

| 步骤 | 类型 | 原因 |
|---|---|---|
| 下载、哈希、解析目录与表格、分块 | 确定性函数 | 结果可重放，无需判断 |
| 在目录中定位"现金流量表"及附注 | 函数优先，失败后模型选择 | 10-K 位置稳定；20-F 目录差异大，程序找不到时让模型从候选章节里选 |
| 单位/期间/符号规范化、精度处理 | 函数 | 契约化规则 |
| 提取事实（含原口径、引用、缺口分类） | skill（版本化任务说明：提示+schema+缺口分类+2 个示例） | 可复用、可对比版本 |
| 小计复算、引用存在性、schema 校验 | 函数 | 程序验收 |
| 缺口分类是否正确 | 模型自报 + 程序对答案键 + 人工抽样 | 程序只能查"声称缺失的项是否在输入中" |
| 决定是否补读相邻章节、是否报失败 | agent 判断（有限循环，最多 N 步） | 这是 T2 唯一需要模型选下一步的地方 |
| 标记 candidate→accepted | 程序规则 + 人工签字 | 见第 4 节 |

结论：T1–T4 中 agent 成分很小；T5 是真正的 agent 任务。工程上"skill"就是一个版本化的提示/契约文件，不需要新的运行时概念。

## 4. 质量标准

### 4.1 三层分级（必须分开报）

| 层级 | 问题 | 判定方式 |
|---|---|---|
| L1 引用可定位 | 块 ID/行列是否存在 | 程序 |
| L2 引用支持陈述 | 该片段是否确实包含该数字/表述 | 程序（数字匹配）+ 裁判（文字） |
| L3 覆盖完整 | 覆盖分母内项目是否全部处理 | 程序对答案键 |

当前 reference_checks_passed 只是 L1。

### 4.2 硬性失败（任一触发即该次失败）

1. 数字、符号、单位、期间任一错误。
2. 引用不可定位或片段不含该内容。
3. 把模型推断写成来源披露。
4. **假缺口**：声称缺失的内容在输入中存在。
5. 覆盖分母内必填项既无值也无缺口分类。
6. 输出不满足 schema。

### 4.3 少量可解释指标

| 指标 | 计算 | 适用任务 |
|---|---|---|
| 事实正确率 | 正确独立事实 / 分母 | T2 |
| 假缺口率 | 假缺口数 / 声称缺口数 | T2、T5 |
| 漏缺口率 | 未报的真实缺口 / 答案键中真实缺口数 | T2、T5 |
| 覆盖率 | 有值或正确分类项 / 分母 | T2、T3、T4 |
| 关系支持率 | L2 通过关系数 / 总关系数 | T4 |
| 复算一致率 | 小计复算相符数 / 可复算数 | T2、T3 |
| 核心事实版本数 | 规范化后不同版本数 | 稳定性 |

不计输出长度、不计文字流畅度。两个模型一致只用于"降低人核优先级"，不等于正确。

### 4.4 缺口判断正确性的检查办法

每个样本预先建立"缺口答案键"：列出分母内每项在输入中的状态（存在 / 不存在 / 存在但无管理层归因）。模型每条缺口声明映射到该键：
- 声明 `not_in_material` 而键为"存在"→假缺口（硬失败）。
- 声明 `not_in_material` 而键为"存在但无归因"→分类错误（扣分，不硬失败）。
- 键为"不存在"而模型未报→漏缺口。

AMD 案例的键：逐项两年数据"存在"；管理层逐项归因"存在但无归因"。正确答案应是会计桥接 + 一条"无管理层逐项归因"缺口。

### 4.5 各任务重点

- T2：硬失败 + 假/漏缺口率。
- T3：覆盖率（章节分母）+ 数字回链率 + 抽样 L2；若双语，加"关键数字两版一致"程序检查。
- T4：关系支持率 + 与分部表一致性 + 未证实关系是否单列。
- T5：问题覆盖度自评与人核一致率；`unanswerable` 时已检索范围是否包含答案键所在章节（即是否"没找到"而非"不存在"）。

## 5. 最小可执行 benchmark

### 5.1 样本组成（第一轮 8 个样本单元）

| 编号 | 材料 | 考察点 | 集合 |
|---|---|---|---|
| S1 | AMD FY2023 10-K 现金流（已有） | 基线 | 调试 |
| S2 | AMD FY2023 10-K 利润表+分部附注 | 覆盖分母扩展 | 调试 |
| S3 | TSMC 20-F 现金流（IFRS 口径） | 20-F 结构、口径字段 | 调试 |
| S4 | 一家非科技美股 10-K 现金流（如工业或消费） | 跨行业 | 保留 |
| S5 | 任一公司 10-Q | 季度/累计期间混淆 | 保留 |
| S6 | S1 人为移除附注表后的版本 | 真实缺口，测漏缺口率 | 调试 |
| S7 | 含重述/重分类的年报（上年数据被 recast） | 重述标记 | 保留 |
| S8 | 单位为千元、财年非 12 月的报告 | 单位/期间 | 保留 |

每个样本 3–6 个冻结材料块，不送全文。调试集可反复看结果改契约；保留集只在契约冻结后跑，结果不回改契约。

### 5.2 契约与答案分离

- 公开给执行模型：schema、单位/期间/精度契约、缺口三分类、分母项目名单（但不含答案值）。
- 独立保留：答案值、缺口键、分母内每项状态。
- 答案制作：人工从原件读取，程序复算小计，两人交叉一次。6 个独立事实太少，第一轮目标每样本 15–25 个独立事实，总计约 150。

### 5.3 重复与停扩规则

- 每样本每任务 3 次重复（第一轮）。
- 扩充条件：调试集硬失败为 0、假缺口率 <10%，再跑保留集。
- 停下条件：保留集任一样本出现 ≥2 次硬失败 → 回到契约修订，不加样本。
- 稳定性承诺只在同一样本 ≥10 次后给出。

### 5.4 组件检查 vs 完整年报验收

组件检查答"这一批输入能否正确提取"；完整年报验收还要答"所有报表/章节都被分批覆盖、批次间重复事实已合并、重述已标记、总成本可接受"。后者的分母来自 T1 目录，不来自模型输出。第一轮只做组件检查，第二轮对 AMD 一份年报做完整验收。

### 5.5 裁判策略

| 情形 | 做法 |
|---|---|
| 数字、引用、schema、假缺口 | 程序判，不用裁判 |
| 文字说明、L2 文字支持 | 单裁判，输入仅"陈述 + 引用片段 + 答案键 + 精度契约"，预计每条 <1k token |
| 裁判结论与程序或自评冲突、保留集首次运行 | 双裁判（不同供应商） |
| 双裁判不一致、硬失败争议、新样本类型首次 | 人核 |

裁判评分规则在调用前冻结并写入 Trace。

## 6. 稳定性问题的最小修正实验

**现象**：数字对，缺口/解释错。
**假设 H**：失败主要由"至少两项 gaps"和未区分"会计桥接 vs 管理层归因"引起，而非推理预算不足。

### 6.1 实验设计（单变量）

| 项 | 对照组 | 实验组 |
|---|---|---|
| 配置 | 现有 Sonnet 固定配置 | 完全相同 |
| 提示 | 旧提示 | 删"至少两项 gaps"；加缺口三分类且允许为空；要求输出结构：①会计桥接（可计算项必须算）②管理层归因摘录（有则引用，无则标 `in_material_no_attribution`）③缺口 |
| 样本 | S1 + S6 | 同 |
| 重复 | 各 5 次 | 各 5 次 |
| 评分 | 预注册：硬失败、假缺口率、漏缺口率、桥接四行是否齐 | 同 |

### 6.2 验收例子（S1）

必须输出：净利润 -466、非现金调整 -229、营运资产负债变动 -1203、经营现金流 -1898，同比 -53.2%（契约声明一位小数，-53.24% 亦接受）；库存 +821 标为抵消项，应付账款 -1350 标为拖累；缺口只允许一条"无管理层逐项归因"。实验组目标：5/5 无硬失败，假缺口为 0。S6 目标：正确报出被移除附注，漏缺口率为 0。

### 6.3 潜在副作用

- 模型可能从桥接推断商业因果，违反边界 → 加硬失败项"桥接后出现未引用的因果语句"。
- 允许缺口为空后漏缺口率可能上升 → S6 专门监控。
- 输出变长，成本上升约 20%–40%。【假设】

若实验组仍有 ≥2 次硬失败，再测 effort/thinking 变量；不先调这些。

## 7. 实施顺序与费用算法

### 7.1 顺序

| 步骤 | 交付 | 验收 |
|---|---|---|
| 下一轮（约 2 周） | T2 契约 v1（含缺口分类、精度契约）；S1–S3、S6 答案键；第 6 节实验；candidate→accepted 规则草案 | 实验组通过 6.2；答案键经两人交叉；accepted 规则可在后台展示状态 |
| 第二步 | AMD 一份 10-K 的 T2 完整覆盖（分批、合并、分母核对）；T3 单语言精编 MVP | 覆盖率 ≥95% 且剩余项有分类；精编每章有段、数字回链率 100% |
| 第三步 | 保留集 S4、S5、S7、S8；T4 接入主流程；T5 与 Analysis 交接演练 | 保留集硬失败 ≤1/样本；T4 关系支持率 ≥90%；T5 一次完整补证闭环 |

### 7.2 成本公式

```
C_task = Σ_i (in_i·p_in + out_i·p_out + cache_i·p_cache)   # 所有调用含重试
       + C_judge  = Σ_j (in_j·p_in_j + out_j·p_out_j)
       + C_human  = 小时 × 时薪
       + C_waste  = 失败/截断调用的模型费用
单请求 = 单个 i 项；完整任务 = 上式；每事实成本 = C_task / 已采纳独立事实数
```

所有 p 取实际发送平台公布价，缓存按账单回填。

### 7.3 算例（全部为假设，非实测）

假设一份 10-K 正文约 120k token，分 30 批，每批输入 5k（含指令）、输出 1.5k：
- T2 模型费 = 150k×$2/M + 45k×$10/M = $0.30 + $0.45 = $0.75
- 重试 20% → $0.90
- T3 单语言：输入 150k、输出 10k → $0.40
- 裁判（Opus，只看陈述+片段）：约 40k 输入、5k 输出 → $0.16 + $0.10 = $0.26
- 人核 1 小时 × 假设 ¥300 ≈ $42
- 合计模型侧约 $1.6，人工占绝对多数。

结论：模型费用不是主要约束，减少人核时间（靠程序前置判定）才是；也因此"便宜模型预处理省钱"在当前量级上收益很小。
