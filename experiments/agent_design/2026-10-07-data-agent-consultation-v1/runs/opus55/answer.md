# Uteki Data Agent 设计意见（2026-10-07）

> 标注约定：**【事实】** 来自你们给出的背景；**【假设】** 是我的推断，尚未验证；**【建议】** 是可执行动作；**【待验证】** 需要新实验支持。

## 一、先下判断

### 1.1 当前最该解决的三个问题

| 优先级 | 问题 | 为什么现在最关键 |
|---|---|---|
| 1 | **缺口与可得性没有标准答案** | 【事实】数字 10/10 正确，但说明只通过 1/5。失败集中在“资料不足”“无法计算”这类声明。现有评估只校验数字和引用，无法判断“该说缺”与“不该说缺”。 |
| 2 | **财报精编、业务图没有可验收定义** | 【事实】双语要求、BOM/业务图都未定稿。没有覆盖清单，就没有分母，也就无法判断“全面”。这需要用户决定，不是工程能补齐的。 |
| 3 | **组件验收与完整年报交付之间断层** | 【事实】目前验证的都是“给定正确材料块”的情形。完整年报还涉及定位、分块覆盖、去重合并。现在这部分既无质量数据，也无费用数据。 |

### 1.2 可能想错的地方

| 现有认识 | 我的质疑 | 影响 |
|---|---|---|
| 同输入重复 5 次即可衡量稳定性 | 同输入重复只测采样方差。6 个独立事实太少，**换输入**比加重复更有信息量 | 应把预算从“重复”挪到“样本多样性” |
| 文字版本数 5/5 说明不稳定 | 文字不同是正常的。应比较**原子声明集合**是否等价 | 改用声明级比对作为稳定性指标 |
| 单个 Codex 盲评可作通过信号 | 【事实】曾因未声明的精度误判。裁判本身未经校准 | 裁判需先与人工标注对齐，才能算数 |
| 需要 Opus 做规划 | 【假设】T2 类任务的“计划”基本是确定性路由（读哪张表、哪一节），不需要大模型规划 | 现阶段不值得引入 Opus 规划 |
| 便宜模型预处理可降本 | 用模型压缩原文会丢失表头、单位、限定词。解析、索引应由程序完成 | 只在少数分类点试用便宜模型 |

### 1.3 Sonnet 执行 / Opus 规划 / Codex 评估：成立条件

| 角色 | 成立条件 | 现阶段结论 |
|---|---|---|
| Sonnet 执行 | 输入已由程序定位并带结构，任务契约明确 | **成立**，可立即用于 T2、T5 |
| Opus 规划 | 补证问题开放、需要跨章节决定搜索顺序，并且有实验证明 Opus 的检索覆盖更高 | **暂不引入**。可在 T5 上做一次小 A/B |
| Opus 难判 | 重述冲突、业务图中的推断边、裁判分歧 | 可作为**升级路径**，不作默认 |
| Codex 评估 | 只评声明级条目；对照人工答案；与人工的一致率达标 | 校准前**只作辅助**，不作最终判定 |

## 二、业务任务表

### 2.1 分类：产物、服务、基础能力

| 类别 | 任务 | 使用上的区别 |
|---|---|---|
| 产物型 | T2 结构化事实、T3 精编、T4 业务图 | 按“公司×报告期”交付，有固定覆盖清单，验收一次后发布 |
| 服务型 | T5 按问题补证 | 由 Analysis 请求触发，按单个请求验收，没有固定清单 |
| 基础能力 | T1 材料登记、T6 更新与重述对账 | 不直接面向研究者；以召回率和一致性衡量，不打“质量分” |

### 2.2 任务定义

| 任务 | 触发 | 必填输入 | 最小输出 | 完成标准 | 缺口表示 | 边界 |
|---|---|---|---|---|---|---|
| T1 材料登记 | 新公司/新期间/refresh | 发行人标识、报告类型、期间 | 来源清单（哈希、版本）、章节与表格索引 | 必需章节已定位，或标记 `section_not_found` 并附检索记录 | 章节缺失、版本冲突 | 纯 Data，不调用 LLM 为默认 |
| T2 结构化事实 | T1 完成或下游请求 | 材料版本、**事实范围**（报表/附注清单） | 原口径标签、规范值、期间、单位、量级、引用 | 范围内覆盖率与准确率达标（见第四节） | 用 §2.3 的缺口类型 | Data；只做公式计算，标 `computed` |
| T3 财报精编 | T2 已核验 | 材料版本、核验事实快照、章节清单 | 分章节浓缩，保留关键表格，逐句引用 | 每个数字来自 T2；清单内章节全覆盖 | `section_omitted` 并说明原因 | Data；只摘录管理层解释，不写判断 |
| T4 业务图 | T2 已核验 | 材料版本、节点/边类型清单 | 节点（分部、产品、客户集中度、供应依赖、地域），边与引用 | 每条边有支持性引用；推断边单独标记或不出现 | `relation_not_disclosed` | Data 只画披露关系；推断归 Analysis |
| T5 按问题补证 | Analysis 请求 | 问题、公司期间、所需证据类型 | 证据包：找到/部分/未找到，附可计算项 | 回答问题，或给出**负向检索记录** | 同 §2.3 | Data 取证；Analysis 下结论 |
| T6 更新/重述对账 | 新文件、重述、分部重编 | 新旧快照 | 差异清单：新增、重述、口径变更 | 旧快照不改动；重述关系可追溯 | `restated` 及 `superseded_by` | Data |

**通用性提醒。** 事实范围应**从文件本身派生**：先保留原口径科目，再映射到规范层。不能把 AMD 的科目当默认模板。20-F 涉及 IFRS、非美元币种、不同的列报顺序，映射层必须允许 `unmapped`。

### 2.3 缺口类型（核心修正点）

| 类型 | 含义 | 必附证据 |
|---|---|---|
| `computable` | 未直接披露，但能从披露数据计算 | 公式与输入事实 ID |
| `no_mgmt_attribution` | 管理层没有逐项归因 | 已检索的章节 ID |
| `not_in_provided_scope` | 本次材料范围内没有 | 范围说明 |
| `not_disclosed` | 全文检索后仍没有 | 检索章节清单 |
| `conflict` | 来源之间矛盾 | 双方引用 |

已观察到的错误，正是把 `no_mgmt_attribution` 说成了“无法计算”。分类之后，这类错误可以用程序直接拦截。

### 2.4 需要用户决定的事项

- 精编的读者是谁、要支撑什么决策。这决定章节清单和长度上限。
- 双语是必须的，还是“中文主版本 + 英文按需生成”。【假设】双语会使输出 token 增加约 60–100%，还需要额外做一致性校验。
- 业务图的节点与边类型清单，以及是否允许“推断边”出现在 Data 层。

## 三、function / skill / agent：以 T5 为例

示例任务：Analysis 请求“AMD FY2023 经营现金流同比下降的构成与管理层解释”。

| 层 | 内容 | 由谁执行 |
|---|---|---|
| function（确定性） | 定位现金流量表；解析科目行；计算两年差额与同比（-1898，-53.24%）；单位与量级检查；引用解析；校验“缺口声明是否与可得性索引矛盾” | 程序 |
| skill（可复用操作说明） | 《现金流同比说明》：①先给会计桥接（程序结果）；②再到 MD&A 查找管理层归因；③每个驱动项标注“披露归因”或“计算贡献”；④区分余额变化、当期现金流作用和同比差额 | 写成提示与清单，Sonnet 执行 |
| agent（模型选下一步） | 所给块中没有 MD&A 归因时，决定是否请求更多章节；遇到科目映射不清时，决定是否标为 `conflict` | Sonnet；仅在开放问题上考虑测试 Opus |
| 验收 | 数字复算、引用存在、缺口类型合法（程序）；“引用是否支持陈述”（裁判抽检）；新缺口类型首次出现时必须人核 | 程序 + 裁判 + 人 |

**原则：** 能由函数完成的，就不交给模型。模型只负责语言组织和有限的检索决策。

## 四、质量标准

### 4.1 三层分离

| 层 | 检查内容 | 方法 |
|---|---|---|
| L1 可定位 | 引用 ID 存在，片段可回读 | 程序，100% 覆盖 |
| L2 真支持 | 被引片段确实支持该陈述（含期间、单位、限定词） | 数字由程序检查；文字由裁判逐条判断，人工抽检 |
| L3 覆盖 | 覆盖清单中的条目都已交付，或给出合法缺口 | 对照人工标注的分母 |

### 4.2 各产物的硬性失败（任一出现即不通过）

| 产物 | 硬性失败 |
|---|---|
| T2 | 数值、符号、期间、单位或量级错误；把计算值标为披露值；引用到其他公司或其他期间 |
| T3 | 出现不在 T2 中的数字；把模型判断写成管理层表述；中英文版本数字或结论不一致 |
| T4 | 无引用的边；推断边未标记；节点来自其他公司 |
| T5 | 虚假缺口（材料中有却声称没有）；漏报缺口；无负向检索记录就声称 `not_disclosed` |

### 4.3 少量可解释指标

- 事实准确率 = 正确事实数 / 交付事实数
- 覆盖召回 = 已交付或合法缺口的条目数 / 分母条目数
- 无支持陈述率 = L2 未通过的声明数 / 声明总数
- 缺口判断正确率（见 4.4）
- 声明集合稳定性：重复运行中，核心声明集合一致的比例

**不用于评分的信号：** 长度、措辞、两个模型是否一致。多余的无支持陈述按条扣分，因此写得越长并不会得分越高。

### 4.4 缺口判断正确性的检查办法

1. 人工为每个样本的分母条目标注可得性：`table` / `text` / `computable` / `absent_in_scope` / `absent_in_filing`。
2. 把模型的每条缺口声明映射到条目，与标注比对。
3. 程序自动拦截两类错误：缺口声明所指的条目在表格索引中存在行；声称 `not_disclosed`，但检索记录未覆盖必检章节。
4. 必须设置**陷阱题**：故意删除关键表格，检验模型是否会如实报告缺口。只有这样才能防止修正过头、反而不报缺口。

## 五、最小 benchmark

### 5.1 样本组成（第一轮）

| 文件 | 用途 | 覆盖的难点 |
|---|---|---|
| AMD 10-K FY2023 | 调试集 | 已有材料，现金流桥接 |
| TSMC 20-F | 保留集 | 20-F 章节、IFRS、非美元币种 |
| 另一家美国公司的 10-Q | 保留集 | 季度与年初至今期间混淆 |
| 一份含重述或分部重编的文件 | 保留集 | `conflict` / `restated` |

每份文件 5 个条目：报表提取、附注提取、变动说明、缺口陷阱、补证请求。总计约 20 个条目。T3、T4 第一轮只在 2 份文件上各试 1 个章节或小范围，用于检验定义是否可操作，不作正式评分。

### 5.2 契约与答案的分离

- **公开给执行模型：** 任务契约、缺口类型表、输出 schema、精度规则（例如百分比保留一位小数，并写在题面上）。
- **独立保留：** 事实答案、分母清单、可得性标注、陷阱位置。
- 保留集不得用于调整提示词。每次修改提示后只跑调试集；进入阶段验收时才跑保留集。

### 5.3 重复次数与停止/扩充条件

- 保留集每条目跑 3 次。
- **停止条件：** 同一条目同一类硬性失败出现 ≥2/3，暂停修复。
- **扩充条件：** 保留集零硬性失败，且缺口正确率 ≥95%。此后再增加 3–4 份不同行业的文件。

### 5.4 组件检查与交付验收的差别

- **组件检查**：给定正确材料块，只测模型。
- **交付验收**：从完整文件开始，测定位、覆盖、合并的全链路，并记录端到端费用与耗时。

组件通过后，至少在 1 份 10-K 和 1 份 20-F 上做一次 T2 交付验收。

### 5.5 裁判降本与分级

- **减少输入：** 裁判只接收“原子声明 + 被引片段 + 对应答案条目”，不接收整份年报。数字一律由程序检查。
- **单裁判：** 用于常规 L2 判断。
- **双裁判：** 用于单裁判与程序结论冲突、缺口声明、管理层解释的转述，以及保留集最终判定。
- **必须人核：** 建立答案；裁决裁判分歧；早期对裁判通过项抽检约 20%；新任务类型首次出现；重述关系；业务图推断边。
- **裁判校准：** 与人工一致率 ≥90% 后，才可降低人工抽检比例。

## 六、稳定性问题的最小修正实验

**现象：** 数字对，但缺口声明或解释错。

| 版本 | 改动 |
|---|---|
| v1 | 现提示（要求至少两项 gaps） |
| v2 | 取消最低数量；引入 §2.3 缺口类型；每条缺口必须附证据 |
| v3 | v2 + 程序预先计算会计桥接放入输入，模型只做解释与分类 |

- **样本：** AMD 现金流（有表、无管理层逐项归因）、一条有管理层归因的保留条目、一条删掉明细表的陷阱条目。
- **规模：** 每版每条目 5 次，共 45 次。按已观察的单次约 $0.02–0.03 估算，执行费约 $1–1.5（【假设】）。

**验收例子。**

- **通过：** “经营现金流 1667，同比 -1898（-53.24%）。会计构成：净利润 -466，非现金调整 -229，营运项目 -1203。库存项目同比 +821 为抵消因素，应付账款同比 -1350 为拖累。所给材料中管理层未逐项归因（已检索：章节 X、Y）。”
- **失败：** “无法计算各项贡献”；“库存减少 821”（把同比差额说成余额变化）；把会计桥接表述为商业因果。

**判定标准：** 虚假缺口为 0；陷阱条目上真实缺口召回 100%；数字正确率不下降。

**潜在副作用：**
- 模型可能少报真实缺口，用陷阱题监控。
- 程序给出的桥接可能被模型当作管理层解释，应检查归因标签。
- v3 增加的输入 token，需要计入成本。

**注意：** 提高 thinking 或换用更贵的模型，不是本实验的变量。只有 v2、v3 都失败时，才考虑测试 Opus。

## 七、实施顺序与费用

### 7.1 下一轮最小交付

**内容：**
- T2、T5 契约及缺口类型
- 4 份文件的答案与分母
- §6 修正实验
- 裁判校准（约 50 条声明的人工标注）

**验收：**
- 保留集零硬性失败
- 缺口正确率 ≥95%
- 裁判与人工一致率 ≥90%
- 每次调用的配置切面完整（未发送的参数记录为“未发送”）

### 7.2 后续两步

1. **T2 交付验收：** 在 1 份 10-K 和 1 份 20-F 上从完整文件开始，测覆盖召回和端到端成本。
2. **T3、T4 试点：** 用户确定定义后，每个产物 2 家公司、各 1 个章节；同时测双语一致性及其增量成本。

### 7.3 费用公式

```
C_交付 = Σ调用[(未缓存输入×p_in + 缓存读×p_cr + 缓存写×p_cw + 输出×p_out)]
         ×(执行 + 重试 + 修复 + 规划)
       + C_裁判 + 人工小时×时薪 + 失败浪费
单位成本 = C_交付 / 通过验收的产物数
```

### 7.4 算例（全部为假设，非实测）

场景：完整 10-K 三张主表提取。

| 项 | 计算 | 金额 |
|---|---|---|
| Sonnet 执行 | 8 片 × 30k 输入、3k 输出 → 240k×$2/M + 24k×$10/M | $0.72 |
| 重试与修复 | +20% | $0.14 |
| Opus 单裁判 | 40k×$4/M + 8k×$20/M | $0.32 |
| 双裁判时加 Fable | 40k×$11/M + 8k×$55/M | +$0.88 |
| 人工复核 | 1 小时 | 按时薪 |

**结论：** 模型费用约 $1–2，人工远高于此。因此**减少人工裁决次数**，比压低模型单价更值得优化。

## 八、立即可做与需实验支持

**立即可做：**
- 采用缺口类型表
- 取消“至少两项 gaps”的要求
- 把精度规则写进题面
- 裁判只接收声明级输入
- 拆分调试集与保留集
- 解析与索引交由程序完成

**需要新实验支持：**
- v2/v3 哪个版本有效
- Opus 规划是否提高检索覆盖
- 便宜模型能否用于 20-F 章节分类（需召回率 ≥99% 才可用）
- 双语的增量成本
- 裁判能否降低人工抽检比例

## 九、背景尚不能回答、但会改变方案的问题

1. 精编和业务图的**主要读者与决策场景**是什么？是否必须双语？这决定覆盖清单和成本。
2. **目标公司范围**是什么：仅美国申报人，还是大量外国发行人、特定行业？这决定 20-F/IFRS 的优先级和映射层投入。
3. 每家公司可接受的**人工复核时长**是多少？哪类错误对用户是致命的？这决定裁判分级和发布门槛。
