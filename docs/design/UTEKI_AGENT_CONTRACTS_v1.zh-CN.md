# Uteki Agent 任务与交付契约 v1

- 日期：2026-09-29；状态：设计稿，供实现与交互稿共同引用。
- 已确认：共享数据、独立研究与 Manager 判断；重要规划和推理使用高能力模型，限定子任务按质量选择性价比模型。
- 用户明确核心交付是报告，尽量减少用户与 Agent 的交互。下文任务、补数与审阅在内部协作完成；正式报告须独立交代核心判断、依据、反证与未知，不能依赖用户逐轮追问才完成交付。
- 2026-09-30 已确认：正式报告交付中文、英文两份完整正文，英文是面向中美及更多国家用户的必要交付。两种语言表达同一研究版本的判断，均须独立可读并通过语言间一致性核验。
- 本文的任务封套、模型档位绑定、审阅发布策略是首版建议；不会因写入文档就成为现有运行能力。
- 范围：Data、Analysis、Manager 及独立内容审阅的交接；不新增调度平台，不扩大公司池，不触发模型调用。
- 2026-09-30 当前主线：巩固上述角色的能力、实现与功能 E2E。Figma 因 MCP 额度限制部分完成并暂缓，交互稿完成不作为当前功能验收前置；优先级及验收边界见[设计入口](README.md)。

## 1. 首版技术选择

| 议题 | 建议默认 | 何时才升级 |
| --- | --- | --- |
| Agent 数量 | 按数据、研究、决策三类责任组织；解析、查询、计算、账户核算使用确定性工具 | 独立上下文、权限或可并行任务带来可测收益时，再增加执行角色 |
| Data 组织 | 一个 Planner 持有任务责任，按需调用一个有界 Worker；保留不委派的基线 | 同输入、同验收下，委派减少遗漏或延迟且额外成本可接受 |
| Analysis 组织 | 一个研究作者，关键候选进入独立审阅；业务、财务、行业、估值先作为任务类型 | 专项任务有独立输入产出、可单独评测，且单作者出现明确瓶颈 |
| Manager | 方法与案例的持续责任主体；复用 Analysis 和共享行业研究 | 两种方法均有可追溯案例后，再扩展更多风格或公司 |
| 运行方式 | 显式计划约束目标，ReAct 选择下一步工具，Skill 提供方法 | 不因一次失败增加一层 Agent；先查输入、接口、工作状态和完成条件 |
| 模型选择 | 已确认现阶段按环节固定模型配置；缺配置拒绝执行，不自动选模或静默换模 | 工程修改并验证显式配置后用于新运行；同一 Manager 的模型对照分别冻结实验配置 |

多 Agent 不是质量保证。增加角色会增加交接、重复读取和收尾成本；首版先把一次交付做完整，再比较协作组织。

## 2. 公共任务封套与稳定交接

以下是建议的共同语义字段，不是已经可直接提交给所有现有入口的统一 JSON Schema。

| 字段组 | 必须表达的内容 |
| --- | --- |
| 身份 | task_id、任务版本、父任务、业务角色、目标问题；重试关联原任务，不覆盖原记录 |
| 范围 | 公司/证券/行业身份、期间、来源政策、公开信息截止、数据快照、候选/采纳政策 |
| 研究上下文 | Manager 与方法版本、案例/行业档案版本；纯数据任务可不带 Manager |
| 输入引用 | artifact/bundle/source/index 的身份、哈希、版本和访问入口；不复制整个会话 |
| 完成条件 | 必须回答的问题、证据与计算要求、允许的未知、哪些缺口使本任务只能部分交付 |
| 执行配置 | skill 版本与哈希、模型配置、工具权限、超时、决策/请求限额及预算政策 |
| 返回封套 | 产物引用、程序检查、内容审阅、未解决问题、执行状态、后续请求和成本 |

稳定获取依赖明确身份与版本，不依赖“最近一次输出”、某个固定本地文件名或模型记住整段历史。
原件、来源版本、原文定位与公开时点由数据层维护；读取接口可以返回原文，不要求先把全文转成指标。
每轮上下文应保留当前计划、已有候选回答、关键引用、待阅读入口、未解决问题和已发生的委派。
超过上下文容量时提供精确 artifact 指针和遗漏说明；保存到磁盘、搜到块、Worker 读过均不代表当前角色已读。
内容相同且处理版本兼容时复用已有产物；来源或处理逻辑变化创建新版本，不覆盖旧快照。

## 3. Data Agent 任务卡

| 项目 | 契约 |
| --- | --- |
| 触发 | 首次研究、新披露/更正、Analysis 的缺失数据请求，或明确要求复核一项记录 |
| scope 输入 | 问题、公司与期间、来源政策、截止和候选政策；当前 CompanyQueryInput 三选一：dataset + scope、prepared_run、company_config |
| 稳定获取 | 经校验的目录、scoped query、原文与 artifact 接口；准备入口获取并冻结原件，查询冻结 dataset 时不假装能任意扩源 |
| 过程方式 | Planner 建立可检查要求；ReAct 调用查询/阅读；必要时限定 Worker；公式计算交给注册的确定性工具 |
| 产物 | 候选指标/来源陈述、原文上下文、确定性计算、带逐条引文的候选回答、覆盖与缺口、不可变证据包 |
| review | 程序核对 scope、期间、单位兼容、引用和真实正文交付；内容审阅再核对解释、完整分类与限定条件 |
| 迭代/退出 | 可纠正的接口错误按反馈修正；信息不足返回具体请求/未知；重复无进展、超时或额度耗尽封存已有结果 |

Data 回答“资料说了什么”，不决定 thesis、风险重要性、合理价格或买卖动作。
来源中实际披露的数字、管理层指引、归属明确的说法必须分类型；管理层说过某事不证明该预测会实现。
当前 ResearchRecord 支持 actual / management_guidance / attributed_statement，记录仍为 candidate。
当前 source_evidence 只要求原文交付；叙述问题使用 source_answer，不能用任意同源段落代替回答。
source_answer 的 statement、temporal_basis、period_context 与逐条精确引文形成候选回答；引用检查通过不证明语义正确。
现状：准备、查询、实际阅读、受限委派与封存已有；六轮真实题仍未通过完整用途分类和稳定收尾验收。
新增 source_answer 已通过离线合成检查，并在本次限定资本支出用途题获得真实模型内容核验；业务地图及各来源提取覆盖需分别核查，不能从单题推广。

人工验收以[实际产物样本](data-agent-acceptance/README.zh-CN.md)为入口：先看材料变成哪些块、哪些数字/叙述记录，再查看执行与核验。当前冻结库中这份 10-K 的 111 条数值候选来自确定性 XBRL 映射，只覆盖五类有记录指标；现金、债务、股本等核心包内容未补齐。本次模型交付为 4 条既有记录的核对及 3 条新叙述 claim，没有执行整份 10-K Direct Extraction。按 10-K／10-Q／8-K 配置版本化提取清单及统一可读交付仍是待落实的方法规范，不是当前专属 prompt 已运行的声明。
单独 coordinator.query 仍在 source_answer 产出后封存。新增实验入口 [run_data_handoff.py](../../scripts/run_data_handoff.py) 将 query、独立 Data 内容核验及限定 Analysis 消费串联；[answer_handoff](../../src/uteki/agents/data_query/answer_handoff.py) 绑定来源/答案版本、核对数值记录、校验审阅结果，并在下游调用前阻止未核验或不完整输入。2026-09-30 已完成限定真实任务：Data 的 7 条事实/6 项要求通过内容核验，Analysis 生成候选；首轮核验容量配置失败后，续跑通过外部固定 query manifest 哈希复用原结果。Analysis 对任务核验与全局采纳状态的理解仍有偏差，不能宣称完整报告或稳定研究质量通过。见[实际结果及缺口](../../experiments/architecture_baseline/2026-09-30-data-handoff-v1/README.md)。
2026-09-30 补充核对：现有 [Record Review](../../src/uteki/agents/data_query/record_review.py) 与 [Semantic Review](../../src/uteki/agents/data_query/semantic_review.py) 主要接收选定记录/packet，尚未覆盖叙述性 source_answer 的完整性审阅。独立评审实验不能当作 query 输出已通过核验；接入时须验证输入与输出语义，而非只增加一次 Reviewer 调用。Direct Extractor 已有独立入口，但在本次检查的 experiments 与 data/company_workspace 中未定位该新版入口的真实封存 run，其效果验收仍保留缺口。

### 新关注公司的基础资料准备：2026-09-30 问答规则

- 已确认采用持续维护基础资料、研究缺口按需补采的机制。基础材料包括年报、季报、重大公告和公司实际公开提供的业绩新闻稿、演示材料、电话会文字或录音；具体来源按选定公司、期间和信息截止核对，历史日行情按下述已确认范围准备。
- 已确认核心材料门槛：约定历史窗口及公开信息截止内、公司实际已公开的年季报、重大公告、官方业绩新闻稿必须达到可研究状态。演示材料、电话会等补充材料存在缺口时，须有可核验依据并经研究审阅确认不影响核心判断，才可注明缺口后发布；无法排除核心影响时须补齐。电话会可使用可研究的文字或录音，不默认两种载体都必需。
- 采集和内部研究可并行；对外首份报告仍须等待必需资料就绪、核心研究及审阅完成。研究调用使用明确的可用资料版本，新资料不覆盖已冻结的运行输入。
- 资料就绪需核验获取、公司/期间/来源/披露时间、版本、可读性和约定覆盖。正文、表格或选用录音的内容须具备可供研究的读取方式；保存了文件不等于可用，不宣称当前已实现全部媒体处理能力。
- 关键材料缺失不能标为就绪。已公开但获取失败、解析失败、确无公开材料、实际历史不足分别表达；不能用“未公开”掩盖获取失败，也不靠修改范围消除缺口。
- Data 记录材料覆盖、获取及解析状态；补充材料缺失对投资判断的影响由研究侧说明、经独立审阅检查，不由 Data 或抓取失败本身推断。允许带已审阅的非核心缺口发布，不等于全部资料齐备；发布依据与缺口保持可追溯。
- 已确认首版历史准备范围为最近 5 个完整财年 + 最近 8 个季度；更早重要历史按研究需要补充。接入配置须显式选择这一政策，并依据目标公司的财年、信息截止和实际公开情况展开期间及来源清单；不把已确认政策硬编码成共享入口的隐式业务默认。只使用明确截止时已公开材料；设计确认不代表采集已运行。
- 已确认实际公开历史不足时仍可研究，报告说明覆盖及影响；这项例外不免除在实际范围内取得必需材料和完成核心研究的要求。
- 已确认保留原始资料及索引，提前整理核心财务包：营收、利润、经营现金流、资本支出、现金、债务、股本等，附期间、口径和原文。具体指标定义、单位和计算规则写入显式契约；其余财务行项及专题证据按研究需要补充，不要求首次接入就全文结构化。
- 已确认提前准备覆盖所选研究窗口的历史每日价格、成交量及拆股、分红记录，供两类 Manager 使用。证券/股类、交易日期与时点、币种、价格类型、复权口径、来源和版本明确；公司行动保留公开及生效时点等可核验信息，不用后续事件或未来数据回填历史决策。实际覆盖不足、交易中断与获取失败分别记录，具体字段和供应源由工程核对。
- 已确认可按研究问题获取名单外竞争对手、供应商、客户等公司的公开资料；每份资料保持真实主体、期间、来源和信息截止，说明对目标公司问题的用途。相关公司资料不能替代目标公司的披露覆盖，核验后按既定共享规则复用；按需引用不触发持续研究名单或投资名单扩容。
- 已确认按需取得的新事实和原文经过数据核验后供所有 Manager 复用；各 Manager 独立保存观点和采纳决定。共享不覆盖已冻结输入，按公司、期间、来源政策及信息截止选择版本；来源更正保留历史。管理层说法的核验只证明出处及披露内容，不证明预测成立。
- 已确认数据采用分层核验：全部结构化数据做程序检查；模型提取、口径转换以及影响核心判断的数据增加内容核验，通过适用检查后才供正式分析使用。未通过或未完成核验的记录保持候选或缺口状态。后续研究若将某条数据用于核心判断，需检查并补齐对应内容核验，不能只依赖最初的检查等级。

上述是目标准备契约，尚未宣称全材料持续采集、核心财务包、共享回补、分层核验、历史覆盖或 ready 发布检查已经接通。资料准备不等于全文结构化、Data 内容核验或投资分析完成；数据核验与 Reviewer 对研究报告的独立初判分别执行，不能互相替代。

## 4. Analysis Agent 任务卡

| 项目 | 契约 |
| --- | --- |
| 触发 | Manager 提出研究问题、新证据影响现有判断、观察条件到期，或行业观点变化 |
| scope 输入 | 明确公司或行业、研究问题、方法及期限、固定证据包、截止、既有案例/行业版本与验收要求 |
| 稳定获取 | 经研究数据接口读取指标与原文上下文；资料不足返回 ResearchDataRequest，不绕开接口解析原始 SEC 文件 |
| 过程方式 | 高能力模型规划与综合；将业务机制、财务勾稽、估值、反证拆为有界任务，先验证是否需要多个执行角色 |
| 产物 | 同一研究版本的中文、英文完整报告候选及其结构化内容：业务、thesis、因果机制、因素与风险、正反证据、经营/估值假设及计算、未知、观察需求和版本差异；标识报告语种并保留原文引用 |
| review | 程序复算并检查引用；独立审阅检查因果跳跃、遗漏反证、假设一致性和结论强度；两种语言核验数字、判断、证据、风险和限定条件一致；作者逐项处理意见 |
| 迭代/退出 | 缺事实退回 Data；有证据但解释分歧保留分歧；关键条件不可判断时交付有限结论，不填造价格或回报率 |

共享行业研究是 Analysis 的一种任务范围，维护独立行业档案与观点作者；公司研究引用版本并说明业务传导。
外部机构研报对照属于观点比较：标明机构、时点、假设与证据；不能把“机构认为”升级为已验证事实。
已确认有可用机构研报就完成对照；没有时记录对照覆盖缺口，自身核心研究、必需资料及审阅完成后仍可发布。外部报告的可得性不替代自身研究完整性要求，也不改变 Reviewer 先独立初判后看作者报告的既定流程。
Analysis 提出观察需求；持续追踪与复核能力维护观察计划，案例和行业档案引用其版本。
双语报告对应同一 Manager、方法、案例和信息截止；不以另一种语言重新生成一套投资判断。语言转换不替代研究审阅，也不改变来源的语言/地区/版本身份。中文、英文都完整且一致才满足双语交付；具体生成顺序和执行角色由工程验证，不因双语要求自动增加独立 Agent。
现状：已有 narrative 与 analyst → reviewer → revision 实验路径；跨材料持续案例、完整行业档案和统一数据交接尚未接成闭环。
旧路径存在 ToolSession 直接读文档，目标接口收敛仍未全面完成。新增 [data_consumer](../../src/uteki/agents/analysis/data_consumer.py) 仅接收通过指定内容核验且哈希固定的交接；解释引用事实 ID，由宿主还原原文引用。输出仍是待内容审阅的内部限定候选，不生成完整公司报告、当前买卖判断或发布状态；注册计算结果的交接尚未支持。

## 5. Manager 任务卡

| 项目 | 契约 |
| --- | --- |
| 触发 | 初建案例、重要研究更新、价格/风险条件触发、持有期限到期或日频复核 |
| scope 输入 | 稳定 Manager 身份、方法版本、公司池、投资期限、案例版本、行情时点、组合/现金快照及投资约束 |
| 稳定获取 | 读取共享来源、指定研究版本与确定性账户快照；分别保存自身假设、采纳理由和决策历史 |
| 过程方式 | 提出问题、安排研究、处理重要质疑，比较持有/调整/退出/现金；保持长期价值与阶段性进攻的方法差异 |
| 产物 | 独立公司投资案例、研究采纳/不采纳理由、目标比例与现金安排、动作条件和退出理由、下一次复核条件 |
| review | 重要判断接受独立反证；组合业务校验只做多、无杠杆及显式方法约束，账户代码记录模拟执行 |
| 迭代/退出 | 依据新证据修订案例；缺行情/关键研究时表达等待或有限判断；实质方法升级形成新实验版本 |

Manager 对最终投资判断负责；它不是 Data Planner 的另一个名字，也不直接改写事实、成交、余额和净值。
Manager 可以自主保持现金和有依据地集中持仓；共享风险线索不强迫各 Manager 得出同一结论。
方法内自主运行沿用既定授权；实质方法升级仍按已确认约定，由用户确认新方法版本生效。
已确认持续研究名单扩容需用户确认：Manager 可提出候选与理由，确认后才加入并持续维护；名单内的正常研究仍自主运行。研究名单不等于可投资名单，面向中美及更多国家的双语交付不自动扩大证券或市场范围。已确认允许按需引用名单外公司的公开资料；这项取证权限不等于持续跟踪该公司或将其加入可投资名单。
已确认每位 Manager 独立 100,000 美元、各自准备好后启动，不追加或提取；用户只看到比例及归一化表现。执行层按已确认规则，以纽约时间 20:00 冻结信息、下一正常交易时段开盘前 30 分钟封存订单，并在取得真实开盘行情且校验通过后记录模拟成交；Manager 的提案不是成交凭证。SPY 主对照与 QQQ 补充对照分别匹配每位 Manager 的起点。具体决策依据与待验证执行细节见 [S01～S08](README.md)；本轮未创建或启动账户。
已确认模拟核算采用单边成交额 0.10% 的合并成本、EFFR 现金计息参考及统一税前口径；0%／0.25% 交易成本情景和零现金利息对照单列。Manager 与配套 ETF 沿用同一核算政策，账本输出实际采用的成本、利率来源/时点、计算版本及未建模税负说明。敏感性结果不覆盖主账本，也不能由 Manager 自行选择更有利的假设替换正式结果；这些规则的确定性计算仍须工程验证。
已确认 16B、17A：支持碎股主动订单，只允许使用已结算且未被其他订单或买入付款义务占用的可用资金。卖出净款先记录为待结算应收，确认结算后才能复用；原有独立可用现金仍可使用。执行代码依据显式证券支持范围、数量步长、金额舍入及预留规则校验，不由 Manager 临时调整精度或忽略成本。Manager 与 ETF 对照采用同一数量和资金政策；公司行动权益单独保留，不能按主动订单精度直接截掉。规则与合成验收例见[设计入口](README.md)，不代表碎股账本已实现。

## 6. 独立内容审阅任务卡

| 项目 | 契约 |
| --- | --- |
| 触发 | 首次发布或实质变化完整审阅；局部数据/引用/文字修正检查修改及其影响，必要时扩审；重要新证据涉及核心判断时不能以结论未变免审 |

| 过程方式 | 完整审阅先独立检查核心问题，再对照报告寻找错项、漏项和替代解释；必要时调用 Data。局部修正按影响限定检查，不默认重写整份报告 |

| review 与退出 | 引用及范围也接受程序检查；审阅失败或重要质量缺陷未处理时保留候选或部分状态，不冒充通过；预测/风险取舍分歧经 Manager 回应后可保留，不要求 Reviewer 同意投资结论 |

独立审阅指任务与上下文独立，不保证模型错误独立；首版可以同模型不同上下文，异构模型是否改善结果由对照验证。
作者自检成本较低，适合提交前纠错；独立审阅能重新取证并挑战问题覆盖，两者不能互相冒名。

## 7. Skill、Plan、ReAct 与 Multi-agent 的关系

| 机制 | 解决的问题 | 首版用途 |
| --- | --- | --- |
| Skill | 这类工作应该怎样做、用什么工具、交付什么 | 版本化取证、计算与审阅方法；不是执行者或模型路由器 |
| Plan | 本任务要解决什么、顺序/依赖及何时结束 | 显式要求、待办、完成条件与修订理由，防止循环取证偏离问题 |
| ReAct | 看到当前工具结果后下一步做什么 | 在允许工具和固定 scope 内逐步决策，工具结果进入下一轮工作状态 |
| Multi-agent | 哪些任务交给独立执行者或审阅者 | 有界子任务和独立审阅；每个角色可同时使用 Skill、Plan 和 ReAct |

推荐组合是“计划限定目标 + Skill 提供方法 + ReAct 执行 + 必要的独立审阅”，不是四选一。
固定解析、查询、计算流程无需为了使用 ReAct 改成模型调用；简单任务无需先召开 Agent 团队。
是否增加角色看同题质量、遗漏、总成本、延迟与失败归属；不能拿更大的团队预算证明组织方式更优。

## 8. 固定模型配置：当前能力与建议增量

当前 coordinator 显式接收 model_config 与 worker_model_config，创建 planner/worker；Provider、model、reasoning_effort、超时和预算由运行配置控制。
当前 Skill 文本及哈希随运行记录固定，但 Skill 中写“用某模型”不会切换 SDK 模型；skill 指定模型的自动路由尚未实现。
已确认现阶段采用固定配置：工程在运行前为各环节指定明确的 provider、model 和关键推理参数；运行中不得自主选择、升级或降级模型。不同环节可以使用不同模型，同一 Manager 的多模型比较分别建立并冻结实验配置；当前仍先跑通 DeepSeek，不将 SOTA 当作可解析的模型名称。
建议增量只做静态配置解析：工程预先声明 task/role/skill 与 model_profile 的绑定，runtime 校验并解析为现有配置。按 role 的默认绑定及特定 task + role + skill 的覆盖规则须在运行前明确；冲突、缺失或未知配置拒绝，Skill 自然语言和业务 prompt 不能改写绑定。这是配置解析方案，不是让 Agent 动态选模。
规划、研究综合与重要审阅使用高能力配置、限定查找/摘录使用合适的经济配置仍是质量选型方向，具体型号由对应任务评测决定。出现复杂口径冲突时可交回规划角色重新规划或审阅，但该角色也继续使用已固定配置；现有配置无法完成时记录缺口，由工程另建配置并验证后新开运行，不自动升级模型。
所有角色沿用原任务的运行限制与计费记录。更换模型配置由工程显式修改并验证，历史记录不变；涉及投资方法实质变更时仍须遵循既定的新方法确认规则。
本轮沿用用户无金额上限的授权：budget_policy=record_only、budget_usd=null；本文不增加花费硬上限。步骤、超时、请求次数及无进展条件控制运行是否有界，与金额政策分别配置，不能互相混称。

**下面仅为未实现、不可运行的配置示意；不是现有 CompanyQueryInput 或 CLI 可接受格式。**

```yaml
schema: proposed-fixed-model-bindings-v1
selection_mode: fixed_before_run
role_defaults:
  data_planner: reasoning_high
  evidence_worker: evidence_economy
  content_reviewer: reasoning_high
bindings:
  - task_type: annual_capital_investment
    role: evidence_worker
    skill: source_narrative@v1
    model_profile: evidence_economy
profiles:
  reasoning_high: <显式 provider/model/reasoning/timeout 配置引用>
  evidence_economy: <显式 provider/model/reasoning/timeout 配置引用>
```

解析后冻结实际 model、provider、参数、角色 prompt、Skill 哈希、工具/代码版本及选择理由；业务 prompt 不隐式改模型。
工程验证后以新模型配置开始的运行可以复用已获原件和合法引用，但新角色需有自己的可验证读取；换模型不能消除来源缺失或把候选变成已采纳。

### 技术修复生效规则

已确认：不改变投资方法、风险政策、质量标准及固定模型配置的技术修复，验证通过后自动用于新任务；保存代码/工具版本、适用配置、验证记录及回退入口，历史运行、原件和冻结产物不改写。模型接口兼容修复可适用该规则，但模型名称、provider 或关键推理配置切换必须按上述固定配置政策处理，不能伪装成兼容修复自动生效。实质方法变更仍按既定政策验证并由用户确认。

以上是设计权限，不代表现有系统已具备自动验证、更新与回退能力，也不触发本轮模型调用或部署。

## 9. Review、评测、发布与有界迭代

| 层次 | 负责检查 | 不能代替 |
| --- | --- | --- |
| 程序检查 | Schema、范围、来源哈希、真实正文交付、引文、公式、预算及版本一致性 | 引文是否支持推断、问题是否完整回答 |
| 独立内容审阅 | 同截止来源下的准确性、遗漏、反证、期间和解释边界 | 方法泛化能力、投资效果或无偏测量 |
| 独立评测 | 冻结问题、输入、评分规则和运行版本，用隔离参考答案评价质量/成本/失败 | 为被测 Agent 补答案，或直接修改正式案例 |
| 采纳与发布（分开记录） | 采纳指定内部研究版本；发布按可见性政策生成对外版本。分别记录责任、条件和历史 | 内部已采纳直接等同对外发布，或从程序通过直接推导买卖资格 |

当前实验的默认提案是每份候选一轮有明确诊断的作者修订及一次复审；这不是已确认的普遍限制，可依据实验调整并在下次任务启动前冻结。仍有关键问题就封存部分结果并列出下一任务需要的输入。
这是新的业务修订默认建议；当前 Data 已有步骤/超时/连续无进展限制，历史 narrative 的一次修订主要针对引用错误。
传输重试、作者修订、重新研究分别计数；重试共享原任务限额，不能借新子任务或新 run 无限重置额度。
失败产物、原始反馈和旧候选保持不可变；新证据/新计划以新版本继续，并说明为何值得再运行。
没有稳定答案时停止本轮不等于删除任务；留下责任方、实际缺口和可触发继续的条件，后续调度持久化仍需建设。
不强制人工逐份审批：常规结果可按经验证的政策分别采纳与发布；首次公司核心研究及审阅未完成只显示“研究中”，不可先发布未完成报告。已有正式报告遇重要新证据时保留旧版并标注待复核范围及截止，新版完成后更新。质量问题进入工作台；正常预测分歧按前述 Manager 责任处理。这套政策执行尚未完整实现。
旧交接文档的“人工审核后更新”在本建议中调整为显式发布政策；已确认的方法升级权限仍保留，不由模型自行放宽。
正式独立评测的 gold、评分和标准答案不得进入被测任务；用过评测反馈的修订只能算开发迭代，不能继续称为未见测试。
