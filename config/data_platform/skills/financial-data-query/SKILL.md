# 财务取数与比较

使用宿主提供的 Data 工具完成原问题。公司、材料、期间、单位和来源范围来自本次请求及已验证元数据；本 Skill 不提供公司事实、默认期间或验收答案。工具是 FunctionTool 或 `mcp__data__*` 时，业务语义相同；`state.next_action` 使用不带 MCP 前缀的业务工具名。

## 先明确交付

将原问题拆成可检查的需求，保留每项要求。先区分需要原始事实、计算结果，还是口径/期间解释；不要因某项难查而从计划中删除。调用方式和一个虚构示例见 [references/tool-use.md](references/tool-use.md)，首次使用本工具组时读取。

- **事实**：数值及原始单位、准确期间、主体、指标、维度、资产版本和原文定位。可用结构化记录时引用 `record`；搜索片段负责定位，不能直接当成完整表格或已确认口径。
- **计算**：引用工具产生的 `calculation`，保留公式、操作数引用和单位。将结果显示为百分比或百万单位时说明换算，不改写原始记录。不把心算或 `note` 里的数字冒充代码结果。
- **上下文**：日期、币种、合并/分部口径等要求也需要对应来源。无维度不自动等于合并口径；空结果不证明原件没有数据。
- **缺口**：指出哪个需求缺什么、为什么停止、已检查哪里。`not_attempted`（尚未查）与 `unavailable`（工具/来源已确认不可用）、`conflict`、`permission_blocked`、`resource_limited` 分开说明，可写在现有 `gaps` 字符串中。

## 根据证据选择下一步

不要求固定工具顺序。用 `find_assets` 查材料，用 `get_asset_schema` 了解实际概念和能力；正文、表格、结构化记录的路径由问题及返回结果决定。

1. 命中片段后，检查是否缺表头、单位、脚注、邻近上下文或完整期间。必要时 `read_evidence`；结果有游标或截断时，不把首屏当作全文。
2. 需要数值时优先使用可用的 `query_records`。概念名称从资产 schema 复制完整 `{namespace}local-name`，不要猜前缀。精确选择本期/上期记录，确认主体、单位、维度和期间可比；重复披露不能相加。
3. 比较计算由 `query_records.calculations` 执行。增长率的第一个操作数为本期，第二个为基期；使用已观察的记录 ID，避免同一概念的重复记录导致歧义。公式与参数见参考文件。
4. 工具错误先按错误类别修正输入或选择支持的能力。`ITEM_TOO_LARGE` 需要缩小读取范围或在允许范围增加本页 `max_bytes`；它不是数据缺失。格式错误不作为来源不可用的证据，不无变化重试。

## 何时交付

逐项对照原问题，而不是只看工具是否成功。凡仍有可用、获准且与缺口相关的读取/计算动作，应继续；“尚未调用计算工具”本身不是无法计算的理由。

全部必需项获得对应事实/计算/上下文证据时提交完整交付。若来源、权限、资源或明确能力限制阻止继续，提交真实的部分结果及具体缺口。输入歧义会改变对象/期间/口径时用 `clarify`。不为了完整而猜值，也不为了避免错误而直接交付空缺口包。

调用 `deliver` 时只提交已实际展示的 `result_refs`。当前接口仍要求同时提交 `request.needs` 和 `state`：两者引用一致，partial/unresolved 的 `gaps` 必须包含对应 `state.gaps[].missing`。这是一项现存接口约束，不是再生成一份财务答案。宿主从引用组装最终 `records`、`calculations`、`evidence`，不是让模型复制数值重建原件。

有文件执行能力且宿主提供交付及需求文件时，可运行：

```bash
python3 <skill目录>/scripts/validate_delivery.py --delivery <交付JSON> --requirements <需求JSON> --require-complete
```

脚本只检查结构、引用依赖和要求的结果类别，不证明选对公司/指标/口径或原文语义。合法 partial 可省略 `--require-complete` 检查；完整性不足仍明确显示。没有文件工具时不要申请额外权限，直接按上述规则使用 Data 工具并由宿主检查。普通 SDK 文本结束不算已提交交付。
