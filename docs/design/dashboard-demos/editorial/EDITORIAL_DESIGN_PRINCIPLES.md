# Uteki Editorial · Anthropic 启发的设计原则 v1

2026-10-10。用于后续页面与组件设计的项目基线。它是我们从原站观察与已认可原型中提炼的方法，不是Anthropic官方设计系统；报告页是本轮应用实例，不代表所有页面已验收。用户最新反馈优先。

## 核心：让内容带领界面

先写清读者要完成什么，再选择表达方式。每页明确一个主要对象、一个主要问题与一个主要操作。层级、版心、字级、留白和图注共同建立编辑感；颜色可独立定制。简洁意味着减少重复和认知负担，同时保留必要来源、单位与状态。

## 证据与原则

| ID | 可复用原则 | 来源层级 | 在页面/组件中如何应用 |
|---|---|---|---|
| ED01 | 先概述，再深入 | [Anthropic研究概述](https://www.anthropic.com/research/tracing-thoughts-language-model)的概述→问题案例→完整论文结构 | 页首给范围与结论；复杂工具/来源按需展开；关键缺口始终可见 |
| ED02 | 结构清楚，装饰克制 | [完整论文](https://transformer-circuits.pub/2025/attribution-graphs/biology.html)的编号章节、图注及分层结构；已认可编辑原型 | 以字体/间距/细线分层；卡片用于独立对象或操作，不把每段文字包成卡片 |
| ED03 | 按角色选择字体 | 本项目用户已认可方向；不是原站统一字体规则 | display负责表达、reading负责长文、ui负责结构操作、numeric负责数据。首页/报告可有展示衬线，任务/运营标题可用无衬线；中文字体与英文分别可靠覆盖 |
| ED04 | 版心随内容功能变化 | 完整论文正文与宽图观察；项目基线 | 正文约640px起步，宽图/表可超出版心，操作栏保持紧凑。宽度是容器规则，不是把所有页面锁成640px |
| ED05 | 操作靠近对象，回程完整 | 完整论文紧凑章节选择；已有来源往返与媒体组件 | 引用贴近陈述，图表切换贴近图；关闭/返回恢复阅读与焦点，不丢筛选、选择或任务阶段 |
| ED06 | 让图解释一个问题 | Anthropic问题案例与对应图注 | 趋势、构成、关系分别选择表示；每图给编号、要点、单位、期间、来源与必要缺口，动效服务理解 |
| ED07 | 美感不改变证据含义 | Uteki证据契约与现有数字/表格规范 | 0/null/负值独立；实测/示例/判断/待确认用文字区分；多视图复用同一ID、范围与数据，不通过换配色更换身份 |
| ED08 | 稳定可定制，行为先于皮肤 | 既有tokens/组件接口与用户反馈 | 语义主题、角色字体、密度、布局变量分别配置；明暗或品牌色变化不改变状态语义。键盘/触屏、错误、减少动效需要明确行为 |

上表原站观察对应上一轮实际浏览记录[REPORT_INTERACTIONS.md](REPORT_INTERACTIONS.md)。短脚注浮层和图表/数据切换分别参考Distill与OWID，不能归为Anthropic实见。官网、论文和App可以有不同字体/密度；目前App资料包含文档与公开视频，未完整检查登录后所有页面。

## 已有可执行基线

实现的单一入口是[tokens.mjs](tokens.mjs)，基础字体在[style.css](style.css)。设计文档不复制一套私有颜色；组件读取语义变量。

| 项目 | 当前可配置基线 | 使用限制 |
|---|---|---|
| 主题 | Paper / Mineral / Plum；canvas/surface/ink/muted/line/accent与正负状态 | 颜色无需贴近Anthropic。自定义主题须提供完整角色，检查文字/焦点可辨，格式校验不等于对比度合格 |
| 字体 | display / reading / ui / numeric；本地中英字体 | 正文字号与行高依内容与语言选；不把宋体用于所有控件 |
| 间距 | 4/8/12/16/24/32/48/64/96 | 控件用小间距，段落/节用大间距；密度变化不能压掉来源和命中范围 |
| 容器 | page 1280、reading 640、sidebar 208；Header 68 | 默认起点；报告与宽表可命名局部变量覆盖，不堆晚期全局override |
| 动效 | control 140ms、panel 200ms | 只过渡状态；减少动效立即切换；布局保持参照位置；视频由读者启动 |
| 数字 | tabular-nums；表格数值右对齐 | 保持原精度和单位；PDF规则不能直接按pt复制成网页px |

`themeCSS(name)`控制主题，`componentCSS(overrides)`控制共用尺寸；新组件优先消费现有变量。需要新变量时，注明职责、默认值与支持边界，保持旧调用兼容。

## 同一原则，不同页面形态

| 页面/对象 | 视觉与交互重点 | 可复用组件 |
|---|---|---|
| 官网/案例 | 强主次标题、内容带、插图与章节节奏 | Header、StoryLead、媒体窗口 |
| 研究报告 | 摘要→连续正文→图注/证据；紧凑目录 | mountReportReader、报告内图表组合、SourcePanel；显式报告内容契约与两份独立样稿已接入 |
| Dashboard | 核心指标与一个主图先行，筛选只放一处 | Metric、范围控制、联动图表 |
| 研究列表/档案 | 扫描比较，选中对象身份始终明确 | DataTable、ItemList、详情与来源 |
| Agent任务 | 输入、执行、待确认、产物有各自状态 | Card、ItemList、AgentTaskPage |

## 每次新设计的简短模板

1. **对象与任务**：谁在看？主要对象是什么？读者要理解/完成什么？
2. **证据与状态**：来源、期间、单位、缺失、模拟/真实范围是什么？
3. **页面表达**：选择阅读/比较/监控/操作中的主要模式；用一句话写层级。
4. **复用与定制**：列已有组件、语义主题、字角色和局部容器配置；不要先造新系统。
5. **验收路径**：真实输入→操作→可见结果→返回；保留可比数据身份，区分程序验证与用户审美评价。

示例（本轮）：研究人员打开原创排版报告→三条摘要选择章节→图表与数据互查→引用定位原文→关闭回原位置。新页面无需与报告拥有相同外形，但应保留同样清楚的对象、层级、来源和回程。

下一版本以新页面实际反馈修订规则，保留版本记录。当前已检查三套内置主题的 9 组不透明文字/背景角色对比度；这不等于整页可访问性审计。跨全部组件自动 lint、长文 PDF 分页和生产迁移仍未实施。

## v1 可执行交付与定制边界

入口是 [system.html](system.html)，接入方式见 [QUICKSTART.md](QUICKSTART.md)。报告内容通过 report-content.mjs 校验，目录、图表/数据与来源面板共享明确 ID。语言、配色变化保留对象身份，阅读状态按报告分别存储。

通用设置置顶；高级阅读项在其后连续展开，不能改变上方布局参照。草稿、最近有效预览与已保存记录分开，校验失败不覆盖保存值。设置样稿只影响本页；是否跟随系统由显式选项决定，目前只有减少动态选项读取系统偏好，颜色由命名主题选择。

每个模块都标注参数化 API 或固定任务模板。原站观察是设计依据，项目实现与交互扩展是我们的推导；不能把模拟 Agent、发票或投资样稿当作 Claude 实际能力。
