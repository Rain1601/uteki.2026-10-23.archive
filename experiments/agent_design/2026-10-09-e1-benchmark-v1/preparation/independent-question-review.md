# 原问题覆盖审核：问题与修复路径

## 观察

E1-06 r3/r4 的取材与模型自审均放行，但 Codex 按预先冻结的原件标准核对后只能确认6/7。规划将原问题中的产品本身定义替换成更宽财务组合的构成，审核沿用了规划者的要求清单。单纯换用更强的 Opus 审核没有解决这个偏差，还要求搜索原问题没有要求的“未披露证明”。失败与费用全部保留。

## 通用改动

增加独立覆盖审核。其输入只包含原问题、范围、来源身份、所选原文及经规范数据集核验的结构化字段；排除取材者的计划、要求清单、摘要和旧审核意见。其职责是拆解原问题并逐项核对实际材料。原来源审核继续检查逐事实、引用和相关性。最终允许交付需要两者同时通过。

不能把 Codex 的金标准、块编号或期待答案输入系统。模型自己提出遗漏，再交还原 Data Agent 查找。程序保留投影、两次原始模型答复、组合结果和调用费用；旧政策产物保持原格式，启用新政策时缺少任一审核文件必须拒绝。

## 两次小规模验证

- probe r1 发现定义缺失，但错误要求额外的单独金额和原文已有的分析结论。因此不能直接启用。
- v2 区分定义、披露指标、关系前提。定义必须对应同一对象；指标可在原问题允许时提供明确限定的组合口径；Data只提供足够分析的事实前提。
- probe r2 的指标和关系误缺口已消失，但模型把组合口径的定义标为完整，并使用只允许指标使用的支持方式。程序拒绝该组合，原结果仍保留为失败。

下一步为一次有界协议纠错和完整系统补查验证。纠错只反馈违反的通用格式/组合规则，不补写答案、不降低缺口标准。此文不是验收通过声明；最新逐题状态见 PLAN 和独立 review。

## 一次协议纠错的实际结果

`E1-06-question-probe-sonnet-repair-r1` 已完成。沿用完全相同的证据与原问题，只反馈程序检出的 `definition_requires_direct_same` 组合错误。模型自行将未受支持的产品定义判为 partial；已披露指标和分析前提维持完整，不再产生额外金额或结论要求。程序校验通过并返回 `needs_more_evidence`。本次新增估算 $0.081852。

这是独立审核小样成功，尚不等同于 Data Agent 已完成自主补查。完整恢复运行仍需独立原件核对。
