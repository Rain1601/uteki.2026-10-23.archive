# Uteki 单屏工作台探索

独立的 0–1 交互原型，不导入已有工作台、旧首页的代码或样式。雨滴品牌使用用户提供的原始 JPEG；只用 CSS 裁出展示区域，没有重绘或改动原图。

## 运行

在仓库根目录运行：

```sh
python3 -m http.server 8768 --bind 127.0.0.1 --directory apps
```

打开 <http://127.0.0.1:8768/uteki_zero/>。如果该端口的 `apps` 服务已经运行，直接访问即可。

## 操作

- 左侧选择公司／组合，右侧标签决定查看什么；两类工作区各自记住对象、标签和条目位置。
- 鼠标在顶部工作区选择区、左侧列表、右侧标签栏、阅读画布上滚动，分别切换该区域的同级条目。画布下方会说明当前切换的对象。
- 滚动达到阈值后翻一屏；同一次手势的惯性不会继续翻页。停顿后再滚动开始下一次切换，边界停止、不循环。
- 点击、前后按钮、页码圆点，以及区域内的方向键，都提供等价路径。编辑笔记时方向键和滚轮保持编辑行为。
- 变化页展示前后判断；持仓含义、证据全文分别进入独立阅读屏。报告按总论和因素分屏；追踪问题逐项展示。
- 公司角标统计未读变化。同一变化的多份证据不重复计数；留待复核、阅读和笔记保持独立，不自动改写报告。

默认整页固定，没有页面级滚动。当前正常窗口中按一屏组织内容；浏览器缩放或极小窗口造成溢出时保留正文内部阅读的兜底，隐藏滚动条。一次手势开始用于阅读后，到正文边界也不会误翻页；停顿后的新手势才可切换。

## 数据与边界

所有研究、来源摘录、任务、经理、持仓、动作、收益和日期均为虚构示意。公司名称沿用设计示例，不连接生产资料或账户。

本机已读、复核标记、笔记和语言使用独立存储键 `uteki.snap-workspace.v1`。未保存的笔记草稿在当前会话中保留；刷新会清除草稿。对象和标签位置在会话内记忆，刷新回到初始页面。没有真实任务执行、收益计算、交易、报告修订或模型调用。

当前专注于单屏布局与同级切换。完整公司搜索、关注管理、全局待复核清单以及真实材料接入尚未实现。侧栏加号进入示例候选公司的初步研究。

## 验证

```sh
node --check apps/uteki_zero/zero.mjs
node --check apps/uteki_zero/content.mjs
node --check apps/uteki_zero/gesture.mjs
node --test apps/uteki_zero/gesture.test.mjs
```

15 项手势测试覆盖阈值、单位换算、方向、停顿、惯性、边界、缩放与区域隔离。启动时核验公司、因素、证据和组合引用，以及含现金的仓位合计。

针对源码审查发现的焦点与滚动边界问题，已在当前正常浏览器窗口定点核对：连续方向键切换；一次长滚动仅切一项；正文滚动余波不翻页，停顿后新手势可翻页。没有截图或多视口视觉验收。

## 公司标识与新增公司

**最新要求（2026-09-29）：必须是截图中 TradingView 风格的紧凑 icon，统一圆形容器，公司名称另列；不能缩小完整横向字标代替。** 批量任务及未来新增公司同样遵守 [icon 接入要求](tools/ICON_REQUIREMENTS.md)。当前六家使用对应证券页已核对的 TradingView 600 × 600 原版图标，保存本地并保留第三方来源；旧官方字标归档在 `wordmarks.json`。


公司记录通过 `website` 明确官网域名，名称和股票代码不参与猜测匹配。`brands.mjs` 按域名读取 `assets/companies/registry.json`：已核实的 Logo 标为 `reviewed-logo`，官网自动发现的图标标为 `official-site-icon`，保留下载地址、来源页面、时间和 SHA-256。注册表另用 `presentation: icon | wordmark` 区分展示形式，公司图标槽位只接受 icon。公司列表、详情标题和组合持仓共用这一机制。组合头像继续使用经理缩写，不作为公司 Logo。

新增公司在数据记录中提供例如 `website: 'https://www.example.com/'`，然后在接入流程运行：

```sh
python3 apps/uteki_zero/tools/import_company_brand.py --website https://www.example.com
```

这里的 example.com 是参数示例，并非可用品牌素材。导入工具从调用者指定的官网发现图标并保存本地；无法自动获取时可传入已经核对的官方素材地址和来源页，详见 [导入工具](tools/README.md)。无需修改公司的专属渲染分支。人工核实的 Logo 优先，自动刷新不会把它降级成网站图标。

缺失注册记录、图片加载失败或来源无效时显示中性公司图标，悬浮提示标识暂缺；不会挪用其他公司图标或把首字母包装成真实 Logo。网页运行时仅加载本地资源，不依赖第三方 Logo API 或密钥。

当前接入点是数据导入工具；自动发现不等于已核实品牌身份，也不保证所有官网都能获取成功。生产环境“新增公司”后台还未连接，完整搜索/新增公司 UI 仍是后续工作。当前六家图标的来源见 [素材记录](assets/companies/SOURCES.md) 和 [机器可读注册表](assets/companies/registry.json)。

批量准备素材使用 [批量导入接口](tools/README.md#batch-import)，必须提交有版本的市场范围和公司身份清单。
它复用同一注册表，提供缓存、有限并发、HTTP 限流、重试、断点续跑和逐条失败记录。
[来源比较](../../docs/COMPANY_LOGO_PROVIDERS_2026-09-29.zh-CN.md) 记录了 TradingView、官网、Logo.dev、Brandfetch 和 Finnhub 的接口及许可边界；
[名单外小批次](../../experiments/company-brand-import/2026-09-29-v1/README.md) 的输出与前端公司池隔离。
