## 一个修复前后可以直接核对的例子

AMD 现金流原件中的 `f-313` 位于表格内，对应 `1,667`，零基 r25/c3。

| 版本 | 锚点目标 | 含义 |
|---|---|---|
| v0.1.7 | `block-000688-a9360e02` | 后继的 Table of Contents 导航，错位 |
| v0.1.8 | `block-000686-a6e8806b` | 所属现金流表，定位已修复 |

新的解析语义先找自身或最近包含块，块外才使用后继。隐藏/脚本锚点保留为无可见目标；重复 ID 保留首次并给诊断。独立合成样例覆盖段落、末尾、空导航、容器、嵌套表格、隐藏祖先、重复 ID 和页码。

第八轮顾问复查另提出未知版本风险。源码复现确认：正式 package 已拒绝未知版本，但低层 `parse_sec_source` 与旧索引脚本存在版本校验缺口。本轮补版本门禁，并把最终实现的包和回执另存为 v2；不覆盖首次修复记录。当前复跑与结果见验收页链接的最终 v2 回执。

首次 `anchor-fix-amd/tsmc` 与 `anchor-fix-verification.*` 是加版本门禁前的快照。它们的实现指纹与最终 v2 不同；不要用当前代码重建结果冒充当时字节。原件与已存结果仍可核对。

## 产物与质量边界

| 小样 | 产生方式与状态 | 本轮实际检查 |
|---|---|---|
| 原文与表格 | 历史程序解析包，原状态保留 | manifest/hash、块与单元格、原句和 inline 币种/尺度 |
| 数值事实 | 历史真实模型提取和规范化，仍为 candidate | 原值 1,667 百万美元与规范化 1,667,000,000 USD；公司、期间和现有记录契约 |
| 精编 | 人工按原文组织的双语、partial 设计草稿 | 拟议样例 Schema、每句证据块、主要包括和 All Other 限定；未运行生成器 |
| 业务图 | 人工按现有 BusinessMap 填写的 partial 设计草稿 | 数据 schema_version=0.1、现有 enum/方向、证据关联与模型边界 Schema；展示元数据由宿主加入 |
| 索引 | 原解析包的 Business 节点 | 块 40…217 与业务小样所在块的关系；索引不是业务结论依据 |

BusinessMap 的 `paragraph_ordinal` 与新块序号的对应仅用于本小样，不代表通用生产桥接完成。标准阅读版和精编分别呈现；精编草稿不替代完整报告。新 prepare 的数值适配缺口仍在，不能用历史候选掩盖。

程序检查只证明所列边界。全文金融含义、漏项、图片/OCR、重复导航、TSMC Item 识别，以及新的 Query 重复稳定性 benchmark 尚未完成。TODO 01 可按“范围定义”完成；03 / 04 / 05 / 11 保留阶段进展和余项。

## Claude 与 Codex 的协作

本轮通过既有 AIHubMix 对话请求 Opus 5.5 两次：一次给出方案/验收，一次复查实际实现。Codex 对照原件、源码及测试决定是否采用。顾问没有运行代码或独立查看完整财报，其意见不作测试或语义评分。

采纳：具体输入→动作→预期→实得、草稿作者与状态分开、未登记版本拒绝。

核查后限定：`_hidden` 已遍历祖先且有测试；新增 null 映射不被当前数值适配/Reader 当作可见块。旧网页桥接另有既存定位限制，未因本修复自动消失。数值单位、时间语义和任务勾选按实际契约修正。

两次顾问调用按冻结单价估算合计 **0.400984 USD**，不是账单。完整上下文、请求、用量和顾问原回答留在项目外私密对话。数据处理、包重建和页面生成均为本地程序，本轮没有新的模型提取、Query 或财报下载。
