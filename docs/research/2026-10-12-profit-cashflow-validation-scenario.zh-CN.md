# 最小验证场景：利润增长是否转化为可持续现金流

2026-10-12 · DS-04 / Query取材方案 · 场景讨论稿v0.1。**未冻结、未选具体公司、未获取场景原件、未开发、未实跑**。依据[技术路径方案](2026-10-12-query-evidence-plan.zh-CN.md)，只验证一个报告判断及其数据链路，不扩展成完整公司研究。

## 1. 目标、范围与完成条件

| 项目 | 建议范围，待确认后冻结 |
|---|---|
| 分析目标 | 根据当时已公开信息，判断利润与经营现金流是否同步、差异由什么造成、哪些因素可能延续或逆转，给出证据、条件、反证与未知 |
| 公司与口径 | 一家美股US GAAP非金融目标公司A；合并口径、实际数值、同一报告币种。利润取与现金流量表调节起点一致的净利润，并核对与利润表的关系；母公司归属/含少数股东、持续经营/整体口径不一致时先对账，不直接相除 |
| 观察时间 | 最近三个已结束财年Y-2/Y-1/Y；逐期使用实际起止日，不能把财年标签当自然年。季度/累计数据仅作为干扰或后续变化，首稿不混进年度序列 |
| 截止日与版本 | T0为首稿知识截止日；只使用确认在T0前公开的材料，采用该时点选定的可比披露口径。T1为后续检查截止日；原始/重列版本各自保留。具体时间、时区和版本策略执行前明确 |
| 材料组 | A的覆盖三年数值的10-K及必要前一期10-K、同期8-K/官方IR业绩材料；SEC Submissions和CompanyFacts作发现/结构化取数入口。B公司材料、A其他期间及T0后的材料作受控干扰，数量与真实版本对执行前另定 |
| 交付物 | 一个短报告片段＋三年数字表＋利润到经营现金流的调节桥＋必要解释/反证＋逐项ref/冲突/缺口；T1另交变化与受影响判断，不覆盖T0结果 |
| 完成条件 | 冻结后的必需事实、条件和出处全部覆盖，口径正确，判断强度与证据相符；或如实返回部分结果及缺口，后者不算完整内容通过 |
| 本轮运行边界/停止点 | 只整理讨论稿和已有能力缺口；零模型执行、零供应商数据调用。公司、原件包/hash、业务标准、重复次数和资源上限尚未冻结，不自动进入执行 |

三个财年的数据可显示历史变化，不能单独证明未来可持续。CFO/净利润高、管理层说“临时”或披露了正FCF，都不能直接成为充分结论。首稿不包含估值、目标价、交易建议、全业务/竞对研究；需要范围外证据时留待补请求。

## 2. Analysis提出哪些Query，Data如何取得

下表是**离线设计与验收的信息需求**，问题措辞和顺序可等价变化。后续端到端执行时，Analysis收到研究目标、公司/期间/来源/截止日及资源边界，自主提出Query；不提前灌入本表、gold、正确数值或答案块。Data只收到真实生成的Query及范围。单独按下表重放时，只称Query能力检查，不称Analysis自主规划验收。

Data先发现发行人ID、财年日历、来源目录、版本和覆盖状态；这是所有Query的共用准备，不要求Analysis预写API参数或答案章节。

| ID | Analysis可能提出的Query | Data获取路径 | 最小交付与核验 |
|---|---|---|---|
| Q1 趋势 | 最近三年净利润与经营现金流如何变化，现金转化情况如何？ | 在同范围核验记录中查数；未入库时，按CIK调用CompanyFacts，或按CIK/分类标准/标签调用CompanyConcept；工具再按单位、实际起止日和允许accession筛候选、绑定原披露核对。期间筛选不能伪装成接口不支持的请求参数；缺项转原10-K利润/现金流量表。计算交确定性工具 | 每年净利润、CFO、变化和CFO/净利润；逐值精确出处、口径/版本。净利润零或负值时不把该比率当质量评分，返回绝对变化、差额及限制 |
| Q2 差异桥 | 为什么经营现金流与净利润不同，差异由哪些项目构成？ | 读现金流量表净利润至CFO的完整调节段及必要表头/脚注；标准XBRL可取的项目直接取，自定义/维度/缺项读原表，再用规则核对 | 三年原始调节项、符号/单位、折旧摊销/SBC等非现金项目与营运资金变动；按原表起点＋带符号调整项回算CFO。保留全部披露项，残差显式报告，不猜“其他”补平 |
| Q3 延续性 | 营运资金、税务或其他现金时点因素是暂时影响，还是连续发生？哪些证据支持或反驳？ | 从Q2异常/变化生成检索条件，定位MD&A现金流解释、相应应收/存货/应付、税务、SBC等附注；按需补读关联段落，不全文提取全部附注 | 相关年度金额、解释、条件、发生记录及反面证据；优先使用现金流量表的变动口径，资产负债表差额不直接替代。管理层归因与分析推断分开；非现金项目的经常性另看，不能默认剔除 |
| Q4 再投资 | 为保持或扩张业务需要多少资本开支，扣除后剩余多少？公司的FCF如何定义？ | 取投资现金流中PP&E现金支出及相关资本开支披露；读取8-K/IR的FCF定义/调节表和必要租赁、资本化支出/承诺说明。各口径分别计算、对账 | 同期CFO与PP&E现金支出，以及明确标记的差额；公司FCF另保留其定义/调整项。维护与增长资本开支未分开披露时保持未知，不猜“维持性capex”或可自由分配现金 |
| Q5 解释核对 | 公司如何解释现金流变化、未来现金需求与风险？不同官方材料是否一致，是否存在反证？ | 在同公司同期间允许原件中检索解释/指引；把10-K、8-K附件和官方IR按来源及公开时间对齐。重复发布关联原件，冲突追到定义/版本；Q3/Q4已有证据按ref复用 | 事实、管理层陈述/指引、条件、风险、分歧和未回答项；同一数值多处出现不相加，GAAP净利润不被Adjusted Net Income替换。未搜到只说明本次范围内未找到 |
| Q6 后续检查 | T1新增披露后，哪些数据、定义或解释变化了，影响了原来的哪些判断？ | 在明确T1范围下取得新增/修订原件，按公司＋事实期间＋指标/维度/定义比较；引用已保存的T0证据依赖，返回差异及ref。新季度单列，不拼进年度数据 | 区别新期间事实、旧期间重列、定义/指引变化、重复/无变化及获取失败；Data报差异，Analysis决定如何修正判断。真实更正版本未取得时该项保留未验，不以构造样本代替 |

Q1→Q2→Q3/Q4→Q5形成首稿；Q6只在T1作一次受控更新验证，不开发追踪调度。Analysis仍可提出必要补问；离线验收看信息覆盖，不要求固定次数、顺序或文字完全一致。

API原始响应存档，工具只把范围内候选/已核验值、必要字段和缺口分页交给模型，不把整份CompanyFacts JSON放进上下文。API返回accession或文件链接还不算精确ref，必须关联到支持该数值/口径的原始事实及表格位置。文档预览用于定位，必要正文须实际读到；磁盘保存不算模型已读。

**计算口径建议，尚未冻结/实现**：利润差额与CFO差额分别按本期减上期计算；同比仅在可比期间且基期为正时使用；现金转化率为同口径CFO/净利润；调节桥按披露符号求和。`CFO－PP&E现金支出`只命名为该明确口径的差额，不能自动等同公司FCF或所有者盈余。输入事实ID、单位、期间、版本、公式和舍入规则一并记录；桥的误差界由原件精度与披露舍入规则预先确定，不能看到残差后放宽。

## 3. 为什么需要这些解析与保存能力

必须保存：发行人/陈述对象；事实的真实起止日及实际/指引；单位与符号；合并/归属/维度；原指标/定义及映射状态；accession/来源ID、公开时间、版本/hash；精确章节/块/行列及关联表头/脚注。正文保留解释段落的条件和所属期间，续表保留关联，转载保留与原件关系。

这使数字可对账、解释可检索、ref可复现。Q2表头或符号丢失，会导致现金流桥错误；Q3只剩脱离条件的一句话，会把管理层假设当事实；Q4定义丢失，会把两种FCF混用。后续检索改进不能恢复这些已丢信息，须先查原件→解析的最早偏差。

每个数字/片段均绑定原件版本；计算绑定输入事实，报告判断绑定Query及所用证据。相同原件可复用，历史原件/解析版本/报告不覆盖。报告年份与所载事实期间分开：Y+1年报也可能有Y比较值，但T0后才公开的版本不得用于T0历史判断；公开时间未知时不能用获取时间推定当时可知。

## 4. 公司、材料和时间不混用，如何检验

先跑一份基线，再分别加入三组干扰；不直接做全组合。**四种配置不是重复次数**，实际次数与资源限额执行前另冻。必要内容保持不变，独立原件核验清单不上送执行Agent。

| 配置 | 同一问题下的输入变化 | 应出现的结果/失败判据 |
|---|---|---|
| 基线 | A、三个财年、T0允许的SEC/IR原件 | 取得所需数值/调节/解释，ref可回到实际表格行及正文；未披露或不支持项有明确状态，不强造可持续结论 |
| 公司干扰 | 加入B同名指标/更强关键词/相似金额；另检查A缺项但B有值 | A的记录/计算/引用只来自A。B不能填A缺口；另做显式切换到B的同类Query时，身份、财年和来源全部切换，A不继续作为默认 |
| 材料干扰 | 加入同披露的IR副本、Adjusted Net Income、定义不同的公司FCF及相关但不必要的正文 | 事实去重，保留出处关系；GAAP与非GAAP分别记录；FCF定义差异被揭示；不因命中一个有用数字把整份无关正文交付 |
| 时间干扰 | 加入其他财年、季度/YTD、T0后公开的年报/修订/指引；同材料池分别以T0/T1查询 | 年度/YTD/单季和实际/指引不混算；T0排除后来才公开信息，包括模型实际输入中的数值/正文/预览，不能只从最终引用删除。T1可使用允许更新并引用正确版本。T0结论保留；新旧数值冲突不静默取“最新” |

在这些配置中再检查：币种/数量级错配、表头脚注漏读、负值/零分母、范围字段缺失或未知、来源/获取失败。符合预期的拒绝或缺口可算边界检查通过，但不计完整报告成功；真实重列、特殊财年或未取得材料分别标未验，不由Schema校验推定支持。

## 5. 什么算通过，失败到哪层找原因

| 层次 | 验收方式 |
|---|---|
| 数据与出处 | 事前冻结必需数字/调节项/条件及等价出处；独立按原件逐项检查，覆盖100%，公司/期间/单位/版本混用为零。引用存在、模型自审及程序退出成功均不替代内容验收 |
| 计算与解释 | 比率/差额可由相同输入复算；调节桥按预定精度闭合，未知不补零。驱动因素带范围、时期、条件和依据；金额贡献与管理层因果表述分开 |
| 报告判断 | 说清历史现金转化、驱动因素、延续/逆转条件、反证及待补资料。依据不足可写“无法判断”；不得仅凭比率、SBC加回或FCF为正写“可持续”。判断是否正确不能由Data通过抵消 |
| 更新 | T1变化能关联到受影响的T0证据/判断，Analysis修正或保留判断并解释原因；未变化、获取失败、缺少版本分别报告，旧报告仍可复现 |
| 信噪比与用量 | 标注必需/必要上下文/可选/无关/重复；分别记录最终证据、每次模型输入峰值、Query及报告全链累计token、唯一原文量、请求/耗时/费用。充分性优先，精简不删必要条件；阈值事前冻结，未知用量不记零 |

按最早偏差归责：Query漏问关键方面→Analysis规划；选错公司/来源/版本→Data选路/范围；取得失败→获取；原表含有但解析丢失→解析/保存；已存但未找到→定位；找到却没读完/未交付→补读/选择；证据充分却推断过度→Analysis判断。工程检查、Query内容验收、报告片段验收分别报告。

## 6. 当前能复用什么，还缺什么

| 源码事实/边界，本轮只读核查 | 本场景意味着什么 |
|---|---|
| [财务适配器](../../src/uteki/infrastructure/research_data/company_materialization.py#L57)映射部分标准净利润/CFO/PP&E现金支出标签 | 有基础取数入口，不能承诺所有标签、财年/币种或全部现金流调节项已覆盖；本场景仍需实际原件核对 |
| [查询计算契约](../../src/uteki/domain/research_data/query_contract.py#L208)仅注册营业利润率、收入/营业利润同比及利润率变化；[计算校验](../../src/uteki/infrastructure/research_data/query_service.py#L374)检查期间、单位、口径/维度 | 本场景的现金转化率、净利润/CFO变化、调节桥与资本开支差额尚不在该注册计算中，需通用计算契约；当前不能交模型自由算术冒充工具结果 |
| [阅读](../../src/uteki/agents/reading/document_reader.py#L64)支持字面搜索/有界读取及结构上下文 | 可复用定位和必要原文读取；语义表达、远处脚注关联与精简粒度未证明足够，需本场景判别 |
| [协调入口](../../src/uteki/agents/data_query/coordinator.py#L646)有受限SEC获取；[Analysis交接](../../src/uteki/agents/analysis/data_consumer.py#L16)可消费经审阅证据、返回待补请求 | 不证明CompanyFacts/FMP通用API规划、Analysis自主多Query和闭环补问/追踪已完成；接口缺口与效果失败分开记录 |

来源规则核查：[SEC API说明](https://www.sec.gov/search-filings/edgar-application-programming-interfaces)限定聚合XBRL入口为非自定义、全发行人事实，并提示frames按自然期间对齐；因此本场景不以API返回量为全部调节/附注分母，期间和版本仍绑定原披露。CompanyFacts是拟用路径，不是本轮已调用或已接通的证明。FMP Free仍为可选后续对照，不成为本场景前置条件。

FCF口径依据：[SEC Non-GAAP说明，Question 102.07](https://www.sec.gov/rules-regulations/staff-guidance/corporation-finance-interpretations/non-gaap-financial-measures)指出其定义不统一，需明确计算及调节，不能误示为可自由支配的剩余现金。这是本场景要求保留定义/必要现金义务限制的依据，不是替某家公司判断现金流质量。
