## 当前运行记录

- `run-01`：真实调用 36 次，失败，终止原因 `ModelBehaviorError`。资本开支用途要求未取证完成。保存的失败运行不修改。
- `run-02`：真实调用 17 次（主 11、子 6），Worker 返回 `evidence_ready`，但父层重复分页读取大交接记录后触发 `no_progress_limit`，整体未完成。两次结构错误均可反馈并纠正，费用照常记录。两轮累计估算费用为 **$0.71487036**，非实际账单。
- 轨迹发现：父层未持续保留已委派任务；目标表已存盘但未进入 Worker 预览；完整但不合结构的模型输出无法在下一轮纠正。
- 第一批修正：持久委派摘要、精确未读正文指针、明确宿主完成检查；保存模型可见输出并将可修正的结构错误反馈给下一轮。隐藏推理不落盘。通过 114 项关联测试及 5 项新增复现用例。
- 第二批修正：Worker 默认交付宿主直接投影的候选记录、引用和已读范围，完整历史单独附上；持久预览给出数值及精确继续读取入口。读取反馈显示真实页大小上限，避免反复增大被截回的参数。相关 87 项回归及 13 项 Worker 测试通过。数值交接在人工压缩到 16 KB packet 的附加诊断中仍可能 `context_limit`；本次显式配置为 300 KB，不声称所有小上下文配置可完成。
- `run-03`：主角色已越过大交接记录，独立重新查询资本开支，但搜索动作夹带计划字段；过于泛化的错误反馈未能指导修正，整体再次触发 `no_progress_limit`。Worker 实际收到完整现金流表的三个连续片段及单位说明，随后仍重复查询，未正常结束。曾经收齐各片段不表示当轮模型能同时看到完整表格。
- 第三批修正：结构错误反馈仅透传白名单内静态规则及纠错建议；每轮保留一份有字节上限的、当前角色确实已读的完整原文块，让金额、期间和单位可以共同核对。未读块不进入保留区，超大块明确计为遗漏，不切成伪完整正文。
- 第三批修正验证：76 项 runtime/Worker/Coordinator 关联测试、22 项 SDK 适配测试、6 项上下文反馈测试通过。`run-04` 以相同输入、原账本执行；前三轮共 73 次调用，累计估算 $1.04167062。
- `run-04`：Worker 正常完成且独立内容核验通过，父层仍重复导航、未完成；整体 `limited / no_progress_limit`。主 25 次、子 10 次，估算 $0.84029574。此时四轮累计 108 次、$1.88196636。发现原 `information` 只检查引用存在，无法表达“必须读原文”的要求；无效 node_id 还会留下错误的资料缺口。
- 第四批修正：新增显式 `source_evidence` 类型和创建时固定的 source_scope；原文要求必须由本角色读取指定来源的完整正文才能满足。持久 `source_leads` 仅作可执行导航；显式 read_source 起始目标也计入未读检查；node_missing 为可纠正动作错误，不豁免正文验收。原有 83 项相关测试、23 项 SDK 测试及 8 项新 source_evidence 用例通过。
- `run-05`：父层首次 `evidence_ready`、零程序缺口，主 16 次、子 7 次，估算 $0.54155262。Worker 返回空白决策而失败，父层继续完成。独立内容复核判为**部分通过**：四项金额、单位、期间、原表实际交付均通过；用途只读到报告期总额与未来投资计划，未读完整主要用途分类。程序完成不能替代内容验收。五轮累计 **131 次、估算 $2.42351898**，全部已记账，实际账单未知。
- 第六轮采用 `input-v2-review-guided.json`，只增加独立评审后的取证标准：区分历史实际与未来计划、补读完整分类和列表上下文。不加入任何金额、类别答案或源块 ID；数据、scope、模型及额度配置保持一致。变化记录为 `input-v2-change.json`，不覆盖 v1 或历史运行。
- 正常 `stop` 的空白字符串输出现在进入宿主下一轮有界纠错，当前输出不执行、不当成功；仍记费且无 SDK 暗重试。`None`、截断和过滤响应保持硬失败。此修正后 SDK 24 项测试通过。
- `run-06` 独立内容复核：四项金额、期间、USD 单位、合并口径及父层原表实际交付通过，11 项证据 artifact 的哈希与原件来源一致。用途读取支持技术基础设施及未来投资预期，但未覆盖原文完整类别列表，办公设施等类别遗漏；`gaps=[]` 未表达这项研究缺口。后段新增上下文挤出已读现金流表，随后重复读取已完成表格并触发无进展限制。`source_body_delivered` 只能证明读过同源正文，不能证明相关分类已完整覆盖。运行封存校验 375 个文件通过。

## 复现与边界

`run_live.py` 只加载显式输入配置和冻结数据集，运行前记录代码及数据哈希，运行后核验 manifest 和数据未变。每次使用新目录，费用账本沿用。`evaluation-reference.json` 只供完成后独立内容核验，**不进入模型输入**。

```bash
PYTHONPATH=src .venv/bin/python experiments/architecture_baseline/2026-09-29-deepseek-mixed-v1/run_live.py \
  --config experiments/architecture_baseline/2026-09-29-deepseek-mixed-v1/input-v1.json \
  --output <new-run-directory>
```

验收区分：模型是否完成委派闭环；原文是否实际送达两个角色；四项金额、单位、期间和现金流出方向是否一致；用途引用是否准确。程序的 `evidence_ready` 只表示引用检查通过，不自动表示投资研究或语义质量合格。所有产物保留候选状态。
