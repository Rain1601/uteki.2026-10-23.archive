一个能具体拆解的例子：Daloopa

它公开的取数顺序是：找到 company_id → 发现可用指标 series_id → 指定期间取数 → 查询对应文档 → 带来源进入计算与报告。这说明公司和指标先被识别，分析不用只靠一段自然语言猜数据。工具与返回说明

数据问题供应商公开的处理对我们意味着什么（设计推论）
单季度还是累计值？Daloopa 将披露值和季度化值分开；span 表达季度 / 累计 / 年度。官方说明计算前必须知道数值口径，不能直接把两个数字相除。
财年、单位、发布时间？REST v3 示例提供财务/日历期间、单位与发布时间等字段。MCP 返回不保证与 REST 完全一致。字段示例Data Agent 应保留这些语义，不能只返回 value。
数据后来变了？自动捕获、人审及重述可能形成不同记录；来源 ID 可能改变。记录规则我们应保存获取时的返回与版本，不能把来源 ID 当永久业务键。

MCP 背后不一定是 Text2SQL

FactSet 公开实体、基本面、共识和非结构化材料工具。S&P 同时提供明确参数的 LLM-ready API，以及另一个接自然语言问题的 Adaptive Retrieval 服务；后者有结构化表格和来源信息，但不能推断财报演示已使用它。FactSet 工具列表 · S&P 参数化接口 · 另一检索服务的契约

尚未公开确认：Anthropic 是否把各数据商结果统一存入永久财务库或证据图，以及供应商内部完整抽取算法。公开接口能说明分工，不能证明它们的实际准确率。连接器使用还取决于数据商订阅与授权。

Uteki 可先定义一个“事实包”：公司身份、指标定义、期间、单位、数值、来源、获取时间、版本与缺口。Data Agent 负责给出可计算的事实和材料，Analysis Manager 负责判断与研究产物。这是本轮提出的设计方向，尚未写进产品实现。

Managed Agents 公开到什么程度？

官方 API 文档定义四个概念：Agent（模型、提示词、工具和技能），Environment（执行环境），Session（一次运行），Events（输入、工具结果、状态等事件）。应用创建配置、发起 Session，通过事件流观察和追加指令。文档还列出定时执行能力；这些属于平台能力，不能推定每个金融 Skill 已配置了持续任务。公开运行文档

与 Uteki 的关联，仅作为待讨论的映射

Analysis Manager 可对应“研究职责＋投资方法＋执行配置”；Data Agent 可提供取数、处理、查询与证据产物。但所查金融仓库没有展示一个与我们完全对应的统一 Data Agent，也不能从 MCP 接口推断其后端使用 Text2SQL。

需要继续区分三个问题：模型怎样选工具，数据工具怎样返回可信数据，产品怎样保存研究状态并展示变化。目前公开资料对前两者的接口与参考方法更清晰，对供应商数据处理及产品内部状态存储披露有限。

Uteki 当前主线：先对齐财报更新，再看数据层。Daloopa 作为可接入的数据来源，Quartr 体验暂缓；本轮没有购买、接入供应商或执行真实研究。

新财报与上一版研究 → 数据变化与出处 → 各 Manager 检视旧判断 → 计算和内容复核 → 更新模型、差异表、报告新版本。

我们希望深化的是：哪条旧判断得到支持或反驳、为什么改变，以及下一次还要追踪什么。同一份事实包可以服务多位 Manager，各自的判断和报告保持独立。

为什么还拆成多个 worker？

Managed 示例把电话会阅读、模型更新准备和最终文件写入分开配置。它们的工具权限并不相同：主 Agent 可以调用子 Agent；最终 writer 没有 MCP，接收整理后的材料写文件。这个拆分展示了职责和工具边界，并未证明所有提示词约束都已由程序强制保证。主配置 · writer 配置

数字、图表和报告究竟在哪里生成？

公开 DCF 方法区分两种执行环境：Excel 内通过 Office JS 写公式、由 Excel 计算；独立文件使用 Python/openpyxl，并要求重算。图表技能调用 Python 图表库；报告组装读取前序文本、工作簿和图表。计算路径 · 图表 · 报告组装

不同技能的自动化程度不同。初始覆盖技能明确每次只做一个阶段，需要核对前序文件后继续；Thesis Tracker 描述证据更新与跨会话保存要求，但自身不提供数据库或调度实现。初始覆盖边界 · 论点跟踪边界

研究重点是信息组织方法：网格怎样建立秩序，文字怎样形成层级，色彩怎样服务表达。不能仅用“少颜色、去圆角”概括，也不能直接把海报规范移植到金融工作台。

研究方向来源支持的方法先避免的误解
网格组织Müller-Brockmann 将网格作为组织视觉信息的工作工具，展示不同分区和应用。Niggli · Grid Systems（1981）网格不意味着所有内容使用等大的方格。
字体与层级Emil Ruder 的方法强调结构、可读性、节奏和比例。Niggli · Typography（1967）不能简化为某一字体、大标题和黑白配色。
色彩与信息秩序展览强调几何结构、精简构图和快速理解；作品包含黑白及鲜明红色。Poster House · The Swiss Grid没有依据要求只能使用低饱和色。

对 Uteki 的待验证推论：固定对齐和数字列有利于横向比较；稳定字体层级可能减少无意义卡片；鲜明颜色仍可用于区分公司或曲线。代价是过硬的网格可能压缩中文长标题和报告阅读空间。这些原则已进入用户采纳的 C 基线；后续直接在 C 目录持续优化，历史版本保留作对照。
