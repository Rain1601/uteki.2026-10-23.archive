## 核对覆盖与边界

- 程序完整枚举原 HTML 的同名导航链接、目标唯一性、对应旧块坐标和 TSMC 目录/正文标题。旧块文件只提供定位 ID，旧 index/toc 只作差异观察，不提供正确答案。

- 未经 Rain 人工签审；未做全部金融语义、浏览器 CSS 可见性、PDF/OCR 或全部正文重要性审核。这里的结构枚举不冒充人工完整财报核验。

## 独立反例与验收要求

JSON 中 N01–N07 和 T01–T09 给出具体合成 HTML、预期与 not_run 状态。关键反例：

- 正文叙事里出现 Table of Contents、重复无链接短文本、外链、失效目标、句中目录链接、隐藏导航均不能把正文整块当可忽略导航。
- 数据表里有 Item 1/500、目录表、普通段落提到 Item 16G，均不能成为正文章节。
- 相同 Item 编号跨 Part 要按选定表单的结构分别定位；同 Part 冲突标题、重复锚点、嵌套表、模糊下一节边界必须显式处理，不能静默取第一项。
- 原始表格/单元格/span、块文字、原序、原件 hash 必须在前后保持；只允许预期角色与索引变化。

这些反例是独立验收建议，未在此基准生成时执行新解析器。修复完成后应另存实际回执，将“预期”和“实得”逐项比较；不要改写本基准迎合新算法。
