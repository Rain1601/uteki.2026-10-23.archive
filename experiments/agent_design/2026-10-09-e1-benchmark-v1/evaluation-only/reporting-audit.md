# E1 费用与配置对照审计

审查范围为 `summarize_runs.py`、`compare_configs.py`、`render_comparison.py`。仅操作离线实验汇总与验收展示，没有调用模型，也没有修改运行 Agent。

## 修复的缺口

| 原缺口 | 修复 | 为什么影响结论 |
|---|---|---|
| 只有结束收据被汇总 | 额外列出没有结束收据的开始记录、预留金额和基于收据的费用上界 | 请求未结束不能当作零费用；上界仍需和共享账本核对 |
| 只比较配置字典 | 验证运行、数据集、各次查询的清单哈希、全部文件内容及文件集合 | 同一配置不能证明实际使用同一版本的文件 |
| 恢复任务可能只承担审核费 | 拒绝 `initial_query_ref`、非新取材的 attempt、指向其他运行的 query | 复用材料的恢复费用不代表从头完成任务的配置成本 |
| 未核对独立审查所属运行 | 独立审查需绑定当前问题、冻结标准和运行清单哈希，并核对流程终态 | 避免把旧运行验收结果套到新运行 |
| 页面声称协议/Skill 一致超过已查证范围 | 比较实际记录的查询协议、提示词与 Skill 哈希；缺失时明确说明 | 已记录指纹相同仍不证明供应商的有效参数、缓存或上游模型版本相同 |
| 页面未展示未知费用 | 表格和分阶段费用都保留未知预留 | 已知估算与真实账单不同，失败和不确定费用不能被隐藏 |

固定审核配置、资源限制、工具/代码和依赖指纹均纳入对照；只允许 planner/worker 的供应商、模型和 effort 作为本轮变量。比较不等于底座模型排名；每配置一次运行不证明稳定性。本次 E1-04 配置与采用双审核的其他题配置须分开解释。

保留供应商原始 token 字段与费用估算口径。缓存命中、思考 token 等细分字段可能包含在其他字段里，不相加构造虚假的总 token。成功、失败收据都纳入费用；历史恢复与开发支出继续存在总账中，不被新成功运行覆盖。

## 验证

13 个离线检查覆盖：失败费用、嵌套用量不重复求和、未知和未结束请求、非法金额、全新取材对照与页面、旧 query 复用、隐藏 initial query、审核配置改变、数据集篡改、未冻结的新收据、Skill 变化、重复调用 ID、错误审查绑定、重复样本及未核验页面输入（部分场景在同一测试中）。全部通过。

同时核验了现有 E1-04-sonnet-r2、其查询和双年报数据集的完整清单，均通过。真实收据汇总可以读取当前实验记录。动态运行总费用不在本文件冻结，交付时应从共享账本和最新收据重新核对。

尚未完成的新模型结果不能用这次离线验证冒充真实模型比较。后续需逐条原件审查，写入独立评价，再生成对照页。整表粒度的冻结标准通过，也不等于已经达到严格最小材料。
