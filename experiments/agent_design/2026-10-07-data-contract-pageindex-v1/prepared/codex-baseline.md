# Codex 草案：有契约的数据加工与片段级取证

2026-10-07。在 Claude 本轮调用前记录。状态：讨论草案，不代表已实施。本轮请 Claude 明确评审这份思路，属于协作评审，不是匿名独立模型 benchmark。

## 我对业务目标的理解

Data Agent 对同一份原材料建立多种可消费产物。每种产物有结构、语义、访问方法和来源。查询侧先理解数据目录与契约，再选取合适工具，交付可回原文的证据包。Analysis 在这些证据上计算、比较、提出假设并形成结论。

“提取正确”与“消费正确”必须分开验收。SQL、JSON、Markdown 是访问语言或保存形式，不能直接决定业务含义。一个业务图可以保存为 JSON；一个财务事实既可在数据库查，也可导出 JSON，它们应保留同一事实身份与血缘。

## 每种产物需要三层说明

| 层 | 要回答的问题 | 例子 |
|---|---|---|
| 结构 schema | 有哪些字段、关系和约束？ | 数值是 decimal 字符串；期间有起止；证据 ID 必填 |
| 业务语义 | 每行是什么？何时可比较、合计或采用？ | 分部收入按哪个分部口径；候选还是本任务已核验；不能把缺失当零 |
| 消费契约 | 模型该如何读、检索、分页和回到证据？ | query_facts、read_source；参数 schema、返回上限、原文回读方式 |

复用现有 get_schema/probe_schema/Data MCP，在目录中补充产物级说明。先覆盖真实消费者需要的两个例子，不新建全能注册中心。

## 产物与访问方法

| 逻辑产物 | 表示方式 | 访问方式 | 最终出处 |
|---|---|---|---|
| 原文段落、表格 | blocks.jsonl + 来源快照 | 按 ID 读取、短语/关键词检索、邻近上下文 | 冻结原文块、字符区间或单元格及表头 |
| 文档导航索引 | 目录树、主题入口 | 读取目录、选择节点、取其对应原文 | 导航只引路，最终回原文块 |
| 结构化事实 | 记录 schema + DuckDB/JSON | 受限查询计划编译为参数化 SQL | 原始数值、转换规则、来源片段 |
| 双语财报精编 | 文档及陈述—证据映射 | 章节读取和全文检索 | 每条重要陈述关联原文，不只引用摘要 |
| 公司业务图 | 节点、关系及证据 | 按主体、关系和证据查询 | 每个事实关系指向披露依据 |
| 本次查询证据包 | 现有 EvidencePackage | 按类型读取来源、计算和模型产物 | 派生链最终到冻结原件 |

普通短文、官方博客、新闻也可复用来源快照、块、陈述与证据关系。无需每篇都建立深树。需要保留发布时间、获取时间、来源归属以及版本；第三方报道和管理层表述不能自动升级为独立核实的事实。

## 查询流程

```mermaid
flowchart LR
  Q[问题及公司 时间 来源范围] --> C[发现产物与读取契约]
  C --> P[生成并校验查询计划]
  P --> N[事实查询 文本检索 或目录导航]
  N --> E[回读片段与组装证据包]
  E --> A[Analysis 形成带依据的结论]
```

完整流程是拟议目标，已有部分组件尚未统一验收。自然语言到取数计划已经有实现。暂不需要让模型直接执行任意 SQL 或 shell 命令。

例如“指定版本年报里的谷歌业务有哪些、如何赚钱”：先从业务章节、分部附注及相关披露找业务描述；再按明确分部/期间查询收入记录；需要时读回表头和限定条件。结论应分别标记披露事实、公式计算、管理层说法和研究推断。该例是任务示意，没有在本轮实际分析谷歌或选定财年。

## 证据定位的最低要求

引用不是一个网页 URL。它至少要能解析回：来源快照及 hash、解析/索引版本、原文 block 或 table cell、必要上下文。文字区间应注明依附的文本表示及计数方式。页码/DOM 只作为定位辅助，不能在材料变更后偷偷指到新版本。

现有 SourceLocator 已有这些坐标的多数槽位，但它们大多可空。应为不同产物定义实际要求的精度，并报告达不到要求的情况。普通页面只能定位到页时，不能标成片段级引用已通过。

摘要与树节点用于缩小阅读范围。模型不能仅凭索引摘要就形成最终来源陈述。计算结论保留公式和操作数记录，每个操作数继续追溯到原文。新闻或 Web Search 新发现先获取并保存实际材料，再进入同样的取证流程；搜索摘要和网址本身不证明具体陈述。

## PageIndex 的初步判断

适合评估其文档导航与候选证据召回能力，尤其是内容散在多章节时。现有 SEC HTML 块和精细定位应继续保留。PageIndex 本地 PDF 处理与页级引用，不能直接替代这些能力；是否引入要测导航收益和定位成本。

优先比较现有目录+短语搜索、改进关键词召回、树导航三种检索方式；在相同材料和原文证据定位规则下，分别测找回必需证据的比例、错误引用、遗漏、耗时、建索引与查询成本。树导航的摘要可能丢信息，关键词检索也可能漏同义表达，都要留可回读原文的补救路径。

## 最小下一步

1. 在同一份已有冻结材料上完成两个消费案例：一个结构化指标问题，一个分散在多个段落的业务问题。明确范围，不默认公司、年度或来源。
2. 补最小产物说明；让模型实际先发现 schema，再调用正确工具，最后回读具体片段。增加错误单位/期间、缺数据和来源改变的反例。
3. 以这两个案例作端到端验收，再加独立样本比较 PageIndex。两个例子只证明接口贯通，不证明检索总体质量。当前不安装 PageIndex、不改生产主流程。
