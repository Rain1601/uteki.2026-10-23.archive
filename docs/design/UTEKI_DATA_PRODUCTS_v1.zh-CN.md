# Data Agent 产物与验收 v1

2026-10-04。用户认可“两类产物 + 原文检索底座”，并要求对照 Daloopa、FactSet 快速迭代。本文件区分产品目标、当前实现和本轮验收。对标依据仅为公开官方资料，未使用两家的付费数据或实测其正确率。

## 1. 同一份材料的三个可见结果

| 结果 | 输入与过程 | 输出及查看方式 | 验收重点 |
|---|---|---|---|
| 原文检索底座 | 显式公司、材料类型、期间、截止日 → 官方获取与身份核对 → 保存原件 → 解析段落、表格、目录 | 原件、元数据、块/表/单元格及检索 schema；按公司、来源、期间筛选 | 原文可还原；公司、版本、时间不串；解析失败和未处理图片明确 |
| 财务事实库 | 已冻结原文 → 模型选择证据 → 提取源口径候选 → 明确映射与单位转换 → 程序检查 → 内容核验 | 原始候选及 SQL 数据；指标 × 期间查看，点击数字回到原表和核验意见 | 金额、符号、单位、实际财年、主体及口径正确；遗漏单独检查；未知不补零 |
| 财报精编 | 同一来源的业务、分部、风险、MD&A、财务及重要附注 → 阅读与忠实浓缩 → 原文核验 | 中文、英文两个可读版本，正文、引用表格及必要图表 | 重要信息及限定条件保留，每项关键陈述有出处；不引入外部记忆或投资结论 |

精编核心章节：材料身份及范围、业务与收入来源、公司披露的分部/经营指标、财务表现与资金情况、管理层解释、风险与重大事项、重要会计政策/附注、材料缺口。不存在的披露标明未披露或未覆盖；章节根据实际材料适配，不将模板名称当成必须编出内容的要求。公司特有 KPI 可增加条目，不能因不在核心指标目录就丢弃。

精编是所选报告的浓缩版，不是公司截至今天的全部信息，也不是 Manager 的投资报告。管理层解释须保留归属；图表只能来自已明确出处的数值，不能由模型编造。精编正文、原文摘录与模型提取草稿三者分别标记。

## 2. 财务记录及版本

每条候选至少保留公司/主体、指标原名、原数字与单位、实际期间、会计与合并口径、来源/原件 hash、证据定位、提取运行及版本。规范化记录保留原候选关联、转换规则和审核状态。统一货币尺度不等于已经完成跨公司会计口径标准化。

重复检查不能只按“公司 + 年份”决定跳过。事实身份包括主体/维度、指标定义、期间、单位/口径及来源版本；同源同版重复可识别，新来源对比较期的重述应形成新观察，保留旧观察及知悉时间。正式可用视图只纳入符合既定核验要求的记录；候选库与共享已核验事实不能混为一谈。

SQL 由受控写入层执行：校验 → 重复/版本检查 → 写入候选快照 → 回读核对。模型产出数据和证据，不直接任意改写数据库。现有 direct extraction 会写独立 DuckDB 候选快照并回读核对；跨运行去重/重述关系、共享核验发布及持续更新仍待完成。

## 3. 本轮最小交付

输入采用已真实自动获取的 AMD FY2023 年报，保留报告内较早年度的比较列；台积电和其他年度仍保留各自状态。DeepSeek 负责选材与提取，Codex 使用事先独立整理的原文对照检查输出，对照值不得进入提取输入。

页面复用后台资料/评估入口：选择数据包及材料 → 查看产物完成状态 → 显式选择一次提取运行 → 切换原口径候选或数据库记录 → 点数字查看原文及审核。不同单位、主体、会计口径和维度不可强行放进同一行；重复候选不可取第一条或自动相加。未入库候选及原因仍可检查。财报精编未生成时明确显示缺口。

本轮通过条件：真实模型输出已保存；页面数字来自冻结输出/数据库；来源及公司匹配；每个展示值可追到候选和原文；原数据、模型候选、工程校验、内容审核状态分开。失败也进入运行记录，不以示例数据替代。通过单份材料不宣称双公司全部财报完成。

## 4. 补齐顺序与如何比较

1. 当前：真实财务候选、原表证据及可读查看页，先验收 AMD FY2023。
2. 随后：处理发现的遗漏/错误，生成财报精编；用台积电验证 IFRS、TWD 与 20-F，再覆盖已登记的其余年度。
3. 再后：公司特有 KPI、跨年对齐、重复/重述与时间点版本、更新监控，以及同源模型/Prompt 版本对比。

比较指标分开记录：正确率、应提内容的遗漏率、引用定位准确率、口径/期间错误、更新延迟、运行费用和人工核验时间。每项都要有固定样本、独立答案和明确分母；行数增长不是质量提升。没有同范围供应商输出时，只能比较功能与公开方法，不能报告优于供应商的效果分数。

## 5. 与 Daloopa / FactSet 的公开能力对照

| 参照能力 | 官方公开依据 | Uteki 差距与本轮取舍 |
|---|---|---|
| 公司 → 指标序列/KPI → 期间 → 数值与引用 | [Daloopa API/MCP](https://docs.daloopa.com/docs/api-vs-mcp) 列出公司、series、fundamentals 发现与引用接口 | 已有材料和原文索引；财务提取可见性不够。本轮用指标 × 期间表和单值证据详情，后续补公司特有 KPI 目录 |
| 来源追踪与质量核验 | [FactSet 2026 Q2 资料第 8 页](https://investor.factset.com/static-files/e24493a8-95d4-4911-be9f-8ea84b109a84) 说明来源追踪、自动检查与人工复核 | 我们已有原件/hash/引用；需要把原值、转换、核验和未解决原因放到每条可见记录上 |
| 财年、日历年和实际期间区分 | [Daloopa v3 迁移说明](https://docs.daloopa.com/docs/daloopa-api-v3-release-notes-migration-guide) 清理含糊期间字段 | AMD 周制年度已经能保留来源的实际日期；首版 UI 必须显示日期和时点/时段，不能只显示 2023 |
| 跨公司标准化与历史一致性 | [FactSet 同页](https://investor.factset.com/static-files/e24493a8-95d4-4911-be9f-8ea84b109a84) 声明跨会计准则标准化、跨期关联和 PIT | Uteki 的当前 normalized 仅为明确映射与单位换算；全面跨公司可比、重述历史与完整 PIT 均未验收 |
| 更新、歧义和未核验数字的区别 | [Daloopa Scout 更新说明](https://docs.daloopa.com/docs/updating-a-model) 说明有已知映射时规则更新、歧义保留、重述需明确处理，直接读披露所得数值单独标记 | 可以借鉴“探索建立映射，后续按已核验规则更新”的分工。本轮先让候选/入库/审核分别可见，后续再接持续更新 |

这些页面提供的是厂商功能/方法说明，不是已独立证实的准确率。“超过”应先落在有限范围的证据定位、漏提率和复核效率上，用相同材料实测。行情、市场预期及全市场覆盖属于额外数据来源与积累，不能仅从一份年报恢复。

注意 Daloopa 概览与迁移页存在旧端点描述不一致；具体实现须以显式版本契约为准，不照搬概览中的已移除端点。本轮仅参考产品方法，没有接入供应商服务。
