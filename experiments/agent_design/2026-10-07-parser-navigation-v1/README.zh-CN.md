## 验收方式

1. [独立原件基准](independent-oracle.zh-CN.md)在新解析结果生成前建立，原 HTML 是预期的依据。基准不进入生产解析。
2. `verify_stages.py --build` 创建新包和阶段回执；`--check` 检查冻结文件、原版本行为和同环境重建。脚本拒绝覆盖已有包。
3. [独立实现复查](independent-review.zh-CN.md)逐条核对原件，记录发现、修复和未测范围；结构检查不冒充全文金融语义评测。
4. [下游审阅检查](handoff-check.json)验证末尾只有导航时能继续遍历、记省略、拒绝空正文和停滞游标。真实 QueryPort 使用合成材料；不是模型能力评测。
5. `build_delivery.py` 从已核验包生成验收页，核对原文字段不变、实际 search/read 以及页面文件/片段链接。页面不发模型请求。

## 合作与边界

原独立基准 16 条已全部执行：10 条达到原预期，6 条保守拒识或诊断粒度有限。单项目录、缺 Part、缺可验证目录/锚点等条件下，原文保留，但导航/Item 不达到原预期；不改写 oracle，不把这 6 条计作通过，也不为本轮扩大生产推断范围。详见独立复查。

Claude Opus 参与方案和第九轮边界复查；Codex 对照原件、实现并独立验证。完整问答继续保存在仓库外的私密会话。Claude 对 Item 16C 的“div 粗体”有一处误读；原件仍是两格表，按原件纠正，没有为此添加推测模式。该轮顾问请求估算 $0.203644，非账单；四包解析及程序检查无模型调用。

导航规则要求已识别目录至少两个 Item，导航至少两次重复，并核对独立短链接与真实目录目标。带页码的导航文字、单次链接和其他语言变体可能保留。显式原文/按块提取入口仍可读取原始块，不能声称所有模型路径均已过滤，也没有实测 token 节省。

目录范围是连续导航范围。Item 17 / 18 转指后文的财务报表，Item 19 之后还有签名与财务索引；自动跟随交叉引用尚未实现。新章节节点可使用已核对的目录页码，旧原文块的页码标签未重算，例如 TSMC Item 16C 的旧标签为 71，而原目录及新节点为 70。块和单元格 ID 是本轮精确定位依据。

全文语义、表格单位和脚注关联、图像/PDF/OCR、模型加工与 Query 完整评测仍需各自验收。没有浏览器视觉审核，也没有把这两个子阶段完成等同于 TODO 04 整项完成。
