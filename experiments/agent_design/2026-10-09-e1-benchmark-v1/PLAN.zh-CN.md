# E1：独立证据评测集与有界模型迭代

2026-10-09 用户授权。当前目标：在 Microsoft FY2024/FY2025 两份独立官方 10-K 上，先建立 Codex 阅读原件得出的评测基准，再验系统 Data Agent 是否能以较少费用取得充分且聚焦的材料。本轮受限评测已完成；下表保留实际完成边界，不将其外推为全材料、全公司能力。

## 职责与输入隔离

- 系统负责通过已有获取入口发现/获取指定原件、准备目录和数据说明、查询、阅读、选材及复核修订。调用者显式给公司、报告年份、来源政策、问题和资源限制。
- Codex 负责代码、原件独立精读、评测基准、运行监控和事后内容审查。使用当前 Codex 能力开展独立复核；不把评测答案或必需块清单交给运行模型。
- `evaluation-only/` 存放标准、证据候选、阅读记录、盲审及评分；系统配置仅包含问题/范围，不读取该目录。独立阅读者先看原件，不看 Agent 交付。
- Claude 可审阅具体技术缺陷/方案。最新用户要求评测集由 Codex 全程构建，顾问不替代 Codex gold，不机械调用额外评审模型。
- 历史失败和新失败保留，新配置/标准/运行用新版本。不能在看到结果后静默放宽标准；必要标准修订要说明原始错误、影响案例，并重新计算所有可比较结果。

## 评测集怎样建立

1. 核验两份独立原件的公司、申报类型、报告日期、公开日期和 hash，检查准备层和模型能实际看到的 schema。
2. Codex 通读相关章节、相邻段落/表格/脚注，并跨节搜索同义词及可能的替代披露。记录阅读覆盖和仍未检查部分，不声称数学上唯一最优。
3. 每题列出必需语义要点、条件性必要上下文、可选证据、无关/误导内容。每个要点绑定原件定位、精确引文、允许替代的证据组；允许多个有效材料集合。
4. 根 Codex 交叉检查原件与独立阅读产物，再冻结问题、范围、证据标准及文件 hash。冻结之后才发起对应系统基线。
5. 评测分硬门槛和效率，不用一个平均总分掩盖关键遗漏。先判主体/版本/真实性/必需覆盖，再计算覆盖、冗余和费用。

## 每题呈现给用户什么

默认只呈现：**问题 → 必须知道什么 → Agent 实际提供什么 → 足够支持哪些回答 → 缺了什么 → 多了什么及原因 → 成本与结论**。过程日志放次级入口。

建议记录的可复核统计：

- 必需语义要点覆盖：完整支持 / 总必需项；部分支持单列，不算完整。
- 条件性上下文是否满足，如单位、期间、表头、限定语和脚注。
- 逐交付片段分类：必需支持、合理可选、必要阅读上下文、重复、无关、未判定；解释理由。
- 可选命中不加分补偿遗漏，不把只给必要材料的结果惩罚为覆盖低。
- 记录无关及重复字符、交付总字符、原表不可裁切的额外字符。不能把整个表格一概计为有效或一概计为浪费；不重复计算重叠区间。
- 公司/材料版本/期间/截止时间及引用真实性，任何错误单列为阻断。
- 运行成功/模型自审/独立验收分开；同时展示调用数、输入/输出/缓存 token、耗时、已知费用和未知预留。

## 本轮费用授权与控制

用户为本轮新增外部模型/API调用授权合计 **100 USD 上限**，不是要求花满，不包括 Codex 账户订阅计费。本轮不继承上一轮无限预算。历史账本保持原样，新轮开始记录边界和自己的全部调用；不能靠重建/分叉账本重复获得额度。

所有系统模型共享本轮强制预算账本，包含失败和未知预留。若顾问沿用私密会话账本，本轮新增顾问调用必须同时计入本轮总限额，不能另享100美元。供应商实际余额/实际账单未经读取；估算不能保证第三方实际价格。用户报告上一轮约70美元，项目已知估算约47美元，两者待对账，不擅自归因。

费用节制：先零API的工程/基准检查；一次一题；每次批次前后查账；首批计划约5美元以内，若必须提高先定位原因并记录；仅跑受影响题，不无差别重复六题；已经冻结的原文/解析/标准复用；缩小无关模型上下文，不能削掉必需证据。unknown保持预留，临时故障有限重试，内容问题先诊断。

若预算无法覆盖当前通过条件，保留未通过结论与可检查产物，不降低质量标准，也不越过总上限。
