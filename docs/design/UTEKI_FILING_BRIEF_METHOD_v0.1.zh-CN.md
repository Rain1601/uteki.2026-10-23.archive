# 材料精编：重要性、双边方法对照与候选 Skill

2026-10-05。状态：**方法设计已进行一次真实 DeepSeek 对照；候选 Skill 已编写和静态校验；完整年报精编执行器尚未实现，未进入默认系统方法。**

## 用户目标与首例

用户希望从财报里区分“必须看、需要留意、没有用”的信息，形成高质量的材料精编；本会话 Codex 与 Uteki 独立回答，再把有效方法沉淀为双方可用的 Skill。参考会话：[整理台积电年报图文摘要](codex://threads/01a10b6e-8e94-7353-9fb6-6af4a1f79090)，其业务图、简明图文和持续跟踪问题可作表达参考，不能当作已经核验的事实标准。

用户已选择首份成品用 **TSMC 2025 英文官网年报**，与参考会话一致。它与后台已保存的同年 SEC 20-F 是不同来源版本，不能静默替换。首轮阅读目的建议明确配置为“首次理解公司业务”；后续更新阅读需显式提供已有基线。这个阅读模式是首例配置选择，不是共享代码里的公司或年份默认值。

## 重要性怎么判断

核心问题：**删掉这条信息，会不会使读者误解公司怎样赚钱、盈利质量、资金需求、执行条件或重大风险？**

| 分层 | 判断依据 | 精编中的处理 |
| --- | --- | --- |
| 必须看 | 是理解业务所必需，或可能实质改变对盈利、资金、依赖和风险的认识 | 正文突出，带证据和限定条件；即使未量化、尚未兑现或不确定，也可能属于此层 |
| 需要留意 | 有明确业务关联，影响尚待后续事实确定 | 写清目前知道什么、不知道什么、下一次通过何种官方披露验证 |
| 本次不展开 | 重复、版面噪声或低相关细节，压缩后不丢失重要含义 | 正文省略或合并，保留来源位置与处置理由，不删除原件 |
| 待评估（内部状态） | 未取得、未读、解析失败或含义不明 | 显示缺口，不能归为“不重要” |

重要性、事实类型、可信度分别记录。管理层计划可以非常重要，但不是已实现事实；审计、治理、法律、环境、附注不能整章降级。百分比阈值只可在明确配置下提示复查，不是通用排除标准。三大报表所有行都可保留在数据层，但不代表必须原样堆进精编正文。

概念例，不代表已完成台积电事实核验：客户数量很多，并不能回答是否依赖少数大客户；未来重大扩产仍可能是必读信息。年报若同时披露投产进展、许可条件及建设承诺，应分别保留，不能压成“扩产已经兑现”。庆典照片可不展开，其旁边的进度数字不能随照片一起丢弃。

## 实际加工与产物

输入是明确公司及原件版本、报告期/信息截止、阅读目的、正文/表格/图形、已有财务候选与核验状态。先建立全文及引用材料的覆盖清单，再生成有证据的信息点，评估重要性，组织图文，最后做双向核验。

- **人读的精编**：中文与英文两份，围绕业务图、重要事实和财务表、变化与约束、留意事项、材料缺口组织。不强制图表数量或压缩比例。
- **机器可用的信息点**：陈述、类型、重要性及理由、来源位置、期间/单位/口径、限定条件、冲突和核验状态。图表和两种语言共用同组事实 ID。
- **覆盖与取舍记录**：哪些区域已读，哪些信息纳入/合并/未展开，为什么，以及哪些引用材料尚未取得。可以按明确范围合并重复噪声，不机械地给每个装饰元素调用模型打标。
- **运行和审核记录**：实际加载的 Skill、Prompt、输出契约与模型，已记录的步骤，问题、修订及版本。找到出处、语义支持、覆盖检查和正式采纳是不同状态。

核验必须包含“结果 → 原文”和“原文 → 结果”两个方向。前者查错，后者查漏。固定目录检查只能证明检查过哪些区域，不能证明没有重要遗漏。重大未知或矛盾即使不能进入已确认事实区，也不能从报告里消失。

## 这一次真实方法对照

共同题目：[common-input.json](../../experiments/architecture_baseline/2026-10-05-filing-brief-method-v1/common-input.json)。

先冻结 [Codex 方案](../../experiments/architecture_baseline/2026-10-05-filing-brief-method-v1/codex-proposal.md)，再通过 Uteki 已有 `SdkRecordReviewer` 的计量/记录机制，调用工程既定的 `deepseek-v4-pro / high`，取得 [系统模型侧方案](../../experiments/architecture_baseline/2026-10-05-filing-brief-method-v1/system-proposal.md)。没有向它提供 Codex 答案，也没有把期待的财务结果作为输入。

运行发生一次真实请求，返回成功；用量 9,260 tokens，含 reasoning tokens。按已有价格快照估算 USD 0.03432792，不是实际账单。原始输入、输出、Prompt、模型配置与用量位于 [运行目录](../../experiments/architecture_baseline/2026-10-05-filing-brief-method-v1/deepseek-method-proposal/model-config.json)。本次保留原共享用量账本，未设置或声称费用上限。

这次调用是**方法设计实验**，运行适配器内部名称仍为 RecordReviewer，不是已经实现的 Filing Brief Agent。Codex 当前会话有额外历史上下文，因此也不是严格控制条件的模型能力排名。

| 发现 | 处理 |
| --- | --- |
| 双方都提出证据定位、保留未展开内容、遗漏检查、版本化方法 | 纳入候选方法 |
| 系统方案明确双语共用事实 ID、财务表与 MD&A 交叉核对、保存机器条目和审核记录 | 纳入输出约定，避免两份报告各自生成一套数字 |
| 系统按会计项目预设 Must/Note，并提出通用 10%/5%/1% 阈值 | 不采纳为默认规则；改为按业务影响和理解缺失判断，数量筛查不能掩盖定性重大性 |
| 系统将原文逐字匹配后标 verified | 区分引用定位、数字一致性、语义支持和覆盖审查；翻译和摘要也不能靠逐字匹配审核 |
| 系统将每个表格单元标记当作覆盖 | 保留独立的原文到精编语义检查，防止全部标 Skip 也算完成 |
| 系统的金额 X、某页某表占位例仍标 verified | 候选 Skill 明确示例和未取得证据不能使用真实已核验状态 |
| Codex 方案强调事实修订，但可能过度限制表达优化 | 明确表达、顺序、术语解释可按阅读反馈改进，事实与条件须保持 |

独立子代理做了方法文本复核；它不是原年报内容审核，也不构成作者盲测。当前选择“按理解影响排序”的原则与共同事实层作为初始模板，不宣布任何模型在完整精编上已经胜出。

## 候选 Skill 与执行边界

[共享 Skill](../../skills/data-agent/brief/SKILL.md) 为 `data-agent-brief / 0.1-candidate`，附[输出约定](../../skills/data-agent/brief/references/output-contract.md)和[审核规则](../../skills/data-agent/brief/references/review-rubric.md)。Codex 可按显式任务读取使用；Uteki 正式任务尚未绑定或调用它。

Skill Creator 的结构校验通过；第一次执行时工作虚拟环境缺少 PyYAML，最终只读取既有本地依赖缓存完成校验，未修改项目依赖。此校验不证明模型遵守方法。候选文件还需通过真实加载、精编、审核及留出材料验证，才可提升为默认系统能力。

## 下一步和验收

1. 用已选原件做首份双边独立精编，带上上述材料缺口；若评价完整财务附注覆盖，先另行取得并冻结被引用的正确版本。不得直接换成 SEC 20-F。
2. 实现独立的材料精编任务入口，真正加载候选 Skill/Prompt 和来源索引，保存机器信息点、覆盖记录、双语正文与审核产物，接入后台原文联动。沿用来源校验，不借用财务数值提取任务冒充精编执行。
3. 同材料、同目的、同信息边界独立产出；先查重大错误与遗漏，再由用户比较可读性。只有优于现有方法的规则才能成为老师反馈。记录模型、上下文与工具条件差异。
4. 在未用于教学的 AMD 材料或其他财年上复验，检查是否仍会把重要计划降级、混用口径、漏掉反证或伪造核验状态，再决定默认方法。

上述后续步骤尚未完成；本轮没有生成全年报精编成品，没有触发正式发布或研究采纳。
