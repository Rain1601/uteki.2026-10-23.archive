## 我的判断

先固定任务及其验收，再评估模型分工。建议保留四类产物：材料库、结构化事实、双语财报精编、公司业务图；再明确按问题补证和更新维护两类任务。

Sonnet 先作为边界明确任务的执行基线。程序负责确定性解析、已明确口径的计算与约束检查。Opus 是否负责规划，要看复杂定位、口径冲突和修复案例上的实际增益。先不把强模型规划加入每一次常规运行。

Data 可以交付披露事实、管理层解释的忠实摘录、可复算结果。Analysis 才进一步判断商业原因、持续性与投资意义。财报精编和业务图也需要任务级语义验收，不能用是否输出了 JSON 判断完成。

以下是拟议的验收流程，尚未实现完整闭环：

## 两份意见带来的输入

| 议题 | Opus 5.5 | Fable 5.1 | 审核后建议 |

这些是建议，不代表能力已实现，也不因两模型一致而自动采纳。

## 不能直接采用的部分

两款模型都把历史 **程序精度评分规则** 的问题归到了 **Codex 盲评**。这是对给定背景的误读。原记录已经明确区分两者。两个模型重复同一个错误，是本次最直观的提醒：模型意见需要来源核验。

Opus 还误称现有评估只检查数字和引用、双语要求未定稿。历史语义评审已经存在，双语精编也已有契约。它把“合法缺口”计入事实召回，这会混淆交付了事实与说明了缺失。应分别报告事实召回、任务条目处理完整率、假缺口及漏缺口。

Fable 将“失败首先由契约造成”说得过于确定；这只是待验证假设。它声称所有快照都是候选、没有独立答案集，忽略已有受限核验路径和小规模答案。它建议“重复十次后承诺稳定性”，没有统计依据。其所谓单变量实验同时改变缺口数量、分类和输出要求，只能测试提示组合，不能归因到单个改动。

Fable 的反例写成“删除 S1 的附注表”，但现有五块 S1 材料没有这张附注表。真正制作反例时，要明确删除哪一块，并检查剩余文字是否仍能提供答案。它又要求只允许一条缺口，会重新引入数量约束。单语言精编 MVP 也会缩减既定双语范围，不能直接采用。

两份建议都存在共同限制：

- 数字出现在片段里，不等于主体、期间、单位和口径正确。程序只对已明确映射的规则作判断。
- 章节都出现、表格数量对上、检索记录齐全，均不能独自证明语义完整或“全文没有披露”。裁判输入必须保留足以作判断的上下文。
- 原文给出的 90%、95%、99% 等门槛是建议值，没有由我们的风险和样本量确定。
- 费用公式都可能把已纳入调用总和的失败/重试再次计入。按唯一调用记录逐项计费，避免重复。

回执中的模型名称属于平台声明，不能独立证明底层权重或路由。两个响应 ID 各异、完整保存在 [Opus 回执](runs/opus55/receipt.json) 与 [Fable 回执](runs/fable51/receipt.json)；响应头未提供独立 request-id，记录为 null。

完整任务的模型成本应按以下方式记录：

`模型费用 = Σ全部唯一调用 [(未缓存输入×输入价 + 缓存读×读取价 + 缓存写×写入价 + 总输出×输出价) / 1,000,000]`

调用集合包含执行、规划、修复、评审和失败，已经包含的失败不能再加一次。外部工具费另加；人工分钟数与按时薪折算费用单列。每件验收合格产物的平均成本，应把同批失败尝试分摊进去。当前咨询费用与历史小片段费用，都不能充当完整年报处理的实测报价。

## 检查和边界

发送前固定共同请求、价格、配置、代码和背景来源。完成后核对 15 个来源文件、准备文件及运行依赖的哈希；两次请求只有 model 字段不同；回执均正常结束；费用重新计算一致；账本共两次、没有未结算或费用未知请求。离线模拟还检查了超时记录、重复调用阻止、费用未知时停止和密钥保护。模拟检查不代表真实模型质量。

没有修改生产提取提示、既有实验、数据库或后台页面。顾问建议尚未写进生产流程。
