# E5：一个问题，两家公司，各自正确取材

2026-10-10 本机最终更新：**E5-A1 指定双公司收入题通过**。r5 经一次合法模型审核反馈驱动的自主取材修订，必要 4/4、真实性/出处、聚焦与最终双审通过；旧失败、受控试验及 r4 反例保留。下一项 E6-P1，见 [真实执行交付](EXECUTION.zh-CN.md)。下方费用缺件说明为另一台机器历史，本机原账本沿用未清零。

## 具体输入与期望交付

从本机已有、hash 验证的 Microsoft 和 Alphabet FY2025 完整 SEC HTML 10-K 构建显式双公司语料。公开输入清单只指定整份报告、公司、期间、截止日和来源，不含章节、块 ID 或金额。

问题：以 2026-02-06 为可得截止日，仅根据所选 Microsoft 与 Alphabet 的 FY2025 10-K，分别提供两家公司 FY2025 和 FY2024 的公司整体收入。保留每项的财年、精确起止日期、币种、单位及可定位原文。不要将两家公司的财年日期混用；不计算增长、不合并公司金额、不展开分部分析。

期望交付：四项有明确公司、期间和出处的收入材料，以及理解这些数字所需的最少上下文。相同 FY 标签在两家公司对应不同日期，这是本题应覆盖的真实边界。Codex 不替运行 Agent 选表或查询；完整语料交由系统自主导航、查询、阅读和选择。

## 已确认的架构边界

ExecutionScope、查询执行器和 Agent 可承载多个公司；获取/准备入口仍以单家公司为单位。本轮优先复用现有 build_dataset，将调用者明确选择的完整来源组成语料，不新增通用编排平台。该实验不证明跨公司联网发现或自动 acquisition 已实现。

每家公司原始完整报告全部进入可查询范围，运行 Agent 自己决定读哪一块。若 builder 只消费导航索引和原件，不将它称作完整 parsed-document 展示包。

## 换机与费用事实

本机有早期 Microsoft/Alphabet 原件和准备层；2026-10-09 E2–E4 私密运行包及原共享 costs.sqlite 未随 Git 到达，交接提到的迁移包亦不在对应路径。早期 E1 账本不能冒充 E2–E4 共享账本，不能根据文档的 176 次 / $2.0569908 估算重建一份空账本。

因此先完成不依赖缺件的材料与工程工作。真实执行前恢复原共享账本，核对在途/未知费用、限额和凭据，并从冻结相对路径输入生成新机配置；不改旧运行的绝对路径或 hash。记录不含凭据，恢复原账本不是新的业务方案审批。
