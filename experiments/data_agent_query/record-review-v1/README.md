## 实际输入、动作和结果

输入为 MSFT FY2025 10-K 的 102 条候选观察，涉及 8 张表和 1 个解释段落，2023/2024/2025 各 34 条，其中 66 条带维度。102 是观察数，去重到 `(entity, metric, period, value)` 为 81 种组合，不能当成 102 个独立可加总事实。

原件：[SEC 10-K](https://www.sec.gov/Archives/edgar/data/789019/000095017025100235/msft-20250630.htm)，SHA256 `0edfaac937bf7042c8cf7901924ccb9cc291ccfab92f83dd0b689b7912089bf6`。快照 `query-a80aa612c40a8ef6ca17e36a`，解析器 `sec-source-blocks-v0.1.6`；该阶段沿用原件，不另行下载。

## 这轮发现与改进

1. **引用拼接。** 原文 `Net income $ 101,832 $ 88,136 $ 72,361` 被模型写成 `Net income $ 88,136`。严格校验正确拒绝，不能用 trim 修正这种跳列拼接。v2 明确要求连续引用整行或分别引用单元格；第二轮未重现该错误。
2. **指标定义缺失。** v1 只有指标 ID；v2 从冻结 `metrics.json` 加入所选指标定义，供模型对照原文。三个资本支出记录现在明确解释括号现金流出与正向 payments 的关系；三个美国地理收入记录也解释并引用 OEM/跨国组织开票归属脚注。
3. **语义仍有遗漏。** 分部重述和费用分摊未充分落实到逐条意见；Microsoft Cloud 的三条意见遗漏紧邻的“这些金额已包含于上述产品/服务收入”说明，却仍将 qualifiers 判为 supported。没有证据据此判定原数字错误，但复核不足以保证下游不会误解或重复加总。
4. **工程边界。** 修复了引用同文件其他块的相同数字即可通过的漏洞；现在必须引用原 fact 所在块。输入和记录哈希、准确 ID 覆盖、跨来源、字段判定一致性及原文连续性均由程序校验。首轮过大输入被预检拦截，未产生模型请求；后续压缩表格重复字段名、按同源上下文去重，原单元格、跨度、原 HTML 与候选记录保留。

独立审阅见[首轮抽查](independent-review.md)与[第二轮抽查](second-pass-review.md)。这些抽查不是 Gold 标注；不能将 102 个 supported 意见报告为 100% 语义准确率。

## 版本与复核入口

完整本机档案：[record_review/msft-fy2025](../../../data/company_workspace/record_review/msft-fy2025/)。该目录被 Git 忽略，原件和响应未进入提交；这里的稳定本机保存不等于远端备份。

- `datasets/…`：冻结原件、索引、候选记录、证据、schema 和 DuckDB，复核前后哈希核验一致。
- `inputs-01`：过大输入的失败预检；`inputs-size-audit`：离线尺寸诊断。
- `inputs-02`：首轮 13 包；`inputs-03`：仅剩余 69 条的新版本，保存父输入 manifest 引用和指标定义。
- `run-01` / `run-02`：各自的实际输入、prompt/模型配置、原始响应、拒绝原因、逐条意见、用量与不可变 manifest。
- `implementation-01.json` / `implementation-02.json`：对应实现文件指纹；`combined-01/result.json`：去重合并的 102 条意见，仍可回查原批次与记录哈希。

机器摘要见 [summary.json](summary.json)，命令见 [CLI 复核入口](../../../docs/DATA_AGENT_CLI.zh-CN.md#提取后的-llm-记录复核)。目前为独立 `prepare/repack/run` 脚本，尚未自动接入公司 `prepare` 或下游查询的语义状态展示。
