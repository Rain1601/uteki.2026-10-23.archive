# 语义审核排因与 v2 契约验证

本轮定位到输入歧义、引文覆盖缺口和重试反馈不足，并完成对应工程改进。**真实模型质量仍为 partial，尚未接入 prepare/查询的事实采纳链路。** 所有原事实仍为 candidate。

## 原因与修改

1. **输入把引用状态和资料缺失混在一起。** 旧输入补入 Note 1 重述详情后，仍继承 `unresolved_note_references: Note 1`。这不是正文丢失，但构成误导性上下文。新输入按实际提供块重建 `context_inventory`：块为 `supplied`，原文中的附注引用为 `unresolved`；后者不能证明缺失。历史选择告警另存，旧输入不改写。该歧义是有证据的诱因，不是对模型内部因果过程的证明。
2. **真实引用可以挂在未被引用的记录上。** v1 只验证 ID 和逐字引文，没有验证 Total 收入引文能否覆盖关联的利润记录。v2 从原始 fact DOM 生成每条记录的行/段落范围；dimensions/value 约束与此类轴下的支持性断言必须逐记录覆盖。真实 27/27 条均可定位。唯一引文由宿主定位字符偏移；重复引文须给明确位置，给错位置会被拒绝。锚点不能唯一定位时显式 unavailable。
3. **协议错误未向模型提供可操作反馈。** 首个真实响应有一条空 `record_ids` 约束，被正确拒绝，但旧执行器只反馈 `ValidationError`。现已补充字段路径和错误类型，省去模型输入值。原始失败响应仍完整留档，重试上限保持每包两次。该改动用于后续合成运行；本次未实际触发合成模型的 schema 重试，修复通过离线反例验证。

v2 的 `context_claims` 只能引用清单中真实对象及其状态。自由 `limitations` 已从新 schema 移除；`context_requests` 与 `unresolved_questions` 只是未核实的问题。**模型仍可能在 reason/statement 中写出错误缺资料句子，结构合法不等于这些自由文字真实。** 本轮合成案例实际暴露了这一边界，未用关键词禁用或公司专用补丁掩盖。
