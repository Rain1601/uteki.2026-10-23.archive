## 规则与验收

规则只检查独立的 1–3 位数字和可选句点。向上查找时，每一层可见文本必须仍然只是同一个数字。遇到混合正文、表格、整页/body 边界或更近的明确非居中样式就停止。规则没有公司、年份、金额或某页号码的分支；本实验中的期望值仅用于核验，未传入解析器。

本轮用独立 Lyra/2030 合成材料覆盖纯包装层、邻近左对齐覆盖、混合内容、数字表格、隐藏数字、F-页不支持边界和缺失末页页脚。新增规则经过相关解析、导航、包校验和消费者检查；70 项程序检查通过。它们不代表金融语义正确率。

两个真实新包均通过 15 文件完整性验证，并在临时目录逐字节重建一致。全部旧文件保持原哈希；v0.1.10 的 blocks/anchors/toc/index 按旧输入复跑一致。旧包的完整 manifest 固定了当时实现指纹，不能用当前运行时冒充其原环境。

## Query 消费边界

现有 `DocumentReader.search/read` 已实际读取两个新包。台积电费用表搜索命中和上下文均返回第 70 页，原始 `2022 / 2023`、`NT$`、`(In thousands)` 与全部单元格保留。AMD 的经营现金流说明保持第 51 页。这里验证的是原文读取；没有把这张费用表转换成金融观察记录，也没有运行模型或数值 SQL。

相同源的 block ID 保持稳定，但新的 index ID、package ID、manifest 和源码指纹已经改变。后续 Query 应明确选择新包并重新绑定这些身份。历史证据引用不能偷偷改写到新包；其原文哈希和块身份应单独核对。数值查询和计算链路由同轮独立验收处理。

## 仍未验收

- 印刷页码仍只是受限 HTML 规则。TSMC 有 848 块页码未知，包含不支持的 F-页等结构；未知值没有自动补号。外部 CSS、罗马页码、封面归页和 OCR 均未在本轮修复。
- 单位与脚注的完整关联、Item 17/18 到财务附表的跨节引用，以及整份材料的语义遗漏，仍需各自验收。合成样例通过显式读取包含后续注释，不能据此称自动脚注关联完善。
- 新 prepare 路径里的数值记录生成仍受期间识别、IFRS/行业指标映射等适配能力限制；本轮不解决该瓶颈。
