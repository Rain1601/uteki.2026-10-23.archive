## 顾问复核

提交现有架构、明确失败、用户边界及计划；顾问建议需Codex按代码复核。原私密会话路径未在已知配置位置发现，本阶段新建Git忽略的私密连续会话，首轮附上此前讨论和最新约束，后续沿同一会话追问，不伪装延续找不到的旧会话。

首轮Opus返回HTTP200但达到输出上限，保留部分意见，不能称完整审阅通过。可用意见为：充分性先于最小化、引用合法不等于内容完整、原问题与修订链不可改写、优先检验现有确定性索引。一次续问没有取得响应，未知费用预留保留。顾问状态与系统任务的真实验收分开记录。

- r1：重复查看不同已读材料被误判无进展；空交付的source_checks身份契约不一致。均已修复，旧失败保留。
- r2：模型偶尔返回XML工具调用；已验证API原生JSON小外壳可用，大型完整决策Schema会被服务端拒绝。当前采用小外壳+主机完整校验。
- r3首轮：系统完成取材，复核指出多余说明；同时发现prompt让missing_information兼作删减建议，与完整覆盖校验冲突。现在独立记录revision_requests。
- 已读正文短暂移出窗口后缺少稳定导航：新增有界read_body_catalog，只有已经完整读过的块才进入，目录不算新证据。
- 精确重复数值引用：从原XBRL DOM派生字符区间和表格位置，禁止简单取字符串第一次出现。

这些状态是运行记录，不代表尚未完成的六题验收已经通过。

## 顾问续审与 Codex 取舍 · 2026-10-09

新一轮 Opus 顾问已完整回复（HTTP 200 / end_turn，公开价格估算 $0.073204）。附带此前问题、未完成回答和本轮真实失败；旧失败/未知预留不清零。私密完整对话仍只保存在本机，以下为工程结论。

- 页码、重复页眉不等于缺少正文；布局判断必须由结构规则给出，短脚注或短业务文字不能按长度丢弃。目前原件和完整读取记录保留；review 明确使用 missing_item_body_ids / missing_context_block_ids，而不是用 all_group_blocks_delivered 单独判缺料。逐块布局排除原因可作为后续可观测性增强，当前不重写冻结包。
- 单次搜索无命中或有下一页只是工具诊断。不能永久污染需求状态，也不能据此声称未披露。显式缺口、未完整读取和真正不满足的需求仍阻止合格交付；六题已知可答的任务若返回 gap，一律不能验收通过。
- 瞬时传输重试必须有界，每次请求单独计费/保留未知预留。不得把内容校验失败当网络问题，不能重放已执行工具动作，耗尽必须失败。
- PageIndex 暂不引入额外依赖；现有 HTML 原文定位及目录先接受多题检验。此结论不代表 PageIndex 对比测试通过，也不证明当前检索路径更优。

顾问原则由 Codex 按代码复核；模型自审通过与独立内容验收仍分别记录。

## 新一轮配置与交付版本

- `configs-v3`：保留六个原问题、公司、原件与范围；每次模型请求120秒，允许1次瞬时故障重试，完整决策300秒。所有尝试同一账本、失败未知预留不丢失。
- `selected-originals-v3`：自动表格上下文剔除被冻结索引明确认出的布局块，并记录原因。模型显式选择、真实标题/单位/脚注保留；v2历史可逐字重建。
- 查询候选增加紧凑 `record_origins`：模型能看清同值的各次出现分别来自哪张原表。原始出处不可被复核时的交叉引用或另选正文覆盖。
- 真正验收仍看每个新run的最终封存材料；这些改动自身不等于六题通过。

## 业务覆盖复核与第四轮矩阵

第三轮六题均结束，但独立审查发现 Alphabet 业务题只保留了 Google Services 的收入来源，遗漏其主要产品/服务定义。因此没有采纳模型的“通过”作为最终验收。旧运行和失败判定保留。

同一 Opus 顾问会话第二次完整回复（HTTP 200 / end_turn，估算 $0.069316）：先按问题判断业务构成是否齐全，再精简；单纯收入查询不应要求产品目录。Codex 将此原则写入通用查询规则、Skill 和语义复核，而不把某家公司的期望产品或块号写入执行输入。方案见 [business-coverage-v4-plan.md](business-coverage-v4-plan.md)。

第四轮保持原六题与冻结原件不变。Google 业务新运行已由系统自行补齐主要产品定义，独立验收通过并保留“可继续精简、并非最优压缩”的限制。Microsoft 业务首次触发重复导航上限，系统自动补查；其具体窗口问题另存 [导航诊断](validation/msft-business-r5-navigation-review.md)。其余最终状态待本轮封存后更新。

## 第四轮封存结果

六个原问题均已通过独立原件内容核验。Microsoft/Alphabet业务各2次取材；两家收入各1次；Microsoft Cloud 2次；Alphabet回购1次。每个attempt及审查留存，[逐题汇总](validation/matrix-v4-summary.json)、[交付说明](DELIVERY.zh-CN.md)链接到各自独立审查，模型pass不替代该审查。Google业务和回购保留相关但可再精简的上下文；未宣称全局最小字数或模型输出逐字稳定。

最后一处工程收尾是已读目录分页：同一问题曾因目录超限且无法续页反复找错已读位置。补全navigation-only目录快照后，仅对该Microsoft业务原题真实复跑，并加离线边界检查；不改原六题问题、原件或验收答案，不将六题历史重新标成新版本运行。
