## 共享实现

提取任务可以显式传入 `required_facts`。每项包含 `requirement_id`、`entity_id`、`metric_id`、`period_id`、`unit`、`accounting_basis`、`value_kind`。它描述要求取得什么，不包含预期金额。

系统在调用前检查所有 ID 属于本次目录，币种/单位与指标定义一致，值类型与口径兼容，且无重复要求。来源身份沿用原 packet 的公司、snapshot、SHA；期间沿用显式 period catalog，不根据年份字符串重建日历日期。不传要求时标为 `not_requested`，不自动生成笛卡尔积后声称完整。

输出逐项状态：

- `candidate_present`：有同一来源、主体、指标、精确期间、单位和口径的候选。
- `not_extracted`：没有对应候选；不等于未披露。
- `unresolved`：有对应原始草稿，但单位、映射或其他规范化检查未通过。
- `conflict`：同一要求存在金额、范围或限定不同的候选，保留所有记录，不擅自选一个。

同值重复记录保留各自 ID，不在覆盖检查里自动去重或采用。`candidate_coverage_complete` 只说明要求均有候选且模型没有保留 gap，仍带 `semantic_acceptance: not_evaluated`。

新运行的候选数据集发布 `fact-coverage.json` 和 `model-gaps.json`，两份均纳入文件 hash 清单。manifest 的 `gaps` 同时保留规范化错误、模型报告缺口和未满足的要求。以前模型 gaps 只留在运行 JSON 中，投影 manifest 只写规范化错误，消费方可能看不到内容缺口；此处已修复。

规范化版本升级为 `direct-normalization-v3`。旧冻结文件与已接受数据不重写。实现仍按现有提取 runner 冻结源码，不新增隐藏的公司规则。
