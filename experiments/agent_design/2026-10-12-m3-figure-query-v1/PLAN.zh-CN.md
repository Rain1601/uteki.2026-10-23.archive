# 03-M3 新重建批次与真实消费验收 v1

2026-10-12，运行前冻结问题、次数和语义标准。用户确认跨机器协作中原 M2/v5 私密包应已丢失，本轮建立新批次；不能称恢复了原 manifest。两张原图副本与 M2 SHA 完全一致；新获取 HTML 来自相同官方 accession，但字节 SHA 不同，独立核验新材料，不改写旧报告。

## 问题、次数与执行边界

问题固定为 [question.v1.json](question.v1.json)。输入是 Alphabet FY2025 10-K 完整冻结 dataset、明确公司/来源/截止日期/candidate scope，以及由系统扫描全部图片得到的强 OCR v3 补充包。Microsoft FY2025 对应 dataset 同时重建并核验，但不放入本题公司 scope。本题验证图像与正文联合取材，不是财务指标题或多公司模型对照。

**固定 R1/R2/R3 三次从零独立执行同一问题、数据、Skill、实现和资源设置。** 原计划/过程/终态封存；不互传前次答案或审核结果，不用重试替换分母。先检查 R1 质量和费用，再顺序执行 R2/R3。每次取材最多两次 attempt，问题/来源机械修订沿已有有界配置；每请求自动网络重试最多一次。失败、未知费用及恢复全部记录；不以增加次数掩盖失败。若实际出现新工程缺陷，修复必须另冻版本，原 v1 失败保留。

图片准备采用官方 `deepseek-flash` 图像输入，主 Query/worker 及两审也使用既有官方 DeepSeek，不调用 AiHubMix。图片阶段新接入属于本轮实验变量，不把它与旧 Sonnet 材料准备差异称严格 A/B。图片 max_tokens=8192、reasoning=high；Query/worker max_tokens=8192、reasoning=low；两审 max_tokens=16384、reasoning=none。正式执行前记录配置、价格快照、实际 upstream model/usage、源码/Skill/hash 及原件 pins。

本次独立重建和 M3 验收合计使用一个 **$3 硬上限**，包括图片准备、所有失败、修订与三个 Query 运行；不是每图或每次运行各 $3。不修改旧缺失 E1 账本、不声称费用继承恢复，也不把历史费用清零；旧历史成本与缺失状态继续保留。预计超过 $3 时停止并取得新增明确额度。

## 独立验收：必要覆盖、真实性与聚焦分别通过

Codex 已独立查看两张同 SHA 原图，并从重新获取的完整 DOM 读取原图前后说明；冻结精确文本、图例/颜色与允许等价出处在本机 evaluation-only，不传给图片生成器或运行 Query Agent。

必要材料：

1. Class A 与 Class C 两张图各自原始字节、身份、原文位置和强 OCR 转录完整；图例及刻度不丢失、不重复、不互换股票类别或曲线颜色。两图各 34 项可见文字，原图没有标题/印刷曲线点值；这是独立材料核验，不用字符数代替 Query 的语义覆盖。
2. 每图的本公司系列及三个比较对象能够精确引用；观察期间有原件依据。
3. 基准投入、分红再投资假设、历史结果不能预测未来的解释限制有适用于两图的原文依据。可以采用多个等价完整出处，不强制唯一块 ID；只交导航或标题不够。
4. 明确曲线没有印刷点值，不生成几何估算值；刻度不能冒充实际股票回报数据。图像证据、原始 HTML 引文及系统局限性分别标注。

真实性/出处：显式公司、报告期、cutoff、candidate、dataset、图片 SHA 与转录绑定正确；运行角色实际完整读取后自主显式选择，审核只见最终原件；来源审核和独立问题审核均通过，严格 `load_reviewed_data` 可加载（不允许 fixture 例外）。Codex 对照实际原件独立核验，不以两模型同意替代内容验收。

聚焦：不交付与本题无关的收入、主财务表、产品/风险业务正文；必要图像原文位置、图例、刻度和解释上下文允许保留。相同必要说明的等价出现不能无理由重复大段；判断其业务信息是否增加，不用最少字符/唯一块数判定。

每次分别报告问题、Agent 实际提供的材料、足以支持什么、遗漏/多余与原因、精确出处、首审/恢复和全部费用。**阶段通过条件：3/3 终态完整交付，3/3 独立必要覆盖/真实性/聚焦与双审/严格加载通过**；首次通过与恢复后通过另列。n=3 只能说明本题小样本，不能宣称长期稳定、任意公司/格式或真实 Analysis 模型已验收。费用披露，不用便宜抵消质量缺口。

## 执行前材料门禁

完整 DOM/表格/目录独立核验、两图内容与严格 Reader 校验通过后，封存 dataset/figure manifest 和评测 hash，才调用 Query。原件重建、图片准备和主 Query 三个阶段分别记录；准备阶段通过不提前勾完 03-M3。原包丢失与旧代理关闭失败均保留，不用新批次消除旧失败。

## 图片配置 v2 修订（主 Query 启动前）

图片 v1 真实执行两次，Class A 通过，Class C 以 length 结束：8192 completion tokens 全为 reasoning，正文为空；费用 $0.0170475，失败与原配置完整保留。证据指向有限输出预算在开启思考时被推理耗尽，不是缺失原图或 JSON 校验误报。

v2 显式关闭图片转录的 thinking，保留同一原图、转录 Schema、8192 上限、全图片 inventory、OCR 门禁与运行前冻结的独立标准。重新准备两张图，不只挑失败图；新增调用仍计入同一 $3 任务账本。该变量修订只发生在材料准备，不能称 v1 图片全部通过。主 Query 尚未运行，R1/R2/R3 的次数、问题、语义验收与 Query 设置完全不变，执行前明确固定为通过独立核验的 v2 图片包。

## 图片配置 v3 修订（主 Query 仍未启动）

v2 两图共四次调用全部完整 stop，34 项文字齐全；但模型采用原像素尺度而非 0..1000，坐标在进入 OCR 前被最终 Figure Schema 拒绝。SDK 只向修订暴露“Invalid JSON”，相同坐标原样再发，两图均未生产。全部失败保留，累计 6 请求/$0.0310857。

v3 在模型输出层显式选择通用 host_ocr_v1 契约：模型负责文字/系列/印刷点值与局限性，OCR 负责可读文字坐标；OCR 后仍通过完全相同的最终 Figure Schema 和严格 Reader，不裁剪/缩放/猜测模型坐标，也不放宽 OCR 标准。保留原语义引用校验，不可读区域仍按严格区域声明；独立标准不变。v3 为新批次的图片准备变量，主 Query 三次仍未执行；执行前固定使用独立验收通过的 v3 原图包。

独立材料检查器以视觉颜色类别为冻结标准。模型可以写英文颜色或 RGB 十六进制；检查器将 RGB 转为明确的色相类别后比较，不能把十六进制当作原图精确印刷色码。先前 v1 检查器只接受颜色名字，错误地将正确色系判为失败；旧报告保留，修订检查器不改变 gold 或精确颜色事实标准。图片 SHA 多重集必须正好为两张原图；验收收据与实际 dataset/figure manifest hash 绑定，主 Query 启动前逐项复核。
