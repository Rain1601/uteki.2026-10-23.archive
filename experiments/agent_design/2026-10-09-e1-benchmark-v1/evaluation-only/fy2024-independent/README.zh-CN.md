## 四题的最少充分要求

| 题目 | 预期与必需材料 | 缺少什么会失败 | 什么不必取 |
|---|---|---|---|
| E1-01：FY2024 原年报总收入 | 总收入 USD 245,122 million；2023-07-01 至 2024-06-30；FY2024 原件出处 | 用后年同额比较列替代原件；没有单位、起止或总额身份 | 产品说明、增长原因、全套会计政策 |
| E1-03：两份年报各自的 FY2024 总收入 | 两边都是 USD 245,122 million；每边保留来源和期间；不相加 | 只给一个出处；把 FY2025 本年数取成 FY2024；将重复披露加成 490,244 million | 每份年报的所有重复位置；整份原文 |
| E1-04：截至 2024-08-01 的 FY2024 总收入 | 使用 2024-07-30 已提交的 FY2024 年报；排除 2025-07-30 才发表的 FY2025 年报 | 用未来比较列，即使数值相同；用报告期末代替可得日期 | 未来报告的财务正文；产品/增长说明 |
| E1-07：同为 FY2024 的分部收入跨版本差异 | 两份分部表、明确来源版本、同期间同单位、FY2025 的重列原因原文 | 覆盖旧值；把差异说成自然增长；只交两张表不交原因 | 全产品目录；全部利润、费用与地理表 |

总收入可接受多个等价出处：利润表，分部合计，或地理/产品表的合计加上说明其为收入表的引导段。只给裸 `Total` 标签不够。MD&A 总表也可以，但须有已验证的财年元数据。

FY2024 利润表原始 XBRL 的总收入值是 `245,122`、scale 为 6、单位为 `U_USD`，context 的 issuer 是 `0000789019`，期间明确从 2023-07-01 到 2024-06-30，没有分部维度。原文年度表头只直写截止日，不把凭空推断的起日当作已引用事实。

E1-04 的可得日期依据采集到的 SEC 提交日期元数据。原件签署日 July 30, 2024 是辅助旁证，不能单独用签署日证明公开可得日期。检查时也要审查过程：不能先让模型读取未来正文，最后删掉该出处就称符合 as-of 限制。

## E1-07：实际会看到的差异

**注意：下面两列都在说 FY2024，不是 FY2024 对比 FY2025 的自然增长。** 单位均为百万美元。

| 报告分部 | FY2024 原年报 | FY2025 年报中的 FY2024 比较列 | 后版本减前版本，仅供核对 |
|---|---:|---:|---:|
| Productivity and Business Processes | 77,728 | 106,820 | +29,092 |
| Intelligent Cloud | 105,362 | 87,464 | −17,898 |
| More Personal Computing | 62,032 | 50,838 | −11,194 |
| 公司合计 | 245,122 | 245,122 | 0 |

出处为 FY2024 Note 19 表（F24-1337），以及 FY2025 Note 18 表（F25-1217）。MD&A 相同数字表也可作为等价出处，不要求两个位置都交。

FY2025 Note 1（F25-0817）明确：2024 年 8 月宣布分部组成变化，尤其把 Microsoft 365 商业组成集中到 PBP；前期分部信息已按 FY2025 内部管理口径重列。这一段是解释差异的必要材料，MD&A 同样说明（F25-0551）也可替代。

FY2025 Note 1 后一段（F25-0818）明确：重列不影响合并资产负债表、合并利润表、合并现金流量表。用户若问“为何合计不变”，这段成为必需；仅列两套分部并说明重列时，保留它有帮助，但不强制为每个简单查询追加。

FY2024 原件的 Windows 定义包括 Windows Commercial，并归 More Personal Computing。FY2025 的 Microsoft 365 Commercial 列表包括 Windows Commercial 的相关组成，并归 PBP。这提供业务边界变化的具体例子。但**不能因此声称全部 29,092 million 都来自 Windows Commercial**；没有读取到支持这种迁移金额归因的原文。具体迁移明细属于额外问题。

FY2024 原件 Note 1 也有“重列某些前期信息且不影响合并报表”的一般说明。它讲的是 FY2024 原件自身的更早比较期，不能偷换为 FY2025 重列原因。

## 重复与差异怎么评分

- E1-01 只要求 FY2024 原件，一个充分出处即可。
- E1-03 明确要求两个版本，因此两份同额出处是必要核对证据，不能按普通重复片段一律扣分。
- E1-07 同名分部、同观察期间，却有不同披露口径；保留两套值是正确行为。覆盖旧值、取平均或相加都是失败。
- 只要内容与版本充分，可以接受原文其他等价位置，不锁死块 ID。
- 原始整张表带来的附带上下文，与主动多取整章不同，分别记录冗余。
- 此标准是候选，不是唯一最优集合；根 Agent 复核后才能冻结。

本轮还观察到：FY2024 原年报的 Microsoft Cloud FY2024 收入为 $137.4 billion，而 FY2025 年报的 FY2024 比较值为 $137.7 billion，且组成定义不同。这是有用的后续测试素材，但**没有擅自把它加入这四题的强制标准**。
