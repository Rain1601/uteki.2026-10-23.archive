# Filing brief output contract — candidate

This is an application-neutral content contract for a first real trial, not a production API or a claim that the current database accepts these objects. The task supplies company/source identities. Preserve the source's native language separately from generated report languages.

## Human-readable brief

- Scope: company, exact source edition, report period, cutoff and coverage limitations.
- A business explanation or diagram when useful.
- Prioritized findings with clear fact/management statement/interpretation boundaries.
- Financial table or charts only from cited, scoped facts; label review state and calculations.
- Important constraints, negative evidence and material changes.
- Watch items with an official-information question that could resolve them. A watch proposal is not an active scheduled monitor.
- Material gaps and links back to evidence.

Chinese and English versions use one reviewed set of item IDs and figures. Do not create independent translations with diverging claims.

## Saved supporting records

**Information item:** stable ID within the artifact; short claim; type; priority; reason for that priority; scope and period; qualifications and uncertainty; source references; related/contradictory item references where applicable; review state. An important but unconfirmed item remains explicitly unconfirmed.

**Evidence reference:** source ID and original content hash; block/table/cell or actual PDF page index; printed page label when available; excerpt preserving the necessary caption/context; financial-record ID when reused. Exact quotes remain in the evidence layer and are not a reason to publish large copyrighted excerpts. If the available precision is a whole table, say so; do not manufacture cell coordinates.

**Coverage/disposition record:** original section/unit identity; acquisition and parsing status; assessed/not assessed; included item IDs, merged-with references, compressed/not-expanded reason, or unresolved gap. Repetitive noise can be grouped by rule and retained source ranges; do not manufacture one model decision per decorative line. Every material source area must have a reviewable disposition.

**Review record:** issue kind, affected output/source IDs, severity, reviewer and method, evidence, proposed action, adjudication and revision result. Conflicting values and disputed judgments remain visible until resolved.

**Run manifest:** task input, selected company/source/hash, exact loaded Skill/Prompt/contract versions, actual provider/model configuration, available tools, steps actually recorded, output references/hashes, request/usage records and limitations. No reconstructed traces for unrecorded work.

Storage uses immutable run artifacts first, with whatever existing record references actually exist. Registering a new result for the backend is a separate implementation step. Neither a saved file nor a display version changes data adoption or MCP scope.
